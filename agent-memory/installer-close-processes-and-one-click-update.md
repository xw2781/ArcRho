Setup's "ArcRho cannot be closed. Please close it manually and click Retry" dialog (0% into the
install) is raised when the old uninstaller cannot move the install folder, and the process holding it
was `arcrho_server.exe`, which electron-builder's built-in check never looks at (it only kills
`${APP_EXECUTABLE_FILENAME}`). The backend survived because `before-quit` in `electron/main.js` was
async and Electron does not wait for it, so the update path's shutdown raced the exit.

Fixed 2026-09-18 (frontend only, no server component deploy):
- `electron/update_checker.js` hides the main window, reuses the startup splash as the update window
  (`updateHost` in main.js), stops the backend outright through `stopBackendForUpdate` and waits for the
  port to be free, then spawns setup with `--updated` and calls `app.exit(0)`. `before-quit` now uses
  the `preventDefault` + re-`quit` pattern around `prepareQuit()`.
- `build/installer/installer.nsh` defines `customCheckAppRunning` (expanded in both installer and
  uninstaller, so it must sit outside `!ifndef BUILD_UNINSTALLER` and use no functions), which runs
  `build/installer/close_arcrho_processes.ps1 -InstallDir "$INSTDIR"`. `customInstallMode`,
  `$ArcRhoIsUpdate` (set in `customInit`) and `customFinishPage` make an `--updated` run show only the
  file-progress page and relaunch the app.

**Why:** electron-builder facts that cost time to establish:
- `${isUpdated}` and the other flag predicates are generated by `NsisScriptGenerator.flags()` at the top
  of the script and expand to `${StdUtils.TestParameter}`; `tests/installer_progress_patcher.test.mjs`
  forbids `${StdUtils.` and `$per(User|Machine)InstallationFolder` anywhere outside `customInit`, so use
  them only in macros electron-builder expands late (customInit, customCheckAppRunning,
  customInstallMode, customFinishPage) and relaunch through `!insertmacro StartApp` from common.nsh.
- NSIS is 32-bit, so `$SYSDIR\...\powershell.exe` is the SysWOW64 PowerShell; `Get-Process().Path` /
  `MainModule` fails for 64-bit processes there. `Win32_Process.ExecutablePath` works.
- `installer.nsh` is CRLF; regexes in the contract tests need `\r?\n` or a normalised copy.

**How to apply:** when setup reports "cannot be closed", read the process list the dialog now prints
before suspecting the main executable; when adding installer hooks, mirror the parse-order rules above
and run `tests/installer_close_processes.test.mjs` (spawns a copied node.exe under `test/`) plus
`tests/server_installer_contract.test.mjs`. See also [[bridge-heartbeat-false-negative]] for the
server-side "killed, not closed" analogue.
