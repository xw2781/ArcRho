# Release 1.5.1

Released on 2026-09-10.

## User-Facing Changes

### Features
- **project instance**: Added a Dependency Graph window that draws every dataset and method of the selected reserving class and how they feed each other.
  - Open it from the new graph icon in the dataset toolbar; it is a nested window like Manage Excel Links, pinned to the reserving class it was opened on.
  - Click a box to light up what it is computed from and what depends on it, and keep it lit until you click elsewhere; double-click a box to open the dataset in Dataset Viewer or a method output in its method page.
  - Right-click a box for a Show Dataset command that opens the same window, and opening a box no longer changes the chain you have lit.
  - Hover a box for two small ports on its edges: the left one lists its precedents, the right one its dependents, and clicking a name scrolls the diagram to that box. A name too long for its box scrolls across the card while you hover it, so you can read the whole of it.
  - Datasets nothing depends on are hidden by default; tick Show all to see them. The diagram has no scrollbars: drag the background to pan it and use the wheel to zoom. Zooming out stops once the whole graph is on screen, so it can never be shrunk into a speck.
  - There is room to drag past every edge of the diagram, so a box in the first column or the last one can be pulled into the middle of the window while you are zoomed in.
  - The diagram redraws on its own after a save, delete, or import changes the class.
- **dataset**: The formula bar now has a button that opens the linked workbook in Excel and selects the range the formula reads from.
  - The button appears in the Dataset Viewer's linked-cell editor and on the DFM Ratios formula bar, only while the formula points at a workbook.
  - Pressing it while typing a formula does not commit the edit.

### Improvements
- **dfm**: The Ratios tab shows each average row's number before its label, such as 10: User Entry, the way ResQ lists them.
  - The number is the row's current position and follows a drag reorder.
  - The label column starts a little wider to make room for the numbers.
  - Formula references, cell notes and copies keep using the bare label.
- **shell**: The Project Explorer tab now uses two overlapping project tiles to represent a collection of projects.
  - The tab icon follows the same monochrome stroke style as the other tabs; the Home card retains its four project tiles.
  - It no longer reads like the workspace folder or the project window beside it.
- **macro**: Shared macros now update on their own, so you always run the latest published version of a macro loaded from the shared macro library.
  - Opening the Macros panel replaces every loaded macro the library holds a newer version of and names the updated macros in the status bar.
  - Running a macro, from the panel or a Flight Deck button, checks the library once more and runs the newest version.
  - A local copy you edited at the same or a higher version is left alone; the yellow Update stamp is gone because there is nothing left to click.

### Fixes
- **methods**: Copying cells from a method grid now pastes the full, unrounded numbers, and a Development Factor Method saved from the page no longer rounds its selected factors to six decimals before they are chained into the ultimate.
  - The Ratios, Curves, and Results tabs of a Development Factor Method, and the Bornhuetter Ferguson, Cape Cod, and Result Selection grids, copy the figure behind each cell rather than the text printed at the chosen decimal places. A percentage copies as its fraction. The Dataset Viewer and Berquist Sherman already copied unrounded values.
  - The selected, cumulative, and percent-developed rows on the Ratios tab now chain the full value of each summary cell instead of re-reading the printed text, so the cumulative factors on screen match the ones the Engine uses.
  - Average-formula values, User Entry results, Excel-linked values, and the percent-developed pattern are saved whole. Only the ratio triangle, which nothing calculates from, stays at six decimals in the file.
  - Opening a Curves tab user value and committing it unchanged keeps every digit instead of saving the displayed number.
- **flight-deck**: Hovering a Flight Deck button's icon shows its label again instead of nothing.
- **methods**: Method results now match ResQ exactly. ArcRho was storing several figures rounded to the number of decimals it displays them at, and then calculating with the rounded copy, which made an ultimate drift from ResQ by a few cents at older origin years and up to about 0.2 at the newest one.
  - A development factor brought in from ResQ is kept exactly as ResQ holds it, instead of being cut back to the Decimal Places on the Details tab.
  - The whole chain a Development Factor Method multiplies together now carries its full accuracy, and so do the percentage developed and the ultimate it publishes.
  - Bornhuetter Ferguson, Cape Cod and Result Selection no longer round the vectors they read from another method, so the error can no longer grow as it passes down the chain.
  - Thirteen places that read a saved table back from disk were quietly losing accuracy in the last few digits. They now read every digit.
  - The Ratios tab still prints to the Decimal Places you choose; that setting now only changes what is shown, never what is calculated.
  - Apply Growth and Cutoff Adjustments writes its rounding into the formula again, as ROUND("Simple - 2", 4) around the method's own average row, so the notes still reconcile with the numbers on screen. The growth and cutoff factors are left alone because they already arrive at four decimals.
  - The formula bar hides that ROUND while you are only reading the formula, and shows it as soon as you click into the cell to edit.
- **resq import**: A ResQ DFM with several User Entry rows now imports every one of them, named User Entry, User Entry 2, User Entry 3 in ResQ order, and the averages listed after them are no longer lost.
  - The import reads the row count ResQ reports instead of stopping at the first User Entry row.
  - The export writes each User Entry row's factors and tail to its own ResQ row.
- **shell**: The line above the status bar is a single hairline again instead of a thicker double line across the middle of the window.
  - Fixed the same way in the main ArcRho window and in Arcode.
- **dataset**: A calculated dataset type whose formula names a type the project does not have is now treated as a manual input everywhere, so the ResQ import keeps its values as hard-coded numbers you can edit.
  - Its datasets no longer carry a formula or precedents, are not read-only, are not refreshed by the dependent walk, and appear in the ResQ transfer review like any other input.
  - One shared rule now decides which dataset types ArcRho calculates itself, for the app, the ResQ import, and the transfer review alike.
