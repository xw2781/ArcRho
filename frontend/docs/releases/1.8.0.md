# Release 1.8.0

Released on 2026-09-27.

## User-Facing Changes

### Features
- **bootstrap**: Bootstrap methods now open from the project list in their own window, and a new one can be added from a vector row.
  - Details, Residuals, Simulation and Targets tabs set up the model; saving runs the simulation.
  - The residual grid and a residual chart sit side by side, with large residuals flagged.
  - A chip above the tabs says whether the stored run still matches the inputs on screen.
- **bootstrap**: The Bootstrap Results tab now shows the reserve range: a summary table with your chosen percentiles, a distribution chart and a fan chart by origin.
  - Switch between scaled and unscaled results, and between reserves and ultimates; the table and both charts follow.
  - Choose the percentiles once and every view uses them; Full Ladder shows every half percent from 0 to 100, and Copy puts the table on the clipboard.
  - A Simulate button runs the model and shows the results without saving them, and the header says how long the run took; Save keeps the run.
- **appearance**: Tables and tabbed pages open in a new Revolutionary style with clearer grid lines, and a Color Theme card on Home lets you preview it beside the original Classic style and switch.
  - Revolutionary keeps tables flat and quiet: slate grid lines you can see, pale headers, softer selection colours, and flat tabs with an underline.
  - Classic is the look the app had before; pick it on the Home Color Theme card to switch back.
  - The Color Theme card shows a live snapshot of each style and a Light / Dark switch, and a choice applies at once.
  - The High Contrast theme has been removed; anyone who had chosen it now opens in Light.
- **stochastic-consolidation**: Stochastic Consolidation methods now open from the project list, and a new one can be added from a vector row: pick bootstraps from other reserving classes, set their correlations, and read the combined reserve range.
  - The Segments tab lists each included bootstrap with its own mean, standard deviation and CV, and says why a segment cannot be combined.
  - The Correlation tab edits the target correlations as a mirrored matrix and shows the correlations a run used and achieved.
  - Consolidate runs the combination without saving; the Results tab shows the range with your chosen percentiles, a distribution chart, a fan chart, and each segment's share and the diversification.
- **bootstrap**: The Bootstrap Results tab's Full Ladder can now step by 5%, 1%, 0.5%, 0.1% or 0.01%, as ResQ's Percentiles choice does.
  - Pick the interval from the dropdown beside Full Ladder; Copy Table and Download CSV follow it.
  - 0.1% and 0.01% re-run the simulation from its seed, so the ladder takes a moment and matches the run on screen exactly.
- **method tables**: Every method page's tables have a Custom Colors window for choosing the font and fill of each part of the tables, and the colour and width of the grid lines.
  - Open it from the right-click menu of any table on a DFM, Bornhuetter Ferguson, Cape Cod, Berquist Sherman, Bootstrap, Stochastic Consolidation, or Result Selection page.
  - Values, column headers, row labels, the green selected cells, the yellow result columns such as ultimates, and highlighted cells share one set of colours across every method page; the DFM also lists the Ratios tables' own parts.
  - The Cell Border row sets the grid line colour and a width of 1, 2 or 3 px for every table.
  - Colours apply at once to every open page and are kept for your user; Reset all returns the theme's own colours.
- **project instance**: The path tree's Filter window has a new Hide paths with no data option, which leaves out reserving classes that hold no datasets yet.
  - The choice is remembered for you in each project, and Clear turns it off.
  - A path that gets its first dataset shows up the next time the tree loads.
- **shell**: A new Server tab, opened from Home, lists the servers this PC knows by name and address, shows whether each one is answering, and switches between them.
  - Add a server by choosing its folder; its address is read from the folder.
  - Switching restarts the app and is blocked while any tab has unsaved changes.
  - The Server Connection dialog now links to the Server tab.
  - A Components panel shows which parts of the server in use are running, on which machine, and how long since each was last heard from.
  - A server whose folder is on this PC can be started and stopped from the Components panel; production is still managed from Admin Control on the Server PC.
  - The title bar names the server in use whenever it is not production; clicking the name opens the Server tab.

### Improvements
- **bootstrap**: The Bootstrap and Stochastic Consolidation windows now look and work like the other method windows.
  - Simulate or Consolidate, Save and Cancel sit together at the bottom, and the run state shows beside the window title.
  - A running animation shows while a run is in progress.
  - Tables select, copy and scroll like the other method tables, and Results can be downloaded as a CSV.
  - On Residuals the chart sits below the triangle, and both widen with the window.
- **dfm**: A tail factor typed on any average row in a DFM's Ratios tab is now kept, as in ResQ, instead of being reset to 1 on computed averages such as Volume - all.
  - The tail cell of every average row is now an input: select it, type the factor, and press Enter.
  - A DFM imported from ResQ keeps the tail ResQ has on a computed average row, so its ultimates match ResQ's.
- **project instance**: The Shortcut and Group And Filter config menus list the last three config files you saved or loaded, so you can switch to one in a single click.
  - A new button to the right of Add Favorite Folder opens the Shortcut menu, as right-clicking the Shortcut header does.
  - The menu items are shorter: Save Shortcut, Load Shortcut, Save Group And Filter, Load Group And Filter.
  - Only the file paths are remembered, on this PC for your user.
  - Loading a config replaces settings already saved in a file without asking; unsaved settings get an offer to save them first.
- **dataset**: Refreshing a Bootstrap method, saving dataset notes, and creating an empty dataset now save on the server under the same protection as a page's own Save.
- **arcbot**: ArcBot edits now land in the open page and save through its normal Save instead of ArcBot writing the file itself.
  - A DFM edit is one undoable step that is saved like a Save you press; if the save fails, the edit stays as unsaved changes.
  - Notebook and JSON file edits in Arcode appear as unsaved changes for you to save.
  - "Revert the latest ArcBot edit" now undoes that change in the page that took it, and ArcBot no longer writes backup files next to the method.
- **arcbot**: ArcBot now reads other objects of your project through the server instead of browsing the shared drive, signed in as you. It can still answer questions about other methods, datasets and reserving classes, but it can no longer open raw CSV files or list project folders.
- **calculations**: Period headings load from the server, and a calculation hands its result straight back instead of through the shared drive, so datasets whose headings or figures need recalculating open faster.
- **project settings**: Import Data now uploads a SQL Server table or a CSV only your PC can open to the server, which writes the project table, and the progress window shows how many megabytes and rows have been sent. A CSV upload interrupted part way picks up where it stopped when you import again, and a failed upload never replaces the table already there.
- **dataset and method windows**: A dataset's details panel, the live preview of the datasets that depend on an unsaved edit, a DFM's dataset cell references, the % Developed comparison curve and the development pattern that Bornhuetter-Ferguson and Cape Cod read from a DFM now load from the server.
- **dfm**: "Open DFM JSON" now shows the method read only in Arcode.
  - The method is loaded from the server the same way the DFM page loads it, so the window no longer opens the method file over the shared drive.
  - A "Read only" chip marks the tab, and Save, Ctrl+S and ArcBot edits are turned off there; change the method in its DFM page.
  - Other JSON files you open in Arcode keep their normal Save.
- **server connection**: A new PC now signs in to the server with your Windows account and receives only your own credential, instead of reading the shared file that holds everyone's sign-in.
  - Server Connection and Add Server ask for the server's address, for example http://server:28767; a PC that is already signed in keeps working as before.
  - If signing in fails, Server Connection stays open and says why.
- **macros**: The Macro Library, the automatic macro updates and ArcBot's shared prompts now load from the server instead of the shared drive, and ArcBot no longer creates prompt files on the server. While the server cannot be reached the Macro Library says it is unavailable and your loaded macros keep running as they are.
- **project settings**: Saving dataset types and copying a project are now submitted and tracked on the server. While the server cannot be reached, the progress window keeps waiting instead of reporting the change or the copy as failed.
- **project settings**: Project Settings, the project pickers and the name on the Home page now load from the server. Opening the Data Processing Rules page no longer re-copies the source table; use Import Data to pick up a changed source file.
- **project settings**: Creating, renaming and deleting a project, saving the project list and General Settings, and clearing generated dataset files now run on the server. A change whose answer is lost on the network is never applied twice.
- **reserving class picker**: The reserving-class picker, its filters, hidden paths and favorites, and your per-project preferences now load and save on the server. Clearing a filter level or removing your last favorite now stays cleared the next time the picker opens.
- **server**: Every save now goes through the server, and saving default number formats in Preferences works again.
  - A save the server cannot take yet says the server needs updating, and a PC that is not signed in is asked to sign in, instead of writing to the shared drive.
  - Default number formats are saved on the server and record who saved them; a save that lists dataset type formats no longer fails.
  - The Dataset Viewer's reserving class list now shows the classes the project's data holds.
- **project settings**: Saving the field mapping, the import settings and the reserving class types now happens on the server, and Import Data no longer copies a shared source file through your PC when the server's import cannot run. While the server cannot be reached, the source refresh progress window keeps waiting instead of reporting a failure.

### Fixes
- **result selection**: Ultimate values copied from Excel with thousands separators, such as 46,759, now paste into a Result Selection's Selected Ultimate column instead of being ignored.
- **change alerts**: The "Updated Outside This Window" alert and the Project Instance "Refresh Table" button now check with the server, so your own saves no longer set them off, and they stay quiet while the server cannot be reached.
- **project settings**: The project audit log is now read and written on the server, so entries recorded from two PCs at once no longer overwrite each other.
- **dfm**: Fixed blurry Ratios summary text after minimizing and restoring a DFM window.

### Breaking Changes
- **server**: Arco now works only while it can reach the server. When the server is down it says "The server can't be reached" instead of reading the shared drive, and a sign-in the server no longer accepts asks you to sign in to the server again.
  - Saving data processing rules needs the server's Engine; it no longer saves another way when the Engine is not running.
  - Arco remembers which server this PC signed in to and refuses a different server at the same address.
  - Sign in again, beside that message in the status bar or on the server in use in the Server tab, signs this PC in with your Windows account; the next request uses it without a restart.
