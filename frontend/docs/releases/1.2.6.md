# Release 1.2.6

Released on 2026-08-09.

## User-Facing Changes

### Features
- **home**: Home now reveals a click-to-add hint below the last group.
  - Hovering anywhere in the space below the last group reveals the add-group hint.
  - Clicking that space opens the new-group naming prompt.

### Improvements
- **arcode**: Refined Arcode Home cards in Dark mode with a focused blue hover border.
- **home**: Aligned Home shortcut drag feedback with the click threshold.
- **project settings**: Source Data now charts Origin Date and Development Date columns as one bar per calendar year.
  - Date columns were previously binned across their raw YYYYMM span, which produced a sawtooth because months 13-99 do not exist; each bar is now a single year.
  - Placeholder zeros and other values that are not real periods are left out of the chart, so a Development Date column with zeros no longer starts at the wrong place.
  - Hovering a bar shows the year it covers, and a year with no rows stays visible as a gap.
  - Each column's Origin Date or Development Date role is now resolved by the app server and refreshes automatically when the field mapping changes.
- **home**: Place the Home add-card plus sign and label on one line.
- **home**: Use the sentence-case + Add card label for Home add-card actions.
- **home**: Show only the card drag hint after the pointer rests for 0.5 seconds.
- **home**: Refined Home card tooltips with a readable styled hover and focus presentation.

### Fixes
- **arcode**: Keep Arcode Home card text color unchanged when a card is highlighted.
- **arcode**: Display Arcode Home group labels in white in Dark mode.
- **home**: Match Home add-card tiles to the fill color of existing cards.
- **home**: Lightened Home add-card tiles and removed idle fill from group action buttons.

## Internal Notes

- **build**: A published release now records itself in the source repository with no manual step.
  - After publishing the GitHub Release, the build asks the source-PC listener to sync the repository, so build_app_listener.bat and build_app_one_click.bat remain the only commands anyone runs.
  - The listener captures the changelog fragments each build ZIP carries, keyed by that ZIP's ready signal, so a release consumes exactly the fragments it was built from even if a later build replaced the ZIP.
  - The sync commits only release bookkeeping and never stages unrelated work in the worktree, and never pushes.
  - Fixed the listener terminating on any failed request before it could publish the failure response, which left the build PC waiting on a response that never arrived and orphaned the request file.
- **build**: Builds now publish only to GitHub Releases, which also decides the next version number.
  - Removed the network installer feed publish step, which copied the installer to the ArcRho Server release folder and then re-hashed that remote copy, costing 8 to 40 minutes per build.
  - The next version number now comes from the GitHub Releases history instead of the retired feed folder, and the build fails loudly rather than reusing a version already published.
  - The release tag format and target repository moved into build/release_channel.json, shared by the publish script and the version manager.
  - Fixed the release-exists probe, which treated every tag as already published because a failing gh command sets an exit code instead of throwing.
  - Release notes longer than the GitHub release body limit are now attached to the release in full and summarised in a truncated body, instead of failing the publish with HTTP 422.
- **build**: Added a repository sync step so a published release records its version, notes, and consumed fragments in the repository.
  - The build runs from a disposable workspace, so its version bump, generated release notes, and fragment archiving were discarded every release; the repository sat at 1.2.0 while 1.2.5 shipped and 493 fragments never drained from changes/unreleased.
  - build/sync_published_release.py verifies the release tag through git ls-remote, writes the version into package.json, package-lock.json, index.html, and splash.html, then archives the fragments that release consumed.
  - Consumed fragments are taken from the fragment list in the build ZIP, so work added after the ZIP was cut stays unreleased for the next version.
  - release_notes.py now exposes release_fragments so a release can consume an explicit fragment set, and version_manager.py exposes update_version_metadata as the single writer of version-carrying files.
- **build**: Fixed the packaging build failing with "cannot find the batch label specified" by keeping build batch files on CRLF line endings.
  - cmd.exe resolves `call :label` by byte offset and cannot find labels in LF-only batch files once the label sits past a certain position.
  - Repository batch files are now normalized to CRLF and pinned there by .gitattributes.
  - Workspace preparation also normalizes batch line endings, so a ZIP or local workspace can no longer inherit the failure.
- **build**: The build share launcher scripts are now version controlled and deployed from the repository.
  - build/build_share holds the canonical copy of build_app_listener.bat, build_app_listener.ps1, build_app_one_click.bat, build_arcode_one_click.bat, and publish_pending_github_release.bat, which previously existed only in the build share with no review, history, or backup.
  - deploy_build_share.bat publishes the scripts that differ, --verify reports drift without writing, and nothing else in the share is touched or removed.
  - A share copy that differs and is newer than the repository copy is reported and left alone, so an edit made directly in the share is never silently overwritten.
  - The listener compares itself against the repository copy at startup and warns when it is stale, because PowerShell loads the script once and a listener left running after a deploy keeps serving the previous version.
