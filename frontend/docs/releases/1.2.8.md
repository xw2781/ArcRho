# Release 1.2.8

Released on 2026-08-09.

## User-Facing Changes

### Improvements
- **theme**: Dark mode now gives Home, DFM results, Project Instance status marks, and Arcode cards more consistent surfaces and contrast.
- **home**: Home shortcut cards now distinguish quick clicks from drag holds more clearly and expose a quieter new-group control.

## Internal Notes

- **build**: A development launch no longer stalls on the splash screen waiting for a server that cannot start.
  - Running the app server under pythonw.exe left uvicorn without a stderr stream, so it exited with code 1 before binding its port.
  - Only the supervisor now runs under pythonw; the app server keeps the console interpreter and stays windowless through Electron's hidden spawn.
  - The supervisor also redirects its child to the null device when its own streams are absent.
- **build**: Development launches now show the source tree's own version instead of a stale release-feed version, and a single launcher replaces the three start scripts.
  - The old no-console launcher pinned the splash and About version to the newest installer in E:\ArcRho Server\releases\installers, which stopped being updated when releases moved to GitHub, so dev launches were stuck reporting 1.2.5.
  - launch_arcrho_dev_mode.bat replaces start_electron.bat, start_electron_no_python_window.bat, and start_arcode.bat; pass arcode to launch Arcode.
  - The Electron host no longer falls back to ARCRHO_DISPLAY_VERSION when running in Arcode mode.
- **build**: Closing a development launch now exits for good instead of being replaced by a new instance.
  - The dev Electron supervisor relaunched the app on any exit and only stopped on a .shutdown_electron flag that nothing ever wrote, so closing the window immediately opened a fresh one.
  - It now relaunches only after an explicit .restart_electron request; File > Restart is unaffected.
- **shell**: A development launch on Windows 10 now shows a blue window frame, so it is unmistakable beside an installed release.
  - The frame reuses the existing Windows 10 shell border and only changes its color.
  - Installed releases keep the standard frame, and Windows 11 is unchanged because its frame belongs to the operating system.
