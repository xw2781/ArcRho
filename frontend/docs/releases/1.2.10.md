# Release 1.2.10

Released on 2026-08-10.

## User-Facing Changes

### Improvements
- **installer**: ArcRho setup now defaults to a per-user E-drive installation folder on the designated PC.
  - Fresh installs on NE7SASWPN02 default to E:\<Windows login>\ArcRho when setup can create that directory.
  - Existing installations, explicit install paths, and the standard C-drive fallback remain unchanged.

### Fixes
- **dataset**: Add > Dataset can now save a new dataset without editing a cell first.
  - The new-dataset draft window opened with Save disabled, and Ctrl+S reported "Dataset settings saved." without creating anything, so the dataset never appeared in the Project Instance table.
  - An unsaved draft is now save-eligible on open and its first save writes the zero-filled placeholder grid; Save is still blocked while the draft grid cannot be built from project origin headers.
- **dfm**: Open as Read-Only now works for Excel workbook links in the installed app, not only in development mode.
  - The installed app launched Excel from its packaged app.asar folder, which Windows rejects as a working directory and reported as "spawn powershell.exe ENOENT".
  - Host commands now run from a real directory and resolve PowerShell under %SystemRoot% instead of the inherited PATH.
  - Applies to read-only Excel opening from DFM Notes, Dataset links, and File Explorer, plus Open Terminal.
- **dfm**: DFM and Result Selection sync now put the NEW seal on the version whose timestamp is actually later.
  - ResQ writes its last-modified value without a timezone while an ArcRho save writes UTC, and the comparison read the ResQ value as UTC too, shifting it by the machine's UTC offset.
  - On a UTC-04:00 machine that marked the ArcRho card NEW whenever the two versions were saved less than four hours apart, even though the review window showed the ResQ card with the later time.
  - A timezone-less value is now read as local wall-clock time, so the seal, the green/red timestamp frames, and the offered sync action match the displayed times.
- **project settings**: Managed source table imports now work in the installed app instead of reporting a missing SQL Server driver.
  - The packaged app server was built without pyodbc, so every SQL Server import answered with a driver-unavailable error.
  - The build now verifies pyodbc before packaging and installs it when missing.

## Internal Notes

- **build**: The packaged build no longer kills makensis part-way through compressing the app.
  - electron-builder allows the piped makensis process four minutes, which assumes it only embeds a pre-built app.7z; ArcRho compresses the whole unpacked app inside makensis.
  - The build patcher now raises that kill timeout to 30 minutes.
  - A build that hit the old limit reported only 'Exit code: null' with empty compiler output, because the kill arrives as a signal rather than a compiler error.
- **build**: The packaged build no longer aborts while compiling the custom NSIS installer script.
  - electron-builder includes build/installer.nsh ahead of multiUser.nsh and of its own plugin directories, so the preferred-install-directory check now reads the install-mode folders and the /D switch from the customInit macro instead of a function body.
  - The install-mode variables failed the build through the -WX warning-as-error flag, and the StdUtils plugin call could not be resolved that early in the script.
  - The bundled runtime smoke test now allows 30 seconds, so a cold first launch of the freshly extracted Codex binary is no longer reported as a runtime failure.
