# Release 1.3.3

Released on 2026-08-23.

## User-Facing Changes

### Features
- **macro**: New macro imports any set of a project's reserving classes from ResQ in one run.
  - Import ResQ Reserving Classes lists every class in the active project in a review table, preselected, so a whole-project re-import is one accept away.
  - Each selected class goes through the same ArcRho Bridge import as the single-class macro, one at a time, with batch progress and a final summary of any failures.
- **dataset**: Typing a number over a selected range of editable Dataset cells now fills the whole range.
  - Select any range in the Data tab of an editable dataset and start typing: every editable cell in the selection takes the number as you type it, matching how the Result Selection Method grid fills highlighted weights.
  - Successive keystrokes build one number, a decimal point and a leading minus sign are accepted, and noneditable cells such as masked triangle cells and Total are skipped.
  - Selecting a single cell still opens the inline editor as before.
- **macro**: Both ResQ reserving-class import macros now offer merging with or overwriting existing ArcRho data.
  - Merge keeps today's behavior: datasets that exist only in ArcRho and any ArcRho copy newer than the ResQ version are preserved.
  - Overwrite makes the fresh ResQ copy win every conflict, even where the ArcRho copy is newer, after an explicit confirmation; datasets that exist only in ArcRho are still kept.
  - The batch macro puts the Overwrite checkbox in the class-selection window itself and preselects the canonical default reserving-class list; review-table windows now support such footer checkboxes for any macro.

### Improvements
- **berquist-sherman**: Saving a Berquist Sherman method now runs on the ArcRho Server instead of the network drive, so the save finishes in a fraction of the time.
  - The method file, its output table, and the output dataset's sidecar are now written in one request that the server carries out beside the data. They used to be two separate trips, the first of which wrote two files across the mapped drive from the user's own PC, where every file opened costs a round trip whatever the file weighs.
  - The window no longer reloads the audit log and the Details dependency lists after saving: the save already answers with both, so it applies what it was handed instead of fetching the same thing again.
  - Switching to the Audit tab now reads through the same server-side route the window already uses when it opens, rather than opening the sidecar, the project's dataset-type rows, the reserving-class index, and one more file for every precedent and dependent.
  - A save is also refused as a whole when the reserving class is busy, so a blocked save can no longer leave the method file written ahead of the sidecar that describes it.
  - Berquist Sherman was the last method type still writing its files from the user's PC; it now behaves like DFM, Bornhuetter Ferguson, Cape Cod, Bootstrap, and Result Selection.
- **project settings**: A Dataset Types change now shows which reserving classes it affects before anything is locked, and a renamed type carries its datasets with it.
  - Renaming or removing a dataset type, or changing its Data Format, Calculated flag or Formula, first opens a confirmation listing the reserving classes the change reaches, how many datasets in each and why. Apply runs the change; Cancel puts the saved table back.
  - Only the listed reserving classes are locked while the change runs. Every other reserving class in the project stays available, instead of the whole project being held for the duration.
  - The affected classes are found by reading each class's dataset index, not by opening every dataset in the project, so the check takes seconds and does not lock anything.
  - If someone changes the project between the confirmation and the run, the change stops with a message asking you to review it again rather than locking more than you agreed to.
  - Renaming a dataset type now renames it for its existing datasets: they keep their place under the new type instead of dropping into a blank category. A dataset named after the old type, that nothing else reads, is renamed with it.
  - The completion message says how many of the project's reserving classes were touched and how many datasets were renamed.
- **ui**: Every Details tab now groups its fields into ordered sections, shows Precedents and Dependents, and reads its formula as plain quoted text.
  - Details rows are grouped in one order everywhere: identity, then what the output is computed from and what consumes it, then length and decimal settings, then any remaining settings. The groups carry no headings - a light line marks each boundary.
  - Every method page now shows Precedents and Dependents, the same chips the Dataset Viewer shows, for the dataset the method publishes. Clicking one opens that dataset or its method window, hovering shows its formula, and both refresh after a save.
  - Cape Cod moves its Latest, Exposure, and Prior Ultimate pickers from the Method tab to Details, so it matches Bornhuetter Ferguson and Berquist Sherman.
  - The Dataset Viewer formula now reads as plain text: operators are the characters you typed and each source is its name in double quotes, in normal body colour. Opening a source is the Precedents row's job, so the formula no longer doubles as a set of links.
  - A formula now reads the same in all three places that show one: the Dataset Viewer Formula field, the Project Settings Dataset Types table, and the Project Instance dataset table. Each dataset name is quoted and operator spacing is normalised, and a name containing '-' or '/' is no longer split into what looks like an expression.
  - The Formula field is shown with the read-only fill, since a calculated dataset's formula belongs to its Dataset Type in Project Settings and cannot be edited from a dataset window.
  - Origin Length, Development Length, and Decimal Places share one short width on every page that shows them, so the numeric fields line up as a column.
  - Segment is read-only on every Details tab and its browse button is gone, matching the fact that the host always fixes it.
  - A picker opens its list only from its own button. Clicking into the text box now just places a caret; typing still filters, and ArrowDown still opens the list.
  - Berquist Sherman moves Number Format into its own group, wide enough for its longest preset, and shows the source triangles above the length and decimal settings.
  - Result Selection and Bornhuetter Ferguson now list Origin Length after their dataset pickers rather than before them.
- **dfm**: A DFM Ratios dataset reference worth exactly 1 now shows as a grey pill in the formula bar.
  - A factor that leaves the User Entry value unchanged reads as quiet instead of active.
  - The pill stays clickable and still shows its value on hover.
- **dfm**: Syncing a DFM or Result Selection method with ResQ now runs on the ArcRho Server instead of the network drive, so the review window opens in a fraction of the time.
  - Sync, Refresh, Keep Local, and the remote update no longer publish their request file and poll for the answer across the mapped drive; the ArcRho Gateway does that work next to the data and the Bridge answers it from local disk.
  - The comparison now reads each method file once instead of two and three times, which speeds up the review window even when the Gateway is unavailable.
  - A sync request now records the person who started it rather than the account the service runs under.
  - A Client PC without the Gateway keeps working exactly as before.
- **dataset**: A broken Excel link now opens an alert in the Dataset or DFM window naming the reference to fix, and the affected cells stay red until it is.
  - Opening a Dataset or DFM method validates its saved Excel references on the server in one pass; a broken reference is reported instead of the "Linked Excel File Updated" prompt.
  - The alert names each failing workbook cell, the grid cell it feeds, and the reason, and opens the workbook in Excel.
  - Saved values are kept, and cells whose reference failed render in red until the reference is fixed or the link is broken.
  - Refresh from Excel reports named references in the same alert rather than only in the status bar.
  - Empty cells inside a linked Excel range are accepted as blanks and shown as muted grey zeros instead of failing the range.
- **build**: When setup cannot register the Excel add-in, it now shows how to add it by hand instead of a raw PowerShell error.
  - The dialog gives the File > Options > Add-ins steps for the add-in path on the ArcRho Server share.
  - It also names the Trust Center change that lets setup do it automatically next time: allow trusted locations on the network and trust the Excel Add-ins folder.
  - The underlying error text stays in the installer details panel for support.
- **dataset**: The "Updated Outside This Window" alert now names who or what changed the open object.
  - Names the user who saved it, or the automation task that rewrote it (for example an automatic dependent refresh) and the account that task ran as.
  - Shows the time the change was recorded, in local time.
  - Reads the attribution once, only after a change is detected, so the open-window watch costs the same as before.
- **project instance**: Project Instance notices another user's dataset changes on its own and offers a Refresh Table button, in every host rather than only in the desktop app.
  - The dataset table checks the selected reserving class's index every few seconds and compares it with the copy it loaded, instead of relying on a desktop-only folder watcher.
  - The prompt that appears is now labelled Refresh Table, so it reads as the action it performs rather than as a status.
  - Changes you make in your own window are adopted silently, and the check pauses while the window is hidden and catches up as soon as you return to it.
- **project settings**: Every Project Settings tab now shows the same flowing loading placeholder while it reads the project, instead of a bare "Loading ..." line.
  - Field Mapping, Reserving Class Types, Dataset Types, Data Processing Rules, and Audit Log fill their grid with placeholder rows shaped like the table that is arriving, matching the effect Source Data already used.
  - Selecting a different project puts all of the tabs into that state at once, so the page reads as one load rather than six unrelated messages.
  - A tab whose data is already loaded for the selected project skips the placeholder instead of flashing it, and reduced-motion mode shows a static placeholder.
- **project instance**: The Sync Reserving Class with ResQ review window now shows its actions in the same table as the Project Instance dataset list, with sortable, filterable, resizable, and reorderable columns.
  - Columns open sized to their own contents, can be dragged wider or narrower, double-clicked back to that sizing, and dragged into a different order.
  - Click a column heading to sort by it, or its filter button to keep only the values you pick; the search box still narrows every column at once.
  - Clicking anywhere on a row ticks or unticks it, and a ticked row is highlighted the same way a selected dataset row is; Shift-click ticks a whole run at once.
  - Dragging across rows no longer selects their text, and ticked rows no longer carry the dataset table's left marker bar, which pointed at a keyboard target the review window does not have.
  - A proposed direction such as ArcRho -> ResQ now draws a real arrow instead of a hyphen and a greater-than sign.
  - The window now follows the Dark and High Contrast themes, which it previously ignored.
  - Grouping is the one dataset-table feature the review window does not offer, because a review lists the actions of a single sync run.
- **shell**: Refined shared toolbar icons and made developer builds easier to distinguish.
- **shell**: Every tab in the main tab bar now shows a small icon for what it is.
  - Home, Project Instance, Project Explorer, My Workspace, Dataset View, DFM, Bornhuetter Ferguson, Cape Cod, Result Selection, Workflow, Arcode, ArcBot Guide, Browsing History, and Task Designer each have their own icon.
  - The icon sits at the left of the tab title and brightens on the tab you are working in.
  - A tab with no icon of its own shows a plain page instead, so nothing is ever blank.
- **update**: The update prompt now scrolls, shows the notes for every version you skipped, and reports the download in megabytes.
  - Upgrading from 1.4.0 straight to 1.4.2 now shows the 1.4.1 notes as well, one collapsible section per version.
  - Release notes open in an in-app window with its own scrollbar instead of a message box that could grow taller than the screen, so per-change detail bullets are no longer dropped.
  - About > Release History lists the notes for every version bundled with the installed build, and works with no network connection.
  - The update download window now reads 64.0 MB / 256.0 MB (25.0%) instead of a raw byte count.

### Fixes
- **dataset**: Restored Dataset Viewer and Berquist Sherman Number Format fields to the compact width used by Decimal Places.
- **shell**: Progress windows such as Refresh Source Table now keep a fixed size.
  - The window no longer grows or shrinks when the main app window is resized; it only moves to stay fully visible.
  - The corner resize handle was removed; the window can still be dragged by its title bar.
  - The default width is wider, so a reserving-class path plus a dataset name fits without truncation.
- **project settings**: Dataset Types edits are saved reliably: the table can no longer keep accepting changes that never reach the file.
  - A Dataset Types save used to rebuild every reserving class's dependency graph inside the request. On a large project that request could run for minutes without answering, and every edit made afterwards was silently dropped while the grid still showed it.
  - Saving now answers immediately. Adding a dataset type, renaming a Category and reordering rows are written straight away.
  - Removing a type, or changing one's Data Format, Calculated flag or Formula, runs on ArcRho Engine as a project-wide job. Project Settings waits behind a progress window showing the current step and how many datasets of the total have been updated, then reports what the change did.
  - Deleting a dataset type is now refused while any dataset of that type is still used by another dataset or method, naming what still reads it. Nothing is saved when that happens.
  - That job locks the whole project while it runs, and refuses to start while any reserving class is still being updated, so a dataset type change can no longer race the data it defines.
  - If a save cannot be confirmed, Project Settings now says so and keeps your edits instead of appearing to have saved them.
- **dfm**: After sending a DFM or Result Selection method to the ResQ server, the next sync no longer reports ResQ as the newer version when nothing has actually changed.
  - ResQ stamps its own modified time when it saves, so an upload used to leave the two copies holding identical settings under different times, and the review window then offered to pull back the values just sent.
  - A confirmed remote update now records the time ResQ itself reported for that save against the local method, so the two compare as the same version.
  - Only the recorded time changes: the method's contents and any dependent refresh are untouched.
  - A Result Selection method's saved-version check now covers its contents rather than the whole file, so recording that time cannot make an open method look out of date.
- **dataset**: Saving a dataset or method no longer raises a spurious "Updated Outside This Window" alert about your own save.
  - A mapped-drive read can report file details several seconds out of date, so the window could baseline on the state from before its own save and then report that save as an outside change.
  - A change is now reported only when the object's recorded write is newer than the one the window already has in view.
  - A rename or Save As no longer lets the window start watching again while the save is still writing.
- **project instance**: The dataset table's Refresh Table prompt no longer appears for saves, propagations, deletes, or Excel-link retargets you triggered yourself.
  - The table load now carries the index fingerprint recorded by the process that wrote the file, so the staleness check starts from the truth instead of a mapped-drive stat that can lag ~10 seconds behind a server-side write.
  - A polled fingerprint older than that baseline is recognized as the network drive's metadata cache echoing the past and is ignored; only a genuinely newer write - another user's or another app session's - shows the prompt.
- **macro**: A ResQ item that cannot be exported is skipped by name instead of failing its whole reserving-class import.
  - The Bridge now commits the rest of the reserving class and reports each skipped item; any existing ArcRho copy of a skipped item is kept under both Merge and Overwrite.
  - Both import macros list the skipped items by name in their completion message, so the operator sees exactly which methods to repair in ResQ.
  - A blank method input is reported by the ResQ field that needs fixing (Latest, Exposure, Perc Developed, or Prior) rather than a generic precedent error.
- **project settings**: Importing the source table again now really rebuilds every generated dataset.
  - The refresh job previously finished green while rebuilding nothing, because it read dataset names from the class index under the wrong field.
  - Downstream calculated datasets and methods are refreshed again after the rebuild, so their timestamps move with the import.

### Breaking Changes
- **workspace files**: Every stored ArcRho file moves to one naming convention and drops the fields that restated other fields. This release must be installed by everyone, and the workspace is converted once before it is opened.
  - Field names in stored files now read the same way everywhere: lower case, words joined by underscores, no spaces and no capitals, however deeply nested. Development factor methods were the last kind still using spaced names.
  - Fields that only repeated something already in the file are gone, along with anything that tied a shared file to one computer: no drive paths, no file timestamps, no code numbers beside the name they stood for. A ratio triangle keeps its own row and column headings on purpose, so the method still reads as a complete table.
  - Every stored file now states which format it is in, every time is recorded in UTC to the millisecond, and the values used to tell whether something is out of date are much shorter. Stored files are about a fifth smaller overall, and dataset files, which are read on every folder scan, are more than a third smaller.
  - History is now kept the same way in every file. Automatic refreshes are no longer thrown away, one dataset keeps its last 200 entries and a project keeps its last 500, and a project's history reads in the same shape as a dataset's.
  - There is no reading of the old shape at all. An older copy of ArcRho cannot open a converted workspace, and this version cannot open an unconverted one, so everybody has to update together.
  - Notes written inside a method are moved into that method's dataset before the old section is removed, so authored commentary is never lost. A handful of Bornhuetter-Ferguson methods saved in a format ArcRho stopped opening some time ago are left exactly where they are, and their notes are rescued the same way.

## Internal Notes

- **build**: ArcRho Engine now records what each hosted save's inline dependent walk refreshed.
  - The walk runs inside the save and never reaches the durable queue, so it left no line in dependent_propagation.log and a save was recorded only as "success".
  - hosted_saves.log now names the refreshed datasets, an unchanged publication, and a failed walk's reason.
