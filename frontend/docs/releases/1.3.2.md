# Release 1.3.2

Released on 2026-08-18.

## User-Facing Changes

### Features
- **dataset**: Added a per-dataset Show/Hide subtotal command to the Data grid right-click menu.
- **dfm**: DFM Ratios User Entry formulas can now pull values from datasets in the current Reserving Class.
  - Vector references use [Dataset][row] or [Dataset][row, 1].
  - Triangle references use [Dataset][row, col], with one-based positions or axis labels.
  - Typing [ opens a searchable list of dataset instances in the current Reserving Class.
  - Negative positions count backward after trimming trailing out-of-valuation Vector cells or Triangle diagonals; nulls inside the valid range are preserved.
- **dfm**: DFM Ratios formulas now show each dataset and resolved coordinate together in one compact reference pill that opens the dataset in Dataset Viewer.
  - Rendered dataset pills use the Dataset @ Coordinate style, show labels instead of numeric positions such as [-1], and preserve the original relative formula for editing.
  - Hovering or keyboard-focusing a dataset pill shows the referenced cell's actual numeric value instead of a navigation hint.
- **shell**: Added a High Contrast color theme that keeps the Light palette and renders spreadsheet text in pure black.
- **project instance**: Added a reserving-class Excel Link Manager that lists every linked workbook and can repoint one workbook for all datasets and DFM methods at once.
  - A new toolbar button opens a floating window showing each linked workbook, whether the file exists, and which datasets and DFM methods use it.
  - Change... opens a file picker and relinks every saved reference in the reserving class to the selected workbook.
  - By default stored values keep their current snapshots until links are refreshed from a Dataset or DFM Links tab.
  - An optional checkbox, defaulting to No for every change, also recalculates all affected datasets and DFM methods from the new workbook, including dependent recalculation.
  - The window follows the selected reserving-class path automatically.
- **links**: Added normal and read-only workbook open commands to Dataset Viewer and DFM Links menus.
- **build**: Added a separate ArcRho Server Components installer for deploying and maintaining the data engine on a new host PC.
  - The server workspace can use any user-selected folder on a local fixed disk.
  - Desktop Setup detects an existing configured deployment but never owns its shared binaries.
- **automation**: Added reviewed, timestamp-based two-way reserving-class sync between ArcRho and ResQ.
  - Every dataset and method-output row shows both ArcRho and ResQ timestamps before the user accepts selected actions.
  - The reusable searchable review table supports disabled actions, select-all, and asynchronous accept or cancel results.
- **dataset**: Saving a dataset or method now runs on ArcRho Engine next to the data, finishing in a few seconds with a short summary of the refreshed datasets.
  - The save and its dependent updates execute on the server host instead of over the network share, cutting a typical save from ~30 seconds to a few seconds.
  - After a clean save, a brief notice inside the window lists the exact dataset instances that were refreshed, then the window closes (explicit Save only; Save As, Sync, and Excel bridge saves keep it open).
  - Save conflicts and validation errors report exactly as before, and a save whose dependent updates hit review-needed items leaves the window open with the affected items flagged.
- **build**: Added a Release Manager for custom-version local builds, deliberate GitHub publishing, history, and guarded release revocation.
  - Runs as a local browser app on 127.0.0.1 with a dark theme by default and an optional light theme.
  - Build-only installers can be tested locally before any GitHub or shared-wheel publication.
  - Pending installers are hash-checked again before publication.
- **arcode**: Added workspace folder add and remove controls to the Arcode file explorer sidebar.
  - The explorer header now has an add-folder button next to Refresh that opens the same folder picker as File > Add Workspace Folder.
  - Hovering a workspace root shows a remove control that takes that root out of the explorer without deleting anything on disk.
- **arcode**: Arcode can now add, edit, and run against SQL Server connection profiles from a new SQL Server console.
  - SQL Server files open in their own console with a connection picker, Test, Run, Format, and a results grid, instead of the plain text editor.
  - A Connections dialog adds, edits, renames, removes, and sets the default connection; each profile holds a name, server, and database.
  - Queries run as your Windows account, so no password is asked for or stored.
  - A `.sql` file opens in the SQL Server console when its name contains sql_server, sqlserver, or mssql, or ends in .ms.sql, the same way Snowflake files are recognized.
  - Run and Test stay disabled until a connection is selected, and a missing ODBC driver is reported with what to install.
- **project instance**: Deleting a dataset or method is now refused while another object still uses it as an input, and the refusal lists those objects as links.
  - Nothing is removed when the check refuses, so the dataset table is unchanged and the selection stays as it was.
  - Each blocking dependent opens in its own method or dataset window from the message, so the input can be cleared there before deleting again.
  - Selecting a method together with the input it consumes still deletes both, because nothing is left pointing at a missing object.
  - The delete now runs on the ArcRho Server through the Gateway when it is available, so removing files and rebuilding the dataset index no longer costs a network round trip per file.
- **project instance**: Manage Excel Links now shows Last Modified, Created, and User for each linked workbook, the same three columns the dataset table shows for a dataset.
  - The values are the workbook's own document properties, so they follow the workbook when it is copied or moved instead of resetting like a file's creation date, and User names whoever last saved the workbook.
  - Each column filters and resizes like the existing ones, and the two dates read in the same format as the dataset table's.
  - A workbook with no readable properties - a legacy .xls or an encrypted file - leaves the three columns blank and is still listed and still relinkable.
  - ArcRho Server reads the properties in the same pass it already uses to check each workbook, so a listing costs no extra trip across the network drive.
- **project settings**: Importing a project's source table now runs on ArcRho Server and refreshes every dataset and method that depends on it, with live progress.
  - A CSV on a network share is copied by the server instead of being pulled through your PC from one share and pushed to another, and the table summary, reserving-class values, and header caches are rebuilt there too.
  - After the import the job walks the project's dependency graph: every engine-built dataset instance is regenerated and the DFM, Bornhuetter Ferguson, Cape Cod, Result Selection, and Bootstrap methods that use them are re-run, instead of each object recomputing whenever it is next opened.
  - A progress window reports the current stage and reserving class, and the job survives closing or reloading Project Settings: reopening the project re-attaches to the refresh still running on the server.
  - Saves into a reserving class the refresh is rewriting are held with the same message a dependent update already shows, and a second refresh for the same project is refused while one is running.
  - A SQL Server import, or a CSV only your PC can open, is still copied here; the dependent refresh runs on the server either way. With no ArcRho Engine available the import behaves exactly as it did before.
  - The CSV path saved in Project Settings is now stored as its network share path rather than your machine's drive letter, so every machine reads the same file.

### Improvements
- **admin control**: Added single-click access-row selection and inline access-level editing in Folder Access.
- **dataset**: Manual Dataset Excel ranges now accept blank source cells and display them as muted formatted zeros.
  - Opening a manual Dataset Viewer dataset now warns when a linked Excel workbook is newer, with options to keep stored values or refresh them as unsaved changes.
  - Dynamic-array highlights now retain their blue left border beside sticky row labels.
  - The linked-cell formula editor now has an 879px maximum width while remaining constrained to the viewport.
- **project settings**: Dataset Type Category now suggests existing categories while allowing new categories with clear inline feedback.
- **project settings**: Dataset Type Data Format is now selected from Triangle or Vector instead of entered as free text.
- **frontend**: Simplified the unsaved-changes close confirmation and relabeled its secondary action to No.
- **dataset**: The Dataset Viewer's linked-cell formula editor now looks and behaves like the DFM Ratios formula bar.
  - It sizes itself to the formula it shows, capped by the visible grid frame, instead of a fixed 879px panel.
  - The formula renders colorized and read-only until you focus it, and the bar re-measures on that swap so nothing is clipped.
  - Clicking a linked cell pins the editor open and clicking it again releases it; hovering still opens it transiently.
  - The DFM Data tab uses the same shared editor, so it picks up the same look.
- **project settings**: The Add/Edit Dataset Type dialog now opens an app-styled Data Format list instead of the browser's native dropdown.
  - The list matches the Category picker beside it: trigger-aligned width, compact hover and selected rows, and correct colors in Dark and High Contrast themes.
  - The field can be opened and navigated from the keyboard, and shows a muted 'Select data format' placeholder until Triangle or Vector is chosen.
  - Triangle and Vector remain the only accepted values, and a rejected save now returns focus to the visible field.
- **dfm**: Saving a dataset referenced by DFM User Entry formulas now refreshes the dependent DFM automatically, so the DFM opens clean with updated values and a Needs Review flag.
  - The Engine dependent-propagation walk re-resolves the dataset references, re-evaluates the affected User Entry values, republishes the method JSON and output CSVs, and marks the method Needs Review.
  - Opening the DFM no longer shows unsaved changes; review the refreshed values and save once to clear the Needs Review flag.
  - A blank or non-numeric referenced cell aborts the automatic refresh and keeps the last valid published values.
  - Formula evaluation reads referenced average-formula rows from the canonical six-decimal values instead of the displayed rounded text, so evaluations match the persisted values exactly.
- **dfm**: The DFM Ratios formula bar now floats above the cell it edits, and follows a linked dynamic array when you hover it.
  - Hovering any cell of an Excel-linked dynamic array shows the shared range formula directly above that array; moving off it returns the bar to the active cell.
  - The bar sizes itself to the formula it shows, never extends past the visible ratio frame, and re-applies both rules as you type, as you leave edit mode, and when the window is resized.
  - The bar no longer reserves a fixed frame above the summary ratios table, so the Ratios grid gains that vertical space.
  - Clicking a User Entry cell toggles its formula bar, so it can be dismissed to read the cells underneath; this works the same in Select and Edit mode.
  - The paste, refresh, and open-in-Excel buttons are gone from the bar; refreshing linked values and opening a source workbook remain Links tab actions.
  - Hover and the click toggle are both ignored while the bar is being edited or a commit is pending.
- **dfm**: DFM User Entry formula evaluations now display referenced values and outcomes with exactly four decimal places.
- **dfm**: DFM User Entry formulas that mix dataset references with average-formula row references now re-evaluate immediately when a referenced row changes.
  - Changing ratio exclusions in the Ratios triangle updates dependent User Entry formula values right away.
  - The dataset-reference portion reuses its last resolved session value without a new precedent read.
- **scripting**: Macro Notes diff previews highlight changed phrases as one connected fill instead of per-word patches.
- **macro**: The Sync Reserving Class with ResQ review table now opens as a nested Project Instance window instead of a modal dialog.
  - The review window can be minimized to the Project Instance toolbar and restored later, so the dataset table and open windows stay reachable while reviewing.
  - Closing the review window cancels the synchronization cleanly instead of leaving the macro waiting.
  - Shells without an active Project Instance page keep the previous modal review dialog.
- **dfm**: The DFM window now shows a saving animation with a spinner while a save is running.
  - Saving blocks page edits behind a centered spinner card that reports the current step and elapsed time.
  - The animation covers every save entry point, including the Save bar, keyboard save, Save As, and Excel bridge saves.
  - It clears before the post-save review dialog or any save error message so no dialog opens behind it.
- **methods, dataset**: Every method window and the Dataset window now show the same saving animation while a save is running.
  - Result Selection, Bornhuetter Ferguson, Cape Cod, Berquist Sherman, and Dataset saves join DFM behind one centered spinner card that names the object being saved, reports the current step, and shows elapsed time.
  - The animation covers every save entry point in each window, including the Save bar, keyboard save, and saves a sync dialog runs first.
  - It clears before the post-save review dialog, the dataset recalculation dialog, or any save error message so no dialog opens behind it.
- **dataset**: While dependent updates run for a reserving class, other saves into that class are paused so edits cannot collide.
  - Saves into a busy reserving class are refused with a clear message until the walk finishes; other reserving classes are unaffected.
  - Project Instance quietly pauses dataset add/delete actions for the busy reserving class; a blocked action explains itself in the status bar.
  - The Engine heartbeats each job's status every few seconds, so a dead worker releases the hold and the save popup within about a minute instead of blocking.
- **save**: Save and dependent-update review responses no longer wait for queue-file cleanup on the network drive.
  - The save result returns as soon as ArcRho Engine reports it; leftover queue files are removed in the background, saving roughly a quarter second per save step on network-drive installs.
- **ui**: Project Instance dataset table shows which selected row Enter will open and only offers Add > DFM for triangle datasets.
  - In a multi-row selection all selected rows share the same background, the last-selected row alone keeps the solid blue left-edge bar while the others switch to a hollow left bar, and Enter now opens that emphasized row (previously it opened the Shift-range anchor).
  - Right-clicking always targets the row under the mouse pointer: outside the selection it collapses the selection to that row, inside it the emphasis moves to that row.
  - Add > DFM is disabled with an explanatory tooltip unless the row is a triangle dataset with Method Type None, matching the other Add method entries.
- **project instance**: Saving a dataset or method window no longer closes it.
  - Dataset, DFM, Result Selection, Bornhuetter Ferguson, Cape Cod, and Berquist Sherman windows stay open after a successful save.
  - The saved-dependents notice still names the dataset instances the dependent walk refreshed; Cancel, the titlebar close, and the close shortcut still close the window with the usual unsaved-changes confirmation.
- **hosted saves**: Extended the faster HTTP save transport to every dataset and method save.
  - Bornhuetter Ferguson, Cape Cod, bootstrap, and result-selection saves now take the same server-local HTTP path as dataset and DFM saves.
  - A save kind stays on the previous transport while the deployed gateway is older than that kind, so an upgrade in progress never fails a save.
- **project instance**: Reserving-class listings, dataset and method window loads, and the Project Settings table summary can now load through the ArcRho Server instead of the network drive.
  - When the ArcRho Gateway advertises the read, the server reads the reserving-class index, cached dataset, method JSON, or master table on its own disk and returns only the result, so a stale index rebuild or a large table summary no longer opens every file over the mapped drive.
  - A read the gateway does not advertise, or that cannot reach the gateway, loads locally exactly as before; the transport used is recorded in the local client_read_latency.jsonl diagnostics log.
- **arcode**: Refreshed the Arcode workspace layout so panes meet at a single hairline seam and toolbars show actions instead of repeated labels.
  - The file explorer and the open editor are now separated by one thin line instead of a blank gutter, so the editor toolbar, Output panel, and its header all have a visible left edge.
  - Removed the Arcode Workspace title from the explorer header and the file name and status labels from the code editor, notebook, and Snowflake toolbars; the tab names the file and the status bar reports state.
  - Clear Output moved from the code editor toolbar to an icon action in the Output panel header, next to the run timing.
  - Save and Save As left the code editor toolbar; they stay on the File menu and on Ctrl+S and Ctrl+Shift+S.
  - Toolbar commands are flat until hovered, with the tinted highlight kept for Run, Run All, and dialog confirmations, and Restart no longer painted as a destructive action.
  - Home create cards now lift on hover without the blue glow, and folder and panel titles read in normal case instead of all capitals.
- **berquist sherman**: Opening a B&S method now takes one Server-hosted read instead of several mapped-drive reads, so the page appears faster on a Client PC.
  - The method JSON and the output sidecar are fetched together and served by the ArcRho Gateway, like the other method pages.
  - The dataset index and the page open no longer wait for each other.
- **dfm**: User Entry formulas in DFM Ratios now edit only through the formula bar.
- **dataset**: Dataset, vector, and header calculations from a Client PC now run through the ArcRho Server instead of writing request files and polling the network drive.
  - When the ArcRho Gateway advertises it, changing origin/development length, running, or refreshing a dataset posts the whole request over HTTP: the server validates the cache, publishes to the data engine, waits on local disk, and writes the sidecar and dependent updates itself, so the Client PC no longer pays dozens of network-drive operations per run.
  - Header-cache and other engine exchanges post the request the same way and only wait for the finished CSV to become visible on the mapped drive.
  - Requests still fall back to the network-drive exchange when the Gateway is unavailable, and an accepted request is never sent twice.
  - Requests published on a user's behalf are stamped with that user, not the server's service account.
- **project instance**: Sped up the reserving class path list when a Project Instance opens against a network drive.
  - The path list and its saved filters now load together instead of one after the other.
  - Reserving class types and tree preferences are each read once per load rather than several times.
- **project settings**: Selecting another project in Project Settings clears the previous project's details immediately instead of leaving them on screen while the new one loads.
  - The detail panel switches to the new project's title and each tab's loading state as soon as the selection changes.
  - Source Data drops the old source path, column list, table details, and reserving-period months and shows its busy frame until the new summary arrives.
  - Field Mapping, Reserving Class Types, Dataset Types, Data Processing Rules, and Audit Log show a loading row rather than the previous project's rows, and Save Field Mapping is no longer left actionable from the project you switched away from.
- **dataset and methods**: Expanded Ctrl+PageUp and Ctrl+PageDown tab switching to every Dataset and method page.
- **frontend**: Reworked the post-save dependents notice: it is silent when nothing was refreshed, and lists each refreshed dataset as a link that opens its page.
  - A save that refreshed no dependent datasets no longer shows the "No dependent datasets required updates." popup.
  - When dependents were refreshed, the Saved notice shows one dataset name per row and stays open until you close it or click elsewhere in the window, instead of disappearing after two seconds.
  - Clicking a name opens that dependent's method page, or its dataset page when it is not a method output.
- **arcode**: Added a "Workspace" title back to the Arcode file explorer header, next to the add-folder and refresh actions.
  - The title is a generic section label; it does not repeat the active folder name, which the workspace root row already shows.
- **shell**: Submenus such as Settings > Color Theme stay open while you move the pointer toward them.
  - The gap between a menu and its submenu is no longer a dead zone that closes the submenu.
  - Leaving the parent row starts a short grace period instead of closing immediately.
  - Reaching diagonally across the rows below keeps the submenu open until you arrive.
  - A submenu near the window edge flips to the other side of its menu instead of being clipped.

  - The read-only Project row, and the Method Type row on Berquist Sherman, no longer take up a form row wherever the host supplies them; a Workflow step still shows Project because it is the one host where you choose it inside the page.
  - Details labels are one size and one solid black on every page, so the Dataset Viewer no longer renders them a step larger and greyer than the method pages.
  - Berquist Sherman Details fields now use the shared field height, padding, border, and focus ring instead of their own slightly different palette.
  - Berquist Sherman Number Format replaces its three-dot picker and floating menu with the same in-field caret and preset dropdown the Dataset Viewer uses; both pages now drive one shared control.
- **ui**: Every Details tab now opens on Name, puts the output identity second, calls the reserving-class row Segment, and lists its fields as one evenly spaced group.
  - Name is the first Details row and Dataset Type (Output Type on the method pages) is the second on the Dataset Viewer, DFM, Bornhuetter Ferguson, Cape Cod, Berquist Sherman, and Result Selection.
  - DFM calls its output row Output Type instead of Output Vector, matching the other method pages; the saved method JSON is unchanged.
  - The reserving-class row is labelled Segment on every Details tab.
  - Details fields are one evenly spaced list: the extra padding and gaps that split them into panels are gone.
- **project instance**: Manage Excel Links now lists one row per dataset or DFM method, with resizable, filterable columns and more row actions.
  - A workbook used by two datasets shows two rows naming them, replacing the "2 datasets" summary cell.
  - Clicking a name opens that dataset in Dataset Viewer or that method in the DFM page.

  - Columns resize by dragging a header edge (double-click restores the default width) and filter from the header, like the dataset table.

  - Listing a reserving class's Excel links opened every dataset sidecar and DFM method file across the network drive, which cost about three seconds for a class with roughly 140 files.
  - That scan now runs on the ArcRho Server machine when the Gateway is available, where those files are local disk; it falls back to the previous behavior unchanged when the Gateway is off or unreachable.
  - Whether each linked workbook still exists is checked on your own PC, so workbooks on shares only your PC maps keep showing as Found.

  - The window is now tied to the reserving class it was opened on and its title shows that path, matching every other nested window. It no longer follows the tree selection; open the button again on another class to get a second window for it.

  - The Snowflake and SQL Server editors gained the code editor's workspace explorer, file open/save, Save As, and changed-on-disk handling.

### Fixes
- **berquist sherman**: Fixed B&S Method triangles to leave unavailable lower-right cells blank instead of displaying padded zeroes.
- **dataset**: Improved the linked Excel update dialog with separated, evenly balanced action buttons.
- **dataset**: Restored linked-cell borders and stabilized the Excel formula bar above linked array ranges.
  - The formula bar now stays in one position while the pointer moves across cells in the same linked array.
  - The bar positions from the full array boundary so it does not cover linked cells.
- **dfm**: DFM Ratios formula formatting now preserves all content inside square brackets.
- **dataset**: Made the complete dynamic-array outline continuous across Dataset cells and visible above the Total row.
- **dfm**: Preserved red excluded ratio text in the High Contrast theme.
- **macro**: Macros no longer fail with 'Project Instance window was not found' when run without an open dataset or method window.
  - The active-window automation query now reports 'no active window' instead of an error, so macros like Sync Reserving Class with ResQ run directly from the dataset table view.
- **dataset**: Fixed newer linked Excel workbook refreshes so unchanged values still mark the Dataset dirty and Save records the refresh.
- **dataset**: Changed Excel-linked Dataset values to use the same normal dark font as other grid values.
- **dataset**: Saving a dataset or method now records the configured full name instead of the Windows login name.
  - The name comes from the workspace-global config/username_index.json and is resolved once per app session.
  - An unmapped login keeps its login name, and existing rows keep their stored name until they are saved again.
- **dfm**: DFM dataset formulas now participate in dependency review and refresh automatically when the method opens.
  - Saved formula datasets appear in Precedents and their sidecars list the DFM output under Dependents.
  - Updating a formula input dataset marks the downstream DFM Review Needed.
  - Opening a DFM with dataset-backed formulas marks it dirty immediately and reports the in-memory formula refresh in the status bar.
- **dfm**: Added clear spacing between the DFM formula bar's leading equals sign and its first reference pill.
- **dfm**: Prevented Ratios-table drag gestures from applying the same cell more than once.
- **scripting**: Macros can run against a DFM with unsaved edits without failing revision validation.
  - The macro runtime re-stamps canonical revisions on the captured in-memory DFM payload instead of rejecting it with 'DFM method metadata.owned revision does not match the canonical payload'.
- **scripting**: Accepting a macro's Notes preview now updates the DFM Notes tab so the next Save persists the generated notes.
  - Macro update_notes() results ride in the transient method metadata carrier used by the DFM RPC bridge; canonicalization keeps them out of persisted method JSON.
- **project instance**: A dataset instance of a newly added dataset type no longer appears under a blank Category.
  - The dataset table now reloads the project's Dataset Types with each table refresh, so Data Format, Category, and Formula follow types added or edited in Project Settings while the project tab stays open.
- **dfm**: Fixed saving a DFM after changing Origin Length, which failed with a Ratio Basis alignment error.
  - Changing the origin basis now re-reads the Results Ratio Basis column on the new origins instead of keeping the column saved on the previous basis.
  - Save and its preview wait for that re-read, and a Ratio Basis that still cannot be aligned is reported by name instead of as a contract error.
- **save**: Saved datasets and methods once again record the person who saved them instead of a random ArcRho Engine account.
  - Saves and dependent updates run on ArcRho Engine, whose instances sign in under their own profiles; the request now carries the editing user, so the User column in the dataset table and the sidecar and audit records name the right person no matter which instance handled the save.
  - Rows saved before this fix keep the account they were stamped with until the object is saved again.
- **berquist sherman**: Fixed both B&S methods to mask the unavailable area of every Method triangle and aligned the Details tab with the other method pages.
  - Cells outside the annual triangle no longer print 0: they show no value and no grid line, matching the Dataset Viewer.
  - A cell with no calculated value inside the triangle is blank instead of 0.
  - Details pickers moved inside their field, the Decimal Places spinner no longer stretches the full width, and the source groups use the standard spacing.
- **dependent propagation**: Saving a Berquist Sherman method no longer waits about 15 seconds after its dependent updates have already finished.
  - Dataset sidecar saves now run their dependent walk on ArcRho Engine like every other method save, instead of queueing a job the client had to poll for.
  - The poll read the job status over the network share, where Windows caches the file for up to 10 seconds and hid a result that was already written.
- **installer**: The Setup Options page of ArcRho Desktop Setup no longer cuts off its checkboxes.
  - Every control now fits inside the installer's page area, with the option checkboxes above the bottom edge.
  - The explanatory text on the page was shortened so it reads in one or two lines.
- **scripting**: Macros now read the DFM Notes tab as it is on screen, so a Notes preview compares against unsaved notes instead of the last saved copy.
  - The DFM assistant/macro context payload carries the live Notes tab text, and active_dfm.notes is seeded from it instead of falling back to the persisted output sidecar.
  - A macro that never calls update_notes() still leaves the Notes tab untouched, and editing Notes while a macro runs invalidates its captured context as before.
- **dfm**: A DFM Ratios cell with no ratio now shows the grey 1.0000 placeholder after loading a saved method, instead of a false 0.0000.
  - An origin period whose value is zero has no link ratio, but reopening the method drew that cell as a calculated 0.0000 that no column average reflected.
  - Reading a stored or calculated ratio now goes through one shared helper, so an empty cell can no longer be read as a ratio of zero.
- **dfm**: Dragging a Ratios formula reference onto another row now clears the blue fill from the row it came from.
- **dfm**: Fixed macros and ArcBot failing on a DFM whose triangle contains zero rows, with "DFM exclusion rows must match the corresponding ratio-value rows".
  - An origin period with a zero value has no ratio, but the live method payload recorded it as a ratio of 0, so the ratio triangle and the exclusion pattern no longer had the same shape and strict validation rejected the method.
  - The saved method file was never affected; only the in-memory payload handed to macros, ArcBot, and the RPC bridge.
- **app server**: UI pages no longer break after an update with a blank page and a missing-export error in the console.
  - The app served UI script files without a cache directive, so the browser could reuse an old copy of one file next to a freshly downloaded copy of another.
  - A mismatched pair stopped the page from loading at all; the DFM method window was the most recent to hit it.
  - UI assets are now revalidated against the server on every load, so an updated file is always picked up.

## Internal Notes

- **build**: ArcRho and Arcode can now be built and released from the PC that holds the repository, without a second build PC.
  - build/build_app_from_local_repo.bat validates prerequisites, builds in place from the repository, publishes the GitHub Release, and commits the release bookkeeping it produced.
  - build/build_app_via_local_workspace.bat gained ARCRHO_BUILD_IN_PLACE, ARCRHO_BUILD_LOG_DIR, and ARCRHO_BUILD_VERSION_OUT; unset, the two-PC ZIP workflow behaves exactly as before and both entry points share one build body.
  - An in-place build writes the version bump, release notes, and fragment archive straight into the working tree, so sync_published_release.py --bookkeeping-only only refreshes the documentation index and commits instead of reconstructing the release.
  - The prerequisite check smokes the bundled ArcBot/Codex runtime and the Python API package destination up front, so an incomplete node-portable or a disconnected network drive fails in seconds rather than after a full package.
  - Removed build/build_arcode_one_click.bat, which was a byte-identical duplicate of the canonical copy in build/build_share.
  - docs/build/packaging.md no longer documents build_app.bat and build_app_from_network.bat, which no longer exist.
  - frontend/build is reorganized so the six scripts a human runs sit at the top level beside a new README, and helpers move into docs/, installer/, release/, transport/, arcbot_runtime/, and helpers/.
  - The PyInstaller specs and entry points deliberately stay at the top level, because they resolve BASE_DIR inside the frozen application and .gitignore covers *.spec with a per-file exception.
- **hosted saves**: Reduced hosted-save network round trips and added rotating local timing diagnostics.
  - The client now reuses preflight validation, treats the request as queued state, waits before its first poll, and reads successful responses from the terminal status.
  - Successful protocol-path safety checks are cached for 30 seconds while heartbeat and reserving-class hold checks still run for every save.
  - Each save records preflight, request publication, status polling, response source, and total elapsed time without storing method payloads.
- **server components**: Renamed the ArcRho Save Gateway to ArcRho Gateway, now that it carries workspace reads as well as saves.
  - The component was named after the first workload it carried; it now serves reserving-class index, cached dataset, method, and table-summary reads too.
  - ArcRho Gateway is a bare role noun like Engine, Bridge, and Orchestrator, so future transports cannot make the name stale again.
  - The deployed app folder, heartbeat folder, config keys, server registry, per-user credential, and receipt store all move to the new name, with no legacy name accepted.
  - Enrolled users are re-enrolled automatically on next startup because the client credential file moved.
- **development tools**: Added a localhost control center for launching, fully relaunching, resetting, and inspecting ArcRho development mode.
  - Project-user preference resets retain a timestamped backup before ArcRho relaunches.
  - The folder inventory exposes ArcRho's local preference, cache, log, runtime, and user-file locations.
- **development tools**: Moved the development control center off the Gateway's port.
  - The page now serves on 127.0.0.1:28768; sharing 28767 meant whichever of the two started first silently kept the port and the other failed to bind.
- **server components**: Held ArcRho Engine and Gateway to their configured instance caps when several users are signed into the server.
  - Each signed-in user's Orchestrator used to fill the same shortfall at the same time, so a five-worker cap produced eight or nine Engines.
  - Replenishment now waits for a launched component to publish its heartbeat instead of assuming a fixed startup time.
  - A component that fails to start is launched once per pass rather than once per missing instance.
  - The Gateway now refuses to share its port, so a second copy exits instead of serving part of the traffic.
- **development tools**: Development Control Center now dismisses its launch overlay after ArcRho starts.
- **dependent propagation**: ArcRho Engine now writes a dependent-propagation log so a slow or failed dependent update can be diagnosed from the server.
  - runtime/logs/dependent_propagation.log records each job's queue wait, claim, per-stage elapsed time, and terminal outcome.
  - Failure lines keep the dataset names and full reason that the client-facing status message truncates.
  - The Engine's three runtime logs now share one appender with common rotation.
- **server deployment**: Deployed server components now record the bundle version they hold, and the previous build can be rolled back from one command.
  - Every deploy stamps the app folder's manifest with the bundle version from frontend/package.json, the build time, the machine, and the commit plus whether the working tree was dirty.
  - deploy_rollback.py status reports the deployed and parked build of each component and flags a split bundle or a server running behind the repository.
  - deploy_rollback.py rollback restores the parked previous build through each component's own deploy-time stopped window.
- **build**: Admin Control now stops itself before a deploy swaps its folder, so a running instance no longer fails the build and blocks every other component in the same run.
  - Adds the apps.admin.kill_all switch that Bridge, Engine, Gateway and Orchestrator already have; Admin Control polls it in its heartbeat thread and shuts down through its normal path.
  - Nothing supervises Admin Control, so its build clears the switch and relaunches the server headless; an open Admin Control page needs a refresh after a deploy.
  - Rollback stops Admin Control through the same window it deploys with.
  - The Launcher keeps its in-place fallback instead: the process pinning its folder is another app, so there is nothing it could stop.
- **build**: Build Manager's Build Selected now runs component builds with Python 3.10 instead of whichever interpreter launched the window.
  - build_manager.bat falls back to pyw -3, which picks the newest installed Python, so on a machine with 3.14 the GUI build was refused by require_python_310 while the same component built fine through the listener.
  - build_runtime.build_python_executable is now the single owner of that choice, and the listener delegates to it.
