# Release 1.5.2

Released on 2026-09-11.

## User-Facing Changes

### Features
- **dfm**: DFM Notes can quote live method values with Python-style {...} placeholders that render as text outside editing.
  - Names such as {development_label(1)}, {ratio_value(2, 1):.4f}, {selected_value(1)}, and {ultimate_value(-1):,.0f} follow the method JSON fields; positions are 1-based and -1 means the last.
  - Placeholders may calculate: arithmetic, comparisons, and/or/not, a conditional, round/min/max, and Python format specs such as .2f, ,.0f, .1%.
  - Any field of the method JSON is reachable by its path, such as {ratio_triangle.development_label(1)} or {average_formulas.values(2, 3)}; lists are called with a position.
  - While editing, placeholders show in deep blue and typing inside braces opens a popup that previews and completes the available names, properties, and values.
  - Braces and parentheses close themselves while typing a placeholder: the pair opens around the caret or a selection, the closer steps over one already there, and Backspace removes an empty pair.
  - An Insert Value button on the Notes toolbar lists every available name; hovering a rendered value shows its placeholder, and one that cannot be rendered stays as typed with the reason.
  - The rendered note can be selected and copied; a plain click enters editing at that spot.
  - A save stores the rendered text as the sidecar's notes, so the ResQ export, macros, and the RPC bridge see values instead of placeholders, and keeps the raw placeholder text beside it for the Notes tab; a note replaced by a macro or by a ResQ note applied through the bridge drops its placeholders.
- **project instance**: Manage Excel Links now checks every linked workbook when it opens and shows a Status column: a yellow Needs Review icon marks a dataset or DFM method whose workbook was saved after its linked values were last loaded.
  - The check compares the workbook's saved time with the dataset's data file or the DFM method file, the same rule the Dataset window applies when it opens; a workbook the server cannot open leaves the cell blank.
  - The status line under the table counts the references that need review, and the column filters like every other.

### Improvements
- **dfm**: A copied Excel link can be pasted straight onto a DFM User Entry cell, and a doubled leading = in the formula bar is folded into one instead of being refused.
  - Pasting a single formula or workbook link onto the active User Entry cell now goes to the formula bar and is applied as if it had been typed there, so the bar no longer has to be opened first.
  - A paste on the Ratios tab used to be answered by the hidden Data tab with a 'Generated datasets are read-only' notice; the shared dataset grid now ignores pastes and keystrokes while its tab is not shown.
  - The formula bar already shows a leading =, so a pasted formula's own = now folds into it while typing and on commit rather than failing validation as '= ='.
- **project instance**: Manage Excel Links shows one Workbook Path column in place of Workbook and Location, and clicking any column header sorts the table.
  - Clicking a header sorts ascending, clicking again sorts descending, and a third click restores the original order.
  - Right-click the Workbook Path cell to open the workbook's folder, as the Location cell offered before.

### Fixes
- **dfm**: Picking a Ratio Basis vector in the DFM Results tab, and saving the DFM afterwards, works again.
  - The Results tab read the dataset-type list with a column key the server does not use, so every option lost its data format and a freshly chosen Ratio Basis was rejected as 'not available in current project'. The lookup now accepts the 'Data Format' label the server sends as well as the older data_format spelling.
  - Saving an existing DFM whose Ratio Basis had just changed failed with 'DFM Ratio Basis values must align exactly to the DFM origins': the save merged only the new dataset name onto the stored method and checked it before reloading the vector. The merge now carries the column the editor already loaded, and the save still reloads the vector from its source right after.
- **project instance**: Nested windows in Project Instance keep their size when dragged by the title bar instead of growing a little on every move.
  - Moving or resizing a nested window now follows the pointer with capture, so a fast drag across an embedded page or past the app edge no longer drops the window.
