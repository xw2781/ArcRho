# Release 1.6.1

Released on 2026-09-15.

## User-Facing Changes

### Features
- **dataset**: The Data tab picks a number format from a list or an Excel-style Format Cells window instead of a typed pattern.
  - The Number Format box no longer accepts typing: clicking it opens the list, which now ends with a Custom option.
  - Custom opens a small window inside the Data tab with General, Number, Currency, Accounting, Percentage, Scientific, and Custom categories, a live sample taken from the open dataset, and a box for a format code of your own.
  - Formats are written and read as Excel writes them, including bracketed negatives, red negatives, currency and accounting layouts, thousands scaling, and scientific notation.
- **dfm**: In the DFM Ratios tab, Edit mode now has a keyboard: arrow keys walk a dashed cell through the ratio triangle as well as the average formula table, and Enter acts on it.
  - The ratio triangle now shows the same dashed cell the average formula table has; clicking a cell in either table moves it there, and only one cell is ever marked.
  - Enter on a marked ratio cell excludes it, or includes it again, exactly as clicking it does.
  - Enter on a marked average formula cell selects that formula for its development column, with the usual green fill.
  - Both are single undo steps, and Enter on a formula already selected for its column leaves the method untouched.
- **dfm**: In the DFM Ratios tab, a User Entry row now carries the same pale blue fill the weight column uses in a Result Selection method, so the cells you can type into stand out at a glance.
  - Selecting one of those cells for its development column still paints it the usual green, which now covers the blue rather than sitting under it.
- **project instance**: Mark method results for review, or sign them off, straight from the dataset table.
  - Right-clicking a row now offers Mark For Review or Set Reviewed, whichever the current status allows, and applies it to every selected row at once.
  - Rows that are not method results are left alone, and a selection holding both statuses is offered Set Reviewed so one click settles it.
  - Setting the status records who changed it and when, and changes nothing else: no values move and nothing downstream is refreshed.
  - The rows you picked stay highlighted afterwards and the table stays where you were reading, instead of redrawing back at the top of the class.

### Improvements
- **dfm**: Clicking the DFM Ratios formula bar away now keeps it away while you move between User Entry cells.
  - Clicking a highlighted User Entry cell hides the formula bar, and it stays hidden as you click other User Entry cells.
  - Clicking a cell you have already landed on a second time brings the formula bar back.
  - Select mode and Edit mode behave the same, and starting a formula with = or pasting one still opens the bar.
- **resq**: Exporting a reserving class to ResQ now carries the notes of every method, not only some of them.
  - Bornhuetter Ferguson, Cape Cod and B&S Settlement Rate methods were previously saved in ResQ without their notes; their notes are now written first.
  - Notes still come from the same place for every item, and blank lines are kept the way ResQ shows them.

### Fixes
- **dfm**: A DFM whose selected factors include one sitting a hair above 1 no longer fails to preview or save. That hair is floating-point dust left by an arithmetic result, and the Curves tab now leaves such a factor out of its fits the way it already leaves out a factor of exactly 1.
  - The Power curve was the one that gave way: the dust point pulled its regression far enough that the fitted parameter ran past the largest number the app can hold, and the whole method calculation stopped with a server error.
  - A curve that still cannot be fitted for any other reason is now reported as unfitted instead of failing the method.
- **excel add-in**: A hand-entered vector read in Excel at a coarser period now comes back as figures instead of a configuration error.
  - Reading a monthly hand-entered vector a year at a time asked the data engine to build it, which it cannot do for figures that were typed in, so the cell showed a data processing configuration error instead of the numbers.
  - The yearly reading is now added up from the stored figures the same way a method already reads the same vector, and nothing is written beside them.
  - The same blindness meant a hand-entered vector was not recognised as hand-entered at all, so a read could clear the only copy of its figures before failing.
- **excel add-in**: Calculate Workbook no longer replaces a method's result with a data processing configuration error, and a dataset name spelled with a doubled space now finds the dataset.
  - A Result Selection output such as 'C 92 - Current Qtr Selected' has no source formula behind it, so a forced rebuild asked the data engine for something it could not build and the engine's error text was written over the stored figures; every ordinary read afterwards showed the error too.
  - A method's published result is now read as it stands whenever a workbook is recalculated or refreshed, the same way a hand-entered dataset already was, and the data engine is never asked for it.
  - ResQ spells some dataset type names with a doubled space that ArcRho and the add-in do not; a workbook using either spelling now reaches the same dataset, on the server and in the data engine's dataset type table.
- **method pages**: Save stays clickable on a method window whose object still needs review.
  - DFM, Result Selection, Bornhuetter Ferguson, Cape Cod, and Berquist Sherman windows kept Save greyed out when nothing had been edited, so clearing a Needs Review flag was only possible with Ctrl+S.
  - Cancel is unchanged, and Save still greys out on a clean object that is already up to date.
