# Release 1.4.2

Released on 2026-09-04.

## User-Facing Changes

### Features
- **berquist sherman**: Both Berquist Sherman method pages now let you select cells in any calculation grid and copy their values, the way the Dataset Viewer and Result Selection grids do.
  - Click a cell, drag a rectangle, Shift-click to extend, Ctrl-click to add a range, or click a row label or column header to select the whole line, on every sub-tab of the Method tab.
  - Ctrl+C or right-click and Copy values puts the selected figures on the clipboard as a tab-delimited block ready to paste into Excel; Escape or Remove Highlights clears the selection.
  - Select Leading Diagonal on the Proportion Settled view now sits in the same right-click menu.
- **dfm**: The DFM page gains a Curves tab that fits Exponential Decay, Inverse Power, Power and Weibull curves to the selected factors and lets you pick the factor and tail factor per development period, and the Ratios tab's "- Ult" column now keeps the tail factor you enter.
  - Curves are fitted by log regression the way ResQ does, with Future Dev. Periods, Free Fit C, per-period Include flags, user value columns, and a Selected Estimate Number per period and for the tail; the selected values drive the ultimates.
  - The Tail Pattern block reads as one choice: the column the tail runs off along is marked X and stays green all the way down the future development period rows, and clicking any of those rows picks the column just as clicking the X row does.
  - The grid uses ResQ's own cell colours, so a method can be read side by side with ResQ: a chosen cell takes the same pale green as a selected average on the Ratios tab, and setting Include to No strikes the flag and the factor it drops in the Ratios tab's pink.
  - A User Entry or benchmark row's value in the "- Ult" column is kept and used as the tail factor instead of being reset to 1.
  - The ResQ import reads each average row's tail factor and the ResQ Curves tab, and the ResQ export writes them back.

### Improvements
- **project settings**: The Source Table details panel now shows the source file's current modified time, read from the file each time the panel opens.
  - The panel used to show the modified time recorded when the file was last copied into the project, which went stale as soon as anyone rewrote the file.
  - A file that has changed since the last import is called out beside its modified time, and an unreachable file keeps the recorded time and says so.

### Fixes
- **bornhuetter_ferguson**: A Bornhuetter Ferguson ultimate is no longer rounded to a whole number, so a DFM or Berquist-Sherman adjustment reading a BF vector now matches ResQ.
  - The New Ultimate column keeps the same six decimals as every other BF vector; ResQ never rounds it.
  - A claim-count BF feeding a Berquist-Sherman settlement-rate adjustment had moved the adjusted paid triangle's earliest ages by up to 2% from ResQ.
  - A BF method saved before this fix keeps its whole-number ultimates until it is saved or refreshed again.
- **dfm**: A DFM whose Engine-generated input or ratio basis is cached at a different period now regenerates it at the method's own period during save and downstream refresh instead of failing with an incompatible origin period length.
  - A quarterly DFM fed by a dataset cached annually no longer blocks the downstream refresh after an upstream save.
  - The regenerated cache is written beside the existing one; the dataset's sidecar and primary cache are left as they were.
  - DFM and Result Selection now share one resolver for reading a precedent at the method's period.

## Internal Notes

- **dfm**: Removed the unused standalone DFM refresh route, which no screen or automation called and which still ran on the client over the mapped drive.
  - A DFM is refreshed by the Engine propagation walk after an upstream save; that remains the only refresh path.
  - A future Refresh button should be built as an Engine-hosted operation rather than reviving this route.
