# Release 1.4.0

Released on 2026-09-01.

## User-Facing Changes

### Features
- **project instance**: The dataset toolbar's gear button now opens a Preferences window that also lets you choose which tab each kind of dataset or method window opens on.
  - Default number formats keep working exactly as before and are still shared with everyone using the same ArcRho Server.
  - The Number Formats table now lists every dataset type of the open project, so a type you just added in Project Settings is there to pick a format for without typing its name.
  - Types left blank simply use the fallback and are not written to the shared file; only the formats you set are saved, and each dataset still keeps any format saved on it.
  - The new Default Tabs section is yours alone, is remembered on your own PC, and is used in every project you open.
  - Each section says whether it is shared with everyone on the same ArcRho Server or personal to you.
  - Reset to app defaults puts every window kind back to the tab the app opens on.
  - Opening an existing method now follows your choice; adding a brand-new one still starts on Details.
  - Windows now open straight onto the chosen tab instead of showing another one first and jumping.
  - Dataset and method windows stay blank until their opening tab is ready, so the contents appear in one step instead of being assembled on screen.
- **dataset**: Dataset cells can now link their values to a cell or range of another dataset in the same segment, alongside the existing Excel links.
  - Type a formula such as =[C 82 - Prior Qtr Selected][1:6] into a cell, or start with = and simply click or drag the cells in the other open dataset window, Excel-style; the picked reference fills in live and Enter loads the values.
  - A linked range wears a teal outline so an ArcRho link reads apart from a blue Excel link, and hovering shows the formula just like an Excel-linked cell.
  - The Links tab now has two sections - Excel Links and ArcRho Links - each with refresh, break, and open actions; refreshing an ArcRho link re-reads the source dataset's current values.
  - Linked values are snapshots saved with the dataset; the sidecar stores them under a new internal_links field beside external_links.
- **dataset**: Dataset cells now accept formulas that combine Excel links, ArcRho dataset links, and numbers with Excel-style array arithmetic, and the Links tab lists every kind of link in one resizable table.
  - Type =[C 82 - Prior Qtr Selected][1:7] * 2, or mix an Excel range and a dataset range in one formula; a range acts as an array, a number applies to every cell, and the result spills from the cell you typed into.
  - A standalone Excel or dataset reference still creates a plain link, so the same formula bar reads all three kinds and shows one hint when a draft fits none of them.
  - Calculated ranges wear a purple outline beside the green Excel and blue ArcRho outlines; refreshing a formula re-evaluates it and the sidecar stores it under a new formula_links field.
  - Picking cells in another dataset window now drops the reference where the formula has room for it, after an operator or in place of the reference at the end.
  - The Links tab in the Dataset and DFM windows is now one table: a kind badge and source, the reference or formula, the destination, the cell count, and the current value on one line per link, with columns you can drag to resize.
- **shell**: Added the Flight Deck, a slim floating strip of one-press macro buttons you can park anywhere on screen.
  - View > Show Flight Deck, or Ctrl+B, shows and hides it.
  - Drag a macro out of the Macros window and drop it on the deck to give it a button.
  - Each button carries an icon plus a label of your choosing. Pick the icon from the built-in set, draw your own on the pad, or paste one in.
  - The pad's tools sit in one compact toolbar above it: a pen, a straight line, a box and an oval, two erasers, one that lifts whole lines and shapes away and one that rubs out only what its ring covers, and Undo and Clear at the end. Press + or - to resize the eraser ring. Hover a tool for its Shift shortcut, which gives a level line, a square or a circle.
  - Picking a built-in glyph lays it out on the pad, so you can add to it or rub parts of it out rather than only replacing it.
  - Reopening a button puts its icon back on the pad, so you carry on from where you left off instead of starting again.
  - The deck stays above the rest of the app, is dragged by the grip on its end, and can stand upright as well as lie flat.
  - Buttons are reordered by dragging, and removed by dragging them off the deck.
  - The whole arrangement is kept permanently on your PC, in its own file beside the other desktop preferences, so it survives Clear Cache & Reload.
- **dataset**: Dataset cells driven by ArcRho links now recalculate automatically when the dataset they read is refreshed, instead of keeping the value of the last manual refresh.
  - A saved link now shows up in the dependency graph: the linked sources appear as Precedents on the Details tab, and the source dataset lists the linked one as a Dependent.
  - The dependent-update walk that runs after every save re-evaluates the linked cells on the server, including formulas that mix ArcRho and Excel references, and everything downstream of them follows in the same walk.
  - An Excel workbook the server cannot reach never blocks the update: those cells keep their last values and the post-save notice lists each affected dataset with the reason, one clickable name per row.
  - Only cells the links own are rewritten; hand-typed values in the same dataset are untouched.
- **dataset**: The ResQ import now translates a vector's own ResQ formula into an ArcRho in-cell formula, so the imported dataset keeps recalculating instead of freezing the copied values.
  - Applies to vectors whose Dataset Type has no formula in ArcRho while the ResQ instance carries one, such as the Claim Count times Severity candidates.
  - Every dataset the formula names must be another imported vector of the same reserving class; a formula referencing something ArcRho does not hold, such as a frozen prior-quarter snapshot, imports as plain hardcoded values exactly as before.
  - The translated formula joins the dependency graph and recalculates automatically with everything else.
- **project settings**: A running project duplicate can now be cancelled from its progress window.
  - The Duplicate Project progress window has a Cancel button while the copy is queued or running. Pressing it asks the server to stop at the next copy step, the window reads "Cancelling..." until the server confirms, and the partly copied folder is discarded so nothing is created.
  - The button disappears once the copy has been published and only the registration step remains; a Cancel at that point is refused with a status-bar note that the project will be registered.
  - A cancelled duplicate closes quietly with a status-bar message rather than an error dialog, and leaves no recovery record behind.
- **macro**: Import ResQ Reserving Class now checks every dataset the ArcRho Engine generates against ResQ's copy and warns when any cell differs at two decimal places.
  - After the Engine has built a generated triangle or vector, the import reads ResQ's values for the same dataset and compares them cell by cell, treating a blank on one side and a number on the other as a difference.
  - The completion box turns into a warning that stays on screen, naming each differing dataset, how many cells differ, and the first differing cell with both values.
  - The Engine result is kept in ArcRho either way; the warning tells you where ResQ would show different numbers.

### Improvements
- **shell**: Redesigned the Browsing History page in the plain Project Explorer style with page-type icons and short, readable times.
  - Each row shows the page icon, the name, and the path, with the full timestamp on hover.
  - A single click always opens a record; the first click on the page no longer gets lost.
  - The page follows the Dark and High Contrast themes through the shared theme colors.
- **macro**: Export Reserving Class to ResQ now runs on the ResQ-connected ArcRho Bridge from any PC, pushes the class in ArcRho's dependency order, and shows its results in a Project Instance window.
  - Input datasets are written with their Notes, DFM and Result Selection selections and Notes are written, and Bornhuetter Ferguson, Cape Cod and Berquist Sherman methods are saved so ResQ recalculates them from what was just written.
  - Calculated and engine-built datasets and Bootstrap methods are left out; a dataset without a CSV cache is reported as skipped with the reason.
  - Items are written in the order ArcRho's dependency graph gives, so a method is never saved before its inputs.
  - The results open in the same nested Project Instance window the Sync macro uses: one row per item with Exported, Saved, Skipped or Failed and the Bridge's message.
  - The export compares no timestamps and records no sync baseline, so the next Sync Reserving Class with ResQ preview reports every exported item as changed on the ResQ side.
- **macro**: Sync Reserving Class with ResQ now pushes the whole reserving class one way, from whichever side changed last, instead of proposing a direction row by row.
  - Each side's timestamp is the latest change among the datasets and method outputs in the review; the newer side is pushed to the other, and the review window's header shows both timestamps and the chosen direction.
  - A row whose own timestamps point the other way is marked Review in a new column and stays ticked; the mark is a caution to read before applying, not a block on the sync.
  - The Proposed Action column is gone from the review table, and the results table names the direction once in its header instead of on every row.
  - The accept button reads Sync to ResQ or Sync to ArcRho so the direction is visible where it is confirmed.
- **macro**: Sync Reserving Class with ResQ now shows its results as a table in the same Project Instance window the review used, instead of a message box.
  - One row per applied, failed, or warned item, with the direction, an Applied/Failed/Warning outcome, and the full message for that item, so a long failure reason is no longer squeezed into a dialog.
  - The results table can be sorted, filtered, searched, and minimized like the review table; it has no checkboxes and a single Close button, and the macro finishes when it is closed.
  - A stale review or an empty selection, which apply nothing, still show their short message box.
  - The shared review-table component gained a read-only mode (selectable: false) any macro can use to present a report.
- **macro**: Sync Reserving Class with ResQ reviews only the input datasets and methods that exist in both ArcRho and ResQ, and no longer flags an interrupted earlier sync.
  - Engine-generated datasets no longer appear in the review on either side: both ArcRho and ResQ rebuild them from source data, so there is nothing to reconcile.
  - A dataset or method that exists on one side only is no longer listed; a new item reaches the other side through an import, not through this review.
  - The 'Previous sync incomplete' status is gone. An interrupted run leaves nothing behind, and the next review compares the current timestamps against the last recorded baseline like any other row.
  - The comparison rules live in the Bridge's synchronization session, so the Bridge must be redeployed to pick this up; the macro itself only reworded its empty-table message.
- **shell**: Browsing History is now a timeline: every page you opened, newest first, grouped by day under Today, Yesterday, and dated headers.
  - Each day is its own block with a date header; a thin line runs down the left with a ring for each day and a dot for each record, and the date header stays in view while you scroll its rows.
  - Click a date header to fold that day away, and click it again to open it back up.
  - Earlier days are left as they were: opening a page again today updates today's record only, so the same page can appear under Today and under earlier days. The history now keeps up to 100 records per kind.
  - Each row shows the time, the page icon, the name, and the path, with names and paths lined up in columns across the whole page. Hovering a row lights its dot and shows an open arrow.
  - Records slide in when they first appear, and a reload leaves records you already saw where they are.
  - A page-type switch in the header narrows the timeline to Project Instances, My Workspace Folders, or Datasets, each with its count. The text filter box is gone.
  - Up and Down arrow keys move between rows.
  - Motion is turned off when the operating system asks for reduced motion.
- **macros**: Export Reserving Class to ResQ now warns which datasets and methods ResQ changed more recently than ArcRho, with links that open them in ArcRho, before it overwrites them.
  - The first confirmation is shorter; after it the macro compares every dataset and method timestamp with ResQ.
  - Items ResQ changed after ArcRho are listed in a second, floating warning; clicking one opens it in the Project Instance page so it can be checked before choosing Export Anyway or Cancel.
  - The check never blocks the export on its own: a comparison that fails is noted and the export goes ahead.
  - Macro message boxes can now carry clickable item links that open a dataset or method in the active Project Instance page.
- **macros**: Sync Reserving Class with ResQ and Export Reserving Class to ResQ now hand their request to the Bridge through the ArcRho Gateway instead of writing it across the network share.
  - The request is published on the server and its progress is read there, so a Client PC no longer writes or polls the Bridge queue over the mapped drive.
  - A wait that hears nothing from the Bridge for thirty seconds is abandoned with a clear message rather than left polling.
  - A macro run from a script outside the app still uses the shared folder directly.
- **dataset**: The Dataset formula bar can be dragged out of the way, and the window you point a formula at now shows what it is about to hand over.
  - Drag the formula bar by its round fx badge when it covers a value you need to read; it goes back over its own cell as soon as it closes or shows another formula.
  - While you are writing a formula, the other dataset window follows the pointer: the cell under it lights up before you click, and the range you have picked is ringed by moving dashes.
  - The formula bar of a cell that is already linked now accepts a picked range too, so an existing link can be re-aimed without retyping it.
  - A link is coloured by where its values come from: green for Excel, blue for another ArcRho dataset, both around the cells and in the formula bar.
- **macros**: The Macros and Macro Library windows now support arrow-key selection and drag gestures: reorder macros by dragging, drag a macro out of the Macros window to delete it, and drag a library macro onto the Macros window to load it.
  - Up/Down (and Home/End) move the selection in either list; the description pane follows.
  - Rows no longer show a hover tooltip; the description pane already holds that text.
  - The macro order is now kept in your local ArcRho preferences folder instead of browser storage, so Clear Cache & Reload no longer resets it. Any order saved by an earlier version is not carried over; reorder once.
  - The Macro Library window opens at the same size as the Macros window.
- **macros**: Import ResQ Reserving Class and Export Reserving Class to ResQ now open the same review window, where you tick the datasets and methods the run should cover; what you ticked comes back ticked for everyone next time.
  - Both macros show one table of every dataset and method either system holds, with where it lives, both timestamps, what changed since the last run, and what this run would do to it.
  - Each row has a tick box. Rows the direction cannot carry are shown greyed out with the reason instead of being left out.
  - The import can now bring across a dataset ResQ has and ArcRho does not, and leaving a dataset unticked leaves the ArcRho copy exactly as it was.
  - The merge-or-overwrite question is asked before the review, so the table says whether a newer ArcRho copy would be overwritten or kept.
  - The ticked list is saved beside the reserving class on the ArcRho server, one for importing and one for exporting, so the next person opens the same choice.
  - The ArcRho Bridge must be rebuilt and redeployed with this release; the macros and the Bridge refuse to work with an older counterpart rather than quietly moving everything.
- **dataset**: The Links tab in Dataset and DFM windows now has two sections, ArcRho and Excel, each headed by a colour stamp - blue for ArcRho, green for Excel - matching the outline those linked cells wear in the Data tab.
  - The stamp replaces the grey section title and reads as the kind's name; no row carries a chip of its own.
  - The separate Formula section is gone: a formula is listed once per source it reads - each dataset under ArcRho and each workbook under Excel - and refreshing or breaking any of those rows acts on the whole formula.
  - A divider separates the two sections, starting at the middle of the tab; drag it to resize them or double-click it to put it back.
  - Each section's scrollbar now matches the Data and Audit Log tabs, with the same width and step arrows.
- **dataset**: The Links tab lists ArcRho links above Excel links in their own sections, names the destination as the real range such as 2017~2023, and keeps its tables filling the frame.
  - The Value column and the hover tooltips on the link rows are gone, and the kind badge reads ArcRho, Excel, or Formula.
  - Columns re-fit whenever the window or tab is resized, can be dragged much wider, and a table narrower than its frame keeps a right edge.
- **dataset**: Deleting a dataset that other objects still read now lists the whole downstream chain and offers deleting all of it together, instead of only refusing.
  - The refusal window lists every downstream object with its method type; clicking one still opens it so the input can be cleared instead.
  - A new Delete all button resubmits the delete with the whole chain included, after the list has shown exactly what it covers.
  - A delete is refused while a dependent update is running on the same reserving class, the same way a save is, so the two can never race.
- **dfm**: The average-formula table now colours a User Entry row's source cells only while that cell is the one you are on, and gives each part of the formula its own colour.
  - The pale blue fill used to sit on every referenced cell all the time; it now appears only when the User Entry cell that names them is selected or being edited.
  - A formula built from several rows colours each one differently, in the order the formula names them, the way a spreadsheet does.
  - Each name in the formula bar carries the same colour as the cell it points at, so you can tell at a glance which part of the formula a cell belongs to.
  - The colours follow the formula as you type or drag a reference onto another row.
- **project instance**: The Excel Link Manager now leads with the dataset or method that uses a workbook, and its folder column is named Location.
  - The columns read Dataset Name, Method Type, Workbook, Location, then the workbook's own Last Modified, Created, and User, so the object the reader acts on comes first.
  - The Location cell and its tooltip no longer end in a stray path separator.
- **macros**: Dragging a macro in the Macros or Macro Library window now carries the row itself under the pointer instead of a small floating name box.
  - The travelling card is a copy of the row you took hold of, at the same width and height and in the same highlighted colour, and it stays under the point of the row you pressed.
  - The row left behind fades, the blue line still shows where a reordered macro will land, and the Flight Deck and the Macros list still tint when they are the drop target.
  - Dragging a macro clear of the Macros window still deletes it, and the confirmation prompt still names the macro before anything is removed.
- **macro**: Import ResQ Reserving Classes now always offers its built-in list of default reserving classes and creates the folder for any listed class the project does not hold yet.
  - The review table lists the fixed default classes, all preselected, instead of scanning the project for every reserving-class folder; classes outside the list are never offered.
  - A listed class with no ArcRho folder yet shows as New in the table, is imported into a freshly created folder, and is named in the batch summary.
  - The macro no longer reads the shared support bundle to find its default selection, so the list is the same on every machine.

### Fixes
- **macro**: The ResQ import macros no longer abandon a running import, and skip the rest of a batch, because one heartbeat reading over the mapped drive looked stale.
  - The Bridge is now judged alive from the ArcRho Server side through the Gateway, where the heartbeat's age is exact, and only counted as gone after thirty seconds with no sign of life.
  - A request's own status file, which the Bridge keeps touching while it works, counts as a sign of life alongside the heartbeat.
  - When a wait is abandoned the message says the import's outcome is unknown and where to check, instead of claiming the data was left unchanged.
  - Import ResQ Reserving Class 1.4.0, Import ResQ Reserving Classes 1.3.0, and Sync Reserving Class with ResQ 1.2.1 carry the change; they need this app version's Python API.
- **dependent propagation**: A Berquist Sherman method's output dataset is now recalculated automatically when one of its sources changes, so the Dataset Viewer and its dependents no longer show the values from the method's last manual save.
  - Saving a Result Selection, DFM, calculated dataset, or input triangle that feeds a B&S Settlement Rate or Case Reserve Adequacy method used to leave the method's output CSV as the page last saved it. The method page looked fresh because it recomputes from its sources on every open, but the Dataset Viewer and every method built on the output read the stale cache.
  - The Engine's dependent update now runs a Berquist Sherman step after Result Selection and before Bornhuetter Ferguson: it recomputes both variants on the server with the same calculation the page uses, rewrites the output CSV when the numbers changed, moves the dataset's Last Modified, records an Auto Refresh entry in its Audit Log, and carries the new triangle on through DFM, Result Selection, Bornhuetter Ferguson, Cape Cod, and Bootstrap in the same walk.
  - A B&S output the update could not recompute — a source it cannot read or one that is not annual — keeps its last saved values and is flagged Review Needed, with the reason reported under a Berquist Sherman heading in the save's refresh report.
- **project instance**: The dataset table's Last Modified now moves for every method a dependent update rewrites, not only for the ones whose published output changed.
  - A DFM, Bornhuetter Ferguson, Cape Cod, or Bootstrap method refreshed automatically with new input, basis, or ratio values used to keep its old Last Modified when the published ultimate happened to stay the same.
  - Such a refresh now stamps the method's output dataset and records an Auto Refresh entry in its Audit Log; a refresh that changes nothing still leaves both alone.
  - The public Python API's DFM propagation applies the same rule.
- **macro**: Datasets the ResQ import generates through the Engine now show the importing user's full name in the Project Instance table instead of a Windows login.
  - The import stamps the person who ran the macro, not the Bridge worker that picked the request up.
  - Classes imported before this fix keep the login until they are imported again.
- **macro**: Sync Reserving Class with ResQ leaves calculated datasets out of the review and writes accepted rows one at a time in ArcRho's dependency order instead of alphabetically.
  - Calculated datasets no longer appear in the review table on either side: propagation recomputes them in ArcRho and in ResQ alike and nobody edits them directly, so they only ever showed the last propagation time as a change to sync.
  - Within one direction a DFM follows its input triangle, a BF or Cape Cod method follows the DFM output and priors it links, and a Result Selection follows every source it loads; rows with no link between them keep the review order.
  - A method whose linked dataset is created earlier in the same run is no longer blocked before writing; the strict check still runs right before each row, so a failed input still stops the rows that read it.
  - The change lives in the Bridge's synchronization session; the macro itself is unchanged and the Bridge must be redeployed to pick it up.
- **macro**: Sync Reserving Class with ResQ now carries Notes in both directions for every dataset and method.
  - An ArcRho-to-ResQ row writes the notes kept on the dataset's or method's Notes tab into the ResQ Notes field with their line breaks intact; an empty note clears the ResQ notes. Before this, notes were never written, so a synced DFM showed stale or empty notes in ResQ.
  - A ResQ-to-ArcRho row brings ResQ's notes into ArcRho for triangles and vectors as well as methods; dataset notes used to come across blank.
  - Every write is checked by reading the notes back, like the other fields the sync applies.
  - Export Reserving Class to ResQ (1.3.0), whose writer the sync uses, pushes notes the same way.
- **macro**: Sync Reserving Class with ResQ no longer refuses a Result Selection over a stray double space in a ResQ dataset name, and no longer refuses a row just because an earlier write in the same run made ResQ recalculate it.
  - ResQ names are left exactly as they are; every comparison of a ResQ name against an ArcRho name now uses the same whitespace-normalized key the review pairing already used, so each ResQ object maps onto exactly one ArcRho item.
  - Before each row is written only the side it is written from has to be unchanged. Saving a DFM into ResQ makes ResQ recalculate the Result Selections downstream of it, which previously failed those rows with 'Timestamp changed during synchronization'.
  - The change lives in the Bridge's synchronization session; the Bridge must be redeployed to pick it up.
- **macro**: Sync Reserving Class with ResQ no longer reports items that were only recalculated by propagation as changes to synchronize.
  - After a run, the items downstream of what it wrote are re-baselined: both ArcRho and ResQ recompute a Result Selection, or a method whose input was written, from the inputs the run just synchronized, and that recalculation used to show up as 'ResQ changed' at the next review. They now appear in the results table as 'Recalculated' rows, and nothing is written for them.
  - Only the side the run moved is re-baselined, so a change that was already pending before the run is still offered afterwards.
  - On the ArcRho side, a Result Selection refresh no longer overwrites the method's last-saved time; like DFM, BF and Cape Cod it records the refresh separately, so editing one input no longer proposes every Result Selection downstream of it as an ArcRho change.
  - The macro (1.3.2) renders the new rows; the Bridge and the Engine must be redeployed to pick up the rest.
- **dataset**: A linked range in the Data tab is now framed as the rectangle you picked instead of following the shape of the triangle.
  - The coloured frame around a linked range used to step down the diagonal of a triangle, because it followed only the cells that received a value.
  - It now closes over the empty corner, so the frame matches the Excel or dataset range the link actually covers.
  - The same applies to all three kinds of link: green for a workbook, blue for another dataset, purple for a calculated range.
- **bornhuetter ferguson**: Bornhuetter Ferguson and Cape Cod now take Percentage Developed from the development factors you selected in the DFM, instead of dividing the latest figure by the ultimate.
  - The figure now matches the % Developed row on that DFM's Ratios tab, read at each origin's own development age.
  - An origin whose latest figure is zero, usually the newest year of a paid triangle, used to leave Percentage Developed and the ultimate blank; it now develops normally.
  - Percentages above 100%, which appeared when the Latest triangle was not the one the DFM was built on, no longer occur.
  - A DFM window you are still editing previews its pattern to any open Bornhuetter Ferguson or Cape Cod window, so their figures follow your unsaved factor selections.
  - A Cape Cod Prior Ultimate that no DFM produced has no pattern to read and keeps its previous behaviour.
  - Import ResQ Reserving Class now copies each method's Percentage Developed column straight from ResQ, so an imported Bornhuetter Ferguson or Cape Cod shows the same figures ResQ does instead of a ratio that went blank for a zero latest.
  - Saved methods keep their old figures until they are recalculated; tools/restate_percentage_developed.py restates a whole project in one pass.
- **dfm**: The move pointer over a referenced cell's border now appears while editing a User Entry formula in Select mode, not only in Edit mode.
  - Select mode was overriding the pointer on every cell in the table, so the border of a referenced cell gave no sign that it could be dragged onto another row.
  - The drag itself always worked; only the pointer was missing.
- **shell**: Dragging a pop-up message or progress window no longer lets go of it when the pointer is moved quickly.
  - The window now holds on to the pointer for the whole drag, so it keeps following the cursor even when it is thrown across the screen or over another window.
  - Releasing the button, or closing the window part way through a drag, ends the drag cleanly.
- **dfm**: An "Ex hi/lo" average over the last N periods now averages within those N ratios instead of reaching further back to replace the pair it dropped.
  - "Simple - 5 Ex hi/lo" takes the last five usable ratios, drops the highest and lowest, and averages the remaining three, matching ResQ and the values ArcRho recalculates on the server.
  - The Ratios tab, the value saved with the method, the Selected line, and the ratio chart's highlighted points all follow the same rule.
- **dfm**: A DFM now divides its ratios from the data exactly as it reads it, so a ratio shown to four decimals is no longer slightly off.
  - The observed triangle a DFM saves in its method file keeps ten decimals instead of six. Six was enough for a large loss figure and far too coarse for a small one, where the rounding landed in the numbers being divided and showed up in the ratio.
  - Ratios, averages, the % Developed and the ultimate are all calculated from the full stored values.
  - Existing methods are unaffected until their data is next refreshed, and nothing is marked out of date by the change alone.
- **dfm**: An origin whose later figure is zero now shows the muted "1.0000" in the Ratios triangle and is left out of every average, instead of counting as a ratio of zero.
  - It behaves exactly like an origin with nothing in the earlier column already did: the cell cannot be struck out, it takes no place in a "last 5" or "last 8" window, and it adds nothing to any sum or divisor.
  - "Ex hi/lo" rows then drop their highest and lowest from the ratios that are really there. Checked against ResQ on one column across four different sets of struck-out ratios: all 24 average values now agree.
  - A method saved before this change reads its stored zero the same way, so the correction shows as soon as you open it.
  - A ratio that lands exactly halfway at the number of decimals you are showing now rounds up, matching ResQ and the saved value, where the grid used to round it down.
- **project settings**: Importing source data into a duplicated project now rebuilds that project's datasets instead of the project it was copied from.
  - A duplicated project kept the original project's name inside every dataset's saved settings, so the import wrote the rebuilt values back into the original project and left the new one with no data to open.
  - Opening a dataset in a duplicated project no longer rebuilds it from scratch every time, because the saved values are recognised as belonging to that project.
  - A method that republishes its output dataset keeps the decimal places the dataset already had instead of resetting them.
- **project settings**: Duplicating a project no longer stops with a "project registry is locked" error when the shared project list is merely busy for a moment.
  - Registering the copied project used to give up on the first refusal, which on the shared server happens whenever another window or poll is reading the project list at the same instant, and the duplicate then had to be finished by reopening Project Settings.
  - The project list write now retries the swap for about two seconds before reporting a lock, and the duplicate's finishing step retries a locked reply twice more with the status bar showing that it is waiting.
  - A registry that really is held open still reports the same error, and the recovery record and copied project are still preserved for the next reopen.
- **macro**: Import ResQ Reserving Class now brings across the calculated and Engine-generated datasets of the reserving class, which the review table never listed and the import silently left out.
  - The review table deliberately hides datasets both systems rebuild from their inputs, but the import only brought across what was ticked, so those datasets never reached ArcRho.
  - They are now imported whatever was ticked, and when the class already exists in ArcRho the usual merge or overwrite rule decides between the fresh copy and the existing one.
  - Dataset types ArcRho does not configure are still skipped, as before.
