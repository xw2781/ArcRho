# Frontend: Dataset

## Purpose
<!-- MANUAL:BEGIN -->
Dataset editing and analysis page used inside shell tabs.
It owns the Dataset workflow across Details, Data, Chart, Notes, Links, and Audit Log views, with `Data` as the default tab and Links immediately after Notes.
The page validates Project Name, Reserving Class, and Dataset Type before running ArcRhoTri, renders/caches the resulting triangle data, and publishes status/history updates back to the shell.
Dataset Notes uses the shared notes editor, including rendered file-path links and its file actions.
Dataset Links uses the shared external-links table to inventory and refresh Excel sources used by editable Data cells, and to break sources into the current hard-coded values.
Implementation details should stay in the generated entrypoint/key-file sections or the focused behavior sections below, not in this overview.
<!-- MANUAL:END -->

## External Interfaces
<!-- MANUAL:BEGIN -->
- Calls app-server dataset/arcrho endpoints plus valid-value list endpoints (`/dataset_types`, `/reserving_class_*`, `/arcrho/projects`).
- Uses `/project-user-preferences` to persist and restore the shared project-specific last Reserving Class path plus the Dataset Viewer Dataset Name in `projects/<project>/users/<windows-login>/preferences.json`.
- Sends status/hotkey/close signals to parent shell, and consumes `arcrho:dataset-save` from shell or Project Instance hosts to run the same save flow as the Dataset Save button.
- Publishes dataset input updates and browsing-history updates to shell via `arcrho:dataset-settings-changed` and `arcrho:browsing-history-updated`.
- Publishes `arcrho:calculated-datasets-updated` after a save/run recalculates dependent datasets, and consumes the same shell-broadcast report from Dataset or DFM saves; open Dataset tabs/windows auto-reload when their current project, reserving class, and dataset name match an updated calculated output. Tabs with unsaved grid/settings/Notes edits show a status warning instead of reloading.
- Publishes `arcrho:dataset-dirty` while saved sidecar settings or Notes have unsaved changes, then uses `arcrho:dataset-close-confirmed` after the user confirms discard in the shared page-local close dialog.
- Dataset uses `ui/shared/tabbed_page/` for reusable tab chrome and the matching `ui/shared/tabs/data/`, `ui/shared/tabs/details/`, `ui/shared/tabs/notes/`, `ui/shared/tabs/links/`, and `ui/shared/tabs/audit_log/` modules for shared tab presentation/runtime. Dataset Viewer modules still own sidecar persistence, dirty state, save/close coordination, Chart behavior, and Dataset Viewer-specific page composition; the established Dataset tab IDs and `arcrho:*` contracts remain unchanged.
- `Ctrl+PageUp` and `Ctrl+PageDown` cycle backward and forward through Dataset Viewer tabs with wraparound. The shared tab runtime handles the keys inside the page, while shell and Project Instance hosts forward the same command when focus has not yet entered the Dataset iframe.
- Dataset loads feature-neutral page/control primitives from `ui/shared/components/`, the app-wide scrollbar treatment from `ui/shared/styles/scrollbars.css`, and spreadsheet primitives from `ui/shared/components/spreadsheet/`. Dataset Viewer-only chart, formula/relationship, save/recalculate, and page-layout styling remains in `ui/dataset_viewer/dataset_viewer.css`; method pages do not import that Dataset Viewer-local stylesheet.
- The host-neutral Data-tab runtime lives under `ui/shared/tabs/data/`: `data_tab_controller.js` remains the stable public facade while focused sibling modules own dependency bridging, Details, inputs, requests, persistence, and the active dataset session. Dataset API/config/state, header, dependency, formatting, and run services live under `ui/shared/dataset/`; the dataset-name picker lives under `ui/shared/components/pickers/`. Dataset Viewer supplies its page, Chart, Notes, and host adapters from `ui/dataset_viewer/`, while DFM supplies its own adapter from `ui/method_pages/dfm/`.
- Inactive Dataset tabs use the same pale hover fill as Bornhuetter Ferguson tabs, while active-tab fill and weight remain unchanged.
- The Data grid's right-click menu contains a standard `Show/Hide subtotal` command that toggles whether the derived footer `Total` row is visible. In Transposed mode it controls the equivalent right-side `Total` column. The setting defaults on for existing sidecars that predate the field and is saved per dataset instance as sidecar `show_subtotal`; formula text no longer overrides the user's Dataset Viewer choice. DFM keeps its separate formula-based total policy because it does not expose this Dataset Viewer control.
- In the Data tab, transposed datasets show totals as a single right-side `Total` column instead of repeating totals across a footer row under each origin column.
- Open-window change alert: durable (non-temporary, non-draft) Dataset Viewer windows poll `/object_change/fingerprint` for their sidecar through `ui/shared/services/object_change_watch.js` and show a one-time "close and reopen" message box when another user or the Engine dependent-propagation job rewrites the dataset. The shared Data tab reports save/run boundaries and durable load completions through `ui/shared/tabs/data/data_tab_change_watch_port.js`, so the page pauses and rebases the watch around its own saves and never alerts on them; hosts that leave the port unconfigured (DFM's embedded Data tab) are unaffected. The alert offers a Refresh Now action that reloads the window in place when it has no unsaved changes. Dependent-propagation jobs started by this app instance never raise the alert: Project Instance broadcasts `arcrho:dependent-propagation-started`/`-finished` scope messages that pause the watch for the job's project and reserving class and rebase it at the terminal status.

## Data/State/Caches
<!-- MANUAL:BEGIN -->
- Uses in-page mutable state for active dataset and selection.
- Reads and caches valid value lists via `ui/shared/services/valid_value_lists.js` for:
  - project names from the project index
  - dataset names by project
  - reserving class paths by project
- Reserving-class path normalization preserves literal `/` characters inside a class name; only `\` is treated as the segment delimiter for validation/history keys.
- Dataset-side reserving path list loading does not auto-crawl `/reserving_class_path_tree/children`; child-path hydration is opt-in to avoid background request storms.
- Caches reserving-class type names from `/reserving_class_types` and validates input paths by segment membership in the Name column.
- Reserving-class tree view toggle preferences (auto-expand/auto-close), picker window sizing/favorite paths, favorite nicknames, favorite folders, and hidden path list are stored per project/user in `projects/<project>/users/<windows-login>/preferences.json`. Final reserving-class paths are always selected with a single click. The favorite path context menu can rename a favorite or revert a custom nickname back to the original raw path label.
- Reserving-class tree favorites appear in a collapsible `Favorite` section above the collapsible `All Paths` tree. New favorite rows display the full raw path until renamed; after rename, only the custom favorite name is shown. Favorite rows include the same value-type icon and level label treatment as source rows plus a slashed-star remove button. When no favorites exist, the empty state instructs users to click the star beside an All Paths entry. Selecting a favorite applies its raw path to the Reserving Class input with the same single-click behavior as source tree paths. Right-click actions can copy the raw path, rename inline, remove from Favorite, or reveal the favorite in the source tree. The Favorite section supports custom folders: users can add folders from the section header, delete or rename folders inline from the folder context menu, and drag favorite rows into a folder or back to the root Favorite list.
- Reserving-class tree hide removes the hidden node in place with a short collapse animation instead of rebuilding the full tree. The tree toolbar includes an eye button next to the filter button, and the tree node right-click menu also includes `Hidden Paths...`; both open a small live-updating window listing hidden paths with multi-select `Unhide Selected` and `Unhide All` actions. Full tree refreshes, such as unhide actions, preserve the current tree scroll offset and expanded paths, then swap in the refreshed tree after it is laid out so the visible area remains stable instead of jumping back to the top or visibly flickering.
- Dataset Type picker preferences (`Double Click to Select`, `Close Window after Selection`) are also stored per project/user so they copy with project duplication.
- On project switch, current Reserving Class input is revalidated against the new project's reserving-class type names; valid paths are retained and invalid paths are cleared.
- Origin Length and Development Length are independent controls. When either length changes, the other length is adjusted only if the current pair breaks the required relationship (`Origin Length >= Development Length` and `Origin Length = Development Length * integer`).
- New standalone Dataset tabs read the last selected Project Name from `%APPDATA%\ArcRho\local_project_prefs.json` first, then load that project's `lastReservingClassPath` and `datasetViewer.datasetName` from `projects/<project>/users/<windows-login>/preferences.json` to restore the last Reserving Class and Dataset Name for that project. The project tree picker also reads the same local preference file and shows a blue virtual `Recent Projects` folder above the real project folders with the last three picker-selected project names.
- Stores the project-specific last Reserving Class under shared `lastReservingClassPath` and Dataset Name under `datasetViewer.datasetName`, then reuses them after a project is selected when no query/workflow values override the inputs.
- Workflow-embedded Dataset pages can bind Project and Reserving Class inputs to Global Control defaults, displaying `Default Project (<project>)` and `Default Path (<path>)` while resolving backend requests to the current default values.
- Persists last-viewed dataset inputs globally, including Cumulative, Transposed, and Development/Calendar mode, and restores them when opening a new Dataset tab.
- Dataset loading has no built-in sample dataset ID. If neither the page URL nor saved selections provide a dataset ID, the page shows a neutral no-selection state and waits for valid Project, Reserving Class, and Dataset inputs instead of issuing a dataset request.
- A Dataset Viewer opened for an existing dataset from Project Instance uses one `/dataset/cache/load` request that reads the exact `<DatasetName>.json` sidecar and its named CSV cache. It applies lengths, formatting, notes, graph/audit data, origin labels, and grid values from that response without loading project, reserving-class, or Dataset Type validation lists and without rereading `index.json`. When an older sidecar has no valid origin labels, the same aggregate request resolves authoritative project headers before returning so CSV rows are not hidden; sidecars with complete labels retain the two-file fast path, and the origin-header, development-header, and Dataset Type hydration reads run concurrently server-side so a mapped-drive open pays one hydration chain of latency. Standalone, draft, refresh, and generated-cache workflows keep their full validation/materialization paths.
- Other Dataset page opens load the base generated dataset sidecar `<DatasetName>.json` for the selected project/reserving-class/dataset and apply its saved `origin_length`, `development_length`, cumulative, transposed, calendar, `show_subtotal`, `decimal_places`, and `number_format` Data-tab settings before loading the triangle.
- The Details tab contains a Project/Reserving Class frame above the aligned Name, Dataset Type, Formula, Precedents, and Dependents fields. Its contents use the shared Details-page typography: Arial-first, 12px black labels and controls, literal `Label : ` punctuation, and a 1px label-to-control gap. Details inputs and graph boxes fill the available panel width and resize with the window. The Formula field renders recognized formula components as clickable dataset chips and formula operators as compact tokens using the same rich token style as the Reserving Class Type formula editor; empty Formula, Precedents, and Dependents boxes stay blank, with empty Formula shown as a compact grey one-line box. Component chips ask the Project Instance host to open the related dataset or, when the component is backed by a DFM, Result Selection, Bornhuetter Ferguson, Cape Cod, or Berquist Sherman method, the related method window for the same reserving-class path. The Precedents field is populated directly from the sidecar `Precedents` graph so it can show sources not present in the formula text. The Dependents field is populated from the sidecar graph with matching dataset chips; hovering a precedent or dependent shows its formula with the same rich token formatting in an app-styled tooltip prefixed by an `=` token, and formula tooltips shrink to the widest wrapped row when the content hits the maximum width. Clicking either a precedent or dependent opens its method window when the related dataset is method-backed and otherwise opens Dataset Viewer.
- Stores latest browsing history entries via `browsing_history.js` (project + reserving class + dataset).
- Rejects invalid typed values on change/Enter and blocks ArcRhoTri requests until all 3 inputs are valid.
- The Loading Dataset popup itself is one instance of the shared progress popup (`ui/shared/components/progress_popup/`), which owns the overlay markup, the sweep spinner, and the elapsed counter; the run controller only decides when to raise and hide it, and pages that suppress the popup never build one. `createArcRhoBusyOverlay` wraps one popup instance in a scope counter so overlapping work keeps a single popup up until the last scope ends.
- The saving animation is the same popup driven by the shared save-progress framework (`ui/shared/components/progress_popup/save_progress.js`), and every window that saves an ArcRho object uses it: Dataset, DFM, Result Selection, Bornhuetter Ferguson, Cape Cod, and Berquist Sherman. A page creates one `createArcRhoSaveProgress({ subject })` instance and wraps its save entry point in `run`, so the save is blocked behind a card titled `Saving <subject>` for the whole round trip and every entry point into that save - save bar, keyboard save, shell save message, and bridge-dialog save - is covered by construction. The framework owns the wording: the card opens on `Preparing the <noun> before saving.`, `progress.writing()` switches it to `Saving the <noun> and updating dependent objects.`, and the noun is `method` everywhere except the Dataset window, which passes `dataset`. `progress.finish()` drops the spinner before any dialog the save opens - the post-save review warning, the Engine-unavailable message box, the dataset recalculation dialog - so no dialog opens behind it, and `run` always dismisses on the way out, including when the save throws. Overlapping saves share one popup through the same scope counter, and the elapsed counter matches the Loading Dataset popup.
- After the write commits, the saving card stays up through the Engine dependent-propagation walk: the save is Engine-hosted and returns with the dependent walk already finished, so the saving card is a plain spinner with no live stream; on a clean outcome that refreshed at least one dependent, the window shows a "Saved" notice listing the exact dataset instances the walk refreshed (`propagation.refreshed_datasets`), one name per row under a `<count> dependent datasets were updated:` line. The notice does not time out - the list is the only record of what the save rewrote, so it waits to be dismissed through OK, the close button, Esc, or a click anywhere in the window outside the box. Each row is a link: clicking it posts `arcrho:project-instance-open-dependent-dataset` with `openMethod`, through the same `openMethodReviewDataset` helper the review warning uses, so Project Instance opens the owning method page when that dataset is a method output and the dataset page otherwise. Clicking a row leaves the notice up, so a save that refreshed several dependents can be walked through one at a time, and the rows scroll inside the box rather than growing it past the window. A clean walk with an empty `refreshed_datasets` opens no dialog at all: it has nothing to report, so `showSavedDependentsNotice` resolves without raising a message box rather than interrupting the user to say that no dependent needed an update. A save never closes its window: the saved dataset or method stays open so the user can keep working in it, and only Cancel, the titlebar close, or the close shortcut dismisses it, each through the existing dirty-close confirmation. The notice covers the same clean-walk cases as before (including a no-op save's `unchanged` payload, which now passes silently) and is skipped for the DFM-hosted Data tab, whose DFM save reports for it. A failed or stalled walk resolves `null`, shows no notice, and leaves the dataset table's review-needed flags as the failure surface. The poller treats a `processing` status that stops updating for 45 s as stalled (the Engine heartbeats it every 5 s), and a `queued` one after 180 s, so a dead worker can never strand the popup. While a walk holds a reserving class, other saves into that class are refused with 423 and the message asks the user to wait; other reserving classes save normally.
- The Loading Dataset popup is reserved for slow paths: a clear-cache rebuild shows it immediately, and any other run shows it only when the request is still pending after the run controller's short scheduling delay, which is when a missing CSV cache forces an engine round trip. Cached Project Instance opens and quick cache hits render the grid without a spinner while the shell status line reports progress; the run controller still adopts an already-visible popup, keeps its running elapsed counter, and hides it when the load settles or fails. Temporary-view opens skip the dropdown/preference/sidecar boot chain the same way cached Project Instance opens do, because their inputs come entirely from the URL and the authoritative run validation reloads the lists it needs on demand; boot and run validation load the Dataset Type and reserving-class lists concurrently. Because that skipped chain is also the only step that resolves a number format, a temporary-view boot resolves the Dataset Type default from `GET /dataset/number-format-defaults` and applies it to the Number Format and Decimal Places controls before scheduling the first run, so the first grid paint is already formatted instead of showing the page default until the next input change. The post-run sidecar sync reuses the memoized response, and if it does resolve a different format for a temporary view - the sidecar-owned format when the dataset already exists - it repaints the grid, because that sync runs after the run controller's first paint.
- The Data grid area has one owner for its three non-data states, `ui/shared/tabs/data/dataset_grid_placeholder.js`, shared with the DFM Data, Ratios, and Results grids. While a load is registered, the area shows a skeleton preview of the grid instead of an empty-state sentence: a header row, origin row labels, and placeholder cells sized from the shared spreadsheet cell tokens, using the already-known origin/development labels when a previous load or the headers service resolved them. The preview takes the shape of the dataset that is arriving rather than always previewing a triangle: known development labels decide it, and on a first open the `data_format` the opener already put in the window URL does, so a vector previews as one column of values under its own column label (`vector_column_label`, such as `Ultimate`) and a triangle keeps the staircase where each newer origin row is one development column shorter. Only a dataset whose format nobody stated falls back to a triangle. Resolving the shape reads the query string the browser already parsed and costs no extra request, and a one-column vector preview builds fewer cells than the triangle preview it replaces. One slow sweep runs across the skeleton, a caption naming the dataset fades in only after roughly `0.8s`, and an elapsed counter follows at roughly `3s`, so a fast local read stays silent while a slow network-drive read explains itself; `prefers-reduced-motion` keeps the same layout without the sweep. Loads are counted rather than toggled, so the skeleton survives the handoff from page boot to a scheduled run to the dataset load, and disappears only when the last one settles. When nothing is loading, the same area shows the empty state (`No Dataset Loaded`, or the host's own wording such as the DFM Ratios and Results hint or `Waiting For DFM Inputs`) or the failure title with the server message. A grid that renders before any load was ever registered shows the empty state rather than a skeleton.
- On Dataset page open, schedules the authoritative dataset run immediately instead of forcing origin/development header refreshes before checking the CSV cache. The dataset response is the canonical origin-label source: the server validates current project headers against the CSV shape and never substitutes a default start year. Development/calendar labels use the validated browser cache when available and otherwise load alongside the dataset request. Explicit Clear Cache still forces both label families to refresh. If valid labels cannot be resolved, the Data grid stays unloaded and shows the server's actionable Origin Start Date error in both the grid and page status. That failure also invalidates DFM views sharing the model, and late responses from an older dataset/header request are ignored so they cannot restore stale data.
- The refresh icon at the top right of the Data controls clears the current dataset cache and reloads the dataset. Existing datasets opened from Project Instance load the project validation list on demand without clearing the selected Project Name. The refresh also clears the ArcRhoHeaders CSV caches for the selected Origin Length and Development Length, including development and calendar column-label variants, before refreshing those labels. The dataset rebuild request and the origin/development header refreshes are independent engine round trips and run concurrently; the dataset reload waits for all of them, so a network-drive rebuild pays one round-trip wait instead of three sequential ones.
- The Data tab prevents invalid period-length combinations before refreshing a dataset triangle: Development Length cannot exceed Origin Length, so increasing Development Length above Origin Length automatically raises Origin Length to the same valid value; reducing Origin Length still lowers Development Length to a valid divisor when needed.
- Double-clicking the Data tab hides or shows the Data controls above the grid, letting the table use the extra vertical space without changing dataset settings or cached data.
- Dataset Type dependency validation and run/load actions use the matching route for the selected Data Format: Triangle rows check and load triangle caches, and Vector rows check and load ArcRhoVec period caches. Formula validation accepts a non-generated or ad-hoc input when its matching cache already exists for the selected reserving-class path and period settings, so an app-calculated output can be rebuilt from durable local inputs even when those inputs are not direct Field Mapping sources. Imported non-generated Vector datasets therefore open from their existing `<DatasetName>@<PeriodLength>.csv` cache instead of being blocked by the generated-triangle dependency guard or overwritten through the triangle route.
- Editable manual-input Triangle and Vector cells accept standard external Excel references entered or pasted directly into the cell editor, with no fixed Dataset formula bar. A reference includes the full workbook path/name, worksheet, and cell or rectangular range address, for example `='C:\Folder\[Book.xlsx]Sheet 1'!$A$1:$C$2`. A range loads its matrix from Excel and spills from the edited anchor into the corresponding editable Dataset cells. When the source range is larger than the visible Triangle or Vector area, values that would land outside the grid or in a noneditable triangle-mask cell are ignored; valid in-area destinations keep their matching source-cell offsets. Blank source cells are accepted and stored as `null`; the non-editing grid displays each one as a muted-gray zero using the Dataset's active number format, such as `0.0%`, without converting the saved value to numeric zero. The affected in-area read remains atomic when a mapped source cell fails to load or contains a nonnumeric value: every affected destination value and link stays unchanged. Valid numeric values, including zero and negative values, remain numeric. Linked cells use the same normal dark text and font weight as other values, while a multi-cell range receives a thin blue outer contour with a light inset glow; all four contour sides remain visible beside the sticky row labels and directly above the optional Total row, following the actual clipped Triangle or Vector destinations without drawing borders between affected cells. Hovering a linked cell opens a formula editor above the cell — above the whole spilled range when the link fills one — so the current external reference can be viewed or edited through the link's anchor. It is the same floating formula bar the DFM Ratios tab uses, sharing that bar's look and rules: the `fx` badge, the read-only colorized rendering that swaps to an editable input on focus, a width that follows the formula and is capped by the visible grid frame rather than a fixed panel size, and a slide-left instead of an overhang when the anchor sits near the right edge. The grid bounds the editor horizontally but not vertically: it is a fixed overlay, so a link in the grid's first row still gets its bar above the range instead of flipped underneath it, and the bar drops below only when the range reaches the top of the screen. Hovering opens it transiently; clicking the linked cell pins it open, clicking that cell again releases it, and while pinned it stays put when the pointer leaves.
- External-range destinations follow the visible grid orientation. In Transposed mode, the displayed spill is mapped back to the Dataset model's normal row/column coordinates so toggling Transposed does not change which logical cells are linked.
- A linked array uses one stable formula-bar anchor for its entire range. Hovering any cell positions the bar from the array's complete outer rectangle—above the array when space permits, otherwise below it—so the bar never covers array cells and does not move while the pointer crosses between cells in that array. `F2` uses the same placement from any selected linked cell.
- The Links tab appears immediately after Notes and lists each external source used by Data in the shared compact links table. Workbook path/name, worksheet, cell address, current Values, and destination are separate columns; a range shows its first current value followed by `...`. The tab has no toolbar; right-clicking a workbook row puts `Open workbook` and `Open workbook as Read-Only` at the top of the context menu, targeting the row that was clicked. Right-clicking the table background offers `Refresh all` and `Break all` when no rows are selected. Clicking a row selects it, Ctrl/Cmd-click toggles individual rows, and Shift-click extends a contiguous selection; right-clicking inside the selection preserves it while right-clicking an unselected row selects that row first, and while rows are selected refresh and break act only on that selection. A menu entry is omitted when it has nothing to act on, and the menu does not open while an action is running. Breaking retains every related currently loaded cell value as a hard-coded value, marks the Dataset dirty, and follows the normal Save/Cancel flow. The Project Instance Excel Link Manager can repoint a saved workbook path for every dataset and DFM method in a reserving class at once; by default it rewrites sidecar `external_links` references without touching values, timestamps, or audit history, while its opt-in recalculation checkbox commits refreshed values through the normal dataset save flow (audit, statuses, and propagation included). Open Dataset windows learn of either rewrite through the standard object-change watch alert.
- Dataset grid cells follow the shared spreadsheet-style table pattern: a translucent blue `#6197f166` selection with black text and no default outline, regular-weight dark-gray implicated row/column labels, a dashed anchor outline, and `aria-selected` state. The table draws its own complete cell-grid perimeter inside a neutral scroll-wrapper frame shared visually with DFM Ratios, and the sticky row-label column automatically expands beyond the standard cell width when needed to show its top-left header label in full. Selected row and column labels retain their dark-gray fill when hovered; the pale hover fill applies only to unselected labels. Shared range normalization, selection painting, anchor/label state, movement, context-cell preparation, TSV generation, and clipboard copy come from `ui/shared/components/spreadsheet/spreadsheet_table.js`; Dataset retains only its editable/transposed-grid adapter. The grid supports rectangular drag selection, Shift-click extension, whole-row/column selection, arrow navigation, Escape clearing, copy, direct numeric entry, and Excel-style paste. Plain Arrow keys follow Excel-style active-cell navigation: a multi-cell highlight collapses to one cell moved from its dashed anchor instead of translating the entire rectangle; Shift+Arrow extends the range, and Ctrl/Cmd+Arrow moves to a grid edge. Clicking a row or column label establishes a label anchor; Shift-clicking a second label of the same type selects every row or column between those two labels. Editable manual-input data cells render formatted display values until the user selects a valid cell and starts typing a number; the inline editor then opens only for the active/top-left selected cell, honors the active Dataset number format, and preserves the current grid column widths. Escape exits edit mode and restores the value and dirty-state entry from before that edit began. Clicking a cell only highlights/selects it, and Delete or Backspace sets the selected editable range to `0`. Pasting one value fills every eligible cell in the selected range; tab-separated matrix paste starts at the selected range's top-left cell, while paste inside an active cell editor starts from that cell. The grid uses native scrolling without idle row/column snapping, so wheel and trackpad scrolling can stop with partial cells visible; visible scrollbar tracks/corners use a light grey fill inside the table frame, and scrollbar thumbs brighten only while scrolling or when the pointer is over a scrollbar lane, then fade to a quieter idle state. When the grid has no vertical overflow, it does not reserve an empty vertical-scrollbar gutter, so the horizontal scrollbar thumb reaches the visible right end of its tray. Right-click preserves the current selection when invoked inside it or selects an unhighlighted target first. The cell context menu shows `Copy values`, eligible-only `Paste`, `Remove Highlights`, and `Export data`; copying uses tab-separated text, or the top-left selected cell when multiple separate ranges are selected. Pasted and typed values mark editable manual input datasets dirty for the visible Dataset Save action, which writes the current grid to the length/mode-scoped CSV.
- The derived `Total` row participates in the same click, drag, Shift, row-label, keyboard, context-menu, and copy selection behavior as data cells. Total cells remain read-only, and paste, direct entry, Delete, and Backspace skip them. In transposed mode, the same behavior applies to the right-side `Total` column and its column label.
- The Data tab Transposed checkbox is a client-side display mode, matching Excel add-in behavior: it reuses the current ArcRhoTri CSV cache and flips rendered rows/columns, totals, chart data, and copied selections without sending a new data-engine request.
- ArcRhoTri dataset files are written under `projects/<project>/data/<ReservingClassFolder>/datasets/<DatasetName>@<OriginLength>@<DevelopmentLength>@<cum|inc>@<dev|cal>.csv`; ArcRhoVec cache files use `<DatasetName>@<PeriodLength>.csv`. Engine datasets share one base `sidecars/<DatasetName>.json` sidecar that records `source_kind: "engine"`, saved Data-tab settings including `transposed` and `show_subtotal`, and the Windows login user in `user` and `modified_by`; vector sidecars store their single granularity as `period_length` instead of triangle-only origin/development mode fields. Project, reserving-class, and dataset file components use the shared reversible `_%XX_` filename escaping rule used by DFM, the app server, and Excel add-in request paths. For example, `/` becomes `_%2F_` before the dataset page checks or requests a CSV cache file.
- Dataset external-link persistence keeps formulas out of the CSV. The CSV stores only the current value snapshot, while the base sidecar stores `external_links` records with the Excel `reference` and logical `target_cells`; each target uses a zero-based Dataset `{row, column}` plus a normalized A1 `source_cell`. This explicit source mapping preserves offsets when part of a large source range is clipped by the grid boundary or triangle mask. Each record must contain one valid standalone workbook range, every mapped source cell must belong to that range, and one Dataset target can belong to only one link. Reopening an editable Dataset loads the snapshot, restores the mappings, and refreshes the linked cells; only changed refreshed values contribute value edits, while link additions, removals, and breaks participate in Dataset dirty-state tracking independently.
- When the selected Dataset Name resolves to a manual input sidecar (`source_kind: "input"`), Dataset Viewer treats the Name as the cached instance identity rather than a Dataset Type to regenerate. It loads exact manual caches, can derive coarser period requests from finer cumulative caches, and reports a clear local-cache error instead of sending an engine request when a requested finer/detail shape cannot be derived from the available manual cache.
- When an opened manual Dataset Viewer dataset has Excel links, the initial durable open compares each unique linked workbook's filesystem modification time with the stored dataset CSV modification time. If any workbook is newer, a warning defaults to **Keep Current Values** and offers **Refresh from Excel**. Refresh reuses the normal external-link refresh path and marks every successfully refreshed linked cell as unsaved work even when its value is unchanged, so Save rewrites the durable CSV snapshot and advances the freshness baseline; keeping values or encountering an unavailable workbook leaves the stored grid untouched.
- The Dataset page Save/Cancel row uses a reserved bottom frame across all Dataset tabs, matching the DFM page pattern so large Data tables scroll above the buttons instead of underneath them. Save writes the Details `Name` as the instance name, the selected Dataset Type, current Origin Length, Development Length, Cumulative, Transposed, Calendar, Show subtotal, Decimal Places, and Number Format values, and dirty Notes; for Project Instance non-generated drafts and existing manual input datasets, Save also writes the current Data grid values to the backing CSV and stores that file name in the sidecar. Background Data-tab runs may create or reuse a length-scoped CSV cache for preview, but do not update the user-editable source sidecar or clear the unsaved settings state. When a background run generates or derives a cache, it writes only a technical record containing per-CSV processing provenance plus a size, modification-time, and SHA-256 content fingerprint, so a later run can safely reuse that exact file; it does not save Data-tab settings or audit history. Only Save commits those settings. Cancel closes the Dataset window; when dirty, it opens the shared page-local close confirmation where the default Yes action discards unsaved changes, while No, Escape, clicking the backdrop, or closing the box returns to the unsaved page. The dialog states, "Unsaved changes will be discarded and the window will close." The modal stays inside the Dataset page and makes the rest of that page inert while it is open. CSV filenames still distinguish cumulative, incremental, development-view, and calendar-view variants.
- While hosted in Project Instance, dirty manual Dataset grid values publish `arcrho:dependency-source-preview` messages with both latest-diagonal/vector values and full matrix values. Dirty DFM output vectors publish the same preview contract. Open dependent Result Selection windows use the vector values, while DFM input-triangle windows and matching Dataset Viewer windows can render the temporary in-memory table without marking themselves dirty. A Dataset Viewer applies a preview only when the message or its current loaded model provides valid consecutive origin labels matching the selected period type and preview row count; otherwise it leaves the current grid unchanged and reports the Origin Start Date correction instead of creating numeric row labels. Project Instance also requests in-memory app-calculated previews for downstream calculated Dataset Types and publishes target-specific preview messages so open calculated Dataset windows, and Result Selection method sources that reference them, can update before the upstream source is saved. Typing or pasting unsaved Dataset values or Excel references updates only this in-memory dirty/preview flow and does not request a Project Instance disk-backed dataset inventory refresh; the persisted inventory refresh remains tied to Save or an explicit Project Instance refresh. Save, Cancel, or close-without-save publishes `arcrho:dependency-source-cleared`, so dependents reload the source from persisted disk data.
- The Data tab Number Format field is editable and offers preset suggestions for `0,000`, `0.0%`, `0,000.00`, and `0`; changing it marks dataset settings dirty, immediately refreshes the grid/chart display, and persists as sidecar `number_format` on Save. Number Format and Decimal Places use the shared filled-caret dropdown/stepper arrow style, with muted arrows at rest and stronger arrows on hover, focus, or open. Decimal Places remains the source of truth for fractional digits, so changing Decimal Places rewrites the visible format pattern (for example, `0,000.00` becomes `0,000.0` when Decimal Places changes to `1`) and persists as sidecar `decimal_places`.
- The Chart tab uses the same shared right-side legend panel as Result Selection: it shows the visible-series count, full-row visibility checkboxes, and line-and-marker swatches. One series always remains visible; right-clicking a legend item isolates that series, and right-clicking the sole visible item restores all series. In narrow windows the legend moves below the chart.
- The Audit Log tab renders the dataset sidecar `audit_log` entries newest first, with Event Date displayed as `M/D/YYYY h:mm:ss AM`. It uses the shared `ui/shared/tabs/audit_log/` presentation also consumed by method pages, so the compact bounded table, sticky header, plain-text Action values, row hover feedback, loading/error/empty states, continuous square frame, and quiet scrollbar behavior remain consistent. The scrollbar tray consumes space only while overflow requires a scrollbar. Dataset sidecar inserts, metadata saves, grid value patch saves, ArcRhoTri sidecar creation, and calculated dataset recalculation append records capped at 50 entries with `event_date`, `action`, `change_info`, and `user`; `change_info` is blank for `Insert` and `Values` for `Update`.
- When Dataset saves, grid patch saves, or ArcRhoTri refreshes trigger calculated-dataset or method updates, the Dataset page shows a compact modal report with the ordered recalculation chain, decoded reserving-class paths, and skipped/error details. The source Dataset remains saved if a downstream DFM, Result Selection, or BF refresh fails, but the page reports that partial result as a warning with the downstream error instead of showing an unqualified save success.
- Dataset Viewer query parameters accept explicit origin/development lengths, an initial tab, a Project Instance draft mode, an optional `data_format`, an explicit `ds` cache id, and a read-only flag. Draft launches from Project Instance open on Details, honor the provided project, reserving-class path, dataset type, data format, and lengths, but skip the initial auto-run and build an editable zero-filled Data-tab placeholder from validated current-project origin labels and current development labels. A missing/invalid origin-header response leaves the draft grid unloaded, reports the Project Settings error, and blocks Save; drafts never substitute numeric origin rows. Triangle drafts use the standard triangular mask, while Vector drafts use the server-matching one-column vector shape. A draft that has not been persisted yet is always save-eligible: it opens fully prefilled from the picked Dataset Type, so Save and `Ctrl`+`S` stay enabled with no control or grid edit, and the first save writes the placeholder grid even when the user typed no values. Save returns to disabled once the draft is saved, and renaming an already saved draft makes it save-eligible again. That pending-save state is deliberately not the tab dirty state: an untouched draft still closes without a discard confirmation. Saving a draft persists the placeholder grid to the length/mode-scoped CSV, records the returned `ds_id`, and keeps later grid edits attached to that CSV-backed cache. Manual input Triangle/Vector datasets keep Cumulative and Development/Calendar mode locked; if any stored cell is non-zero, the Origin Length and Development Length controls cannot be lowered below the saved lengths until all cells are set to `0`. In draft mode, Details `Name` defaults to the selected Dataset Type but remains editable as an independent instance name. Draft Dataset `Name` values must be unique within the selected reserving-class path; when the name already exists, the Details tab shows a floating warning tooltip beside the Name field and blocks Save and generation until the name changes. Existing dataset launches do not show the draft duplicate-name warning for their own name. Read-only launches disable manual CSV patch saves and reject grid paste edits. Loaded sidecars are editable only when `source_kind: "input"`; other source kinds such as `engine`, `calculated`, `dfm`, `result_selection`, or `bornhuetter_ferguson` force the grid into read-only mode.
- Right-clicking a Dataset page tab temporarily moves that live tab page into a draggable, resizable floating window inside the Dataset page, using the same shared tab pop-out behavior as DFM. The floated tab keeps its original controls, event handlers, and data state because the actual tab DOM is moved rather than cloned. Pop-out and dock use short fade/scale transitions. Floating titlebars support double-click maximize/restore and drag-from-maximized restore to the previous window size. Closing the floating window, right-clicking its titlebar, or right-clicking the grey popped tab button docks the tab back into the normal tab area. The Chart tab redraws after pop-out, dock, focus, and resize so the canvas fits the floating window; in the normal docked tab, the chart panel also stretches with the tab area and redraws when that panel size changes.
