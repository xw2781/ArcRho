## Purpose
<!-- MANUAL:BEGIN -->
Annual MVP page for `B&S Settlement Rate Adjustment` and `B&S Case Reserve Adequacy Adjustment`. It reproduces the imported ResQ COL calculations while keeping the saved ArcRho artifacts minimal.
<!-- MANUAL:END -->

## External Interfaces
<!-- MANUAL:BEGIN -->
- Project Instance offers separate Add commands for the two B&S variants when an annual input triangle with Method Type `None` is selected.
- Both variants use the shared method page and canonical contract module. They participate in the standard save, close, status, tab-state, and live dependency-preview messages. After the first successful save, Project Instance keeps the same floating window open under the saved output Name.
- `Ctrl+PageUp` and `Ctrl+PageDown` cycle through the outer Berquist Sherman method tabs with wraparound through the shared tabbed-page runtime, including when Project Instance still owns keyboard focus.
- The migration macro imports the required ResQ source names, annual labels, and calculation selections. It also fills missing annual labels on existing source sidecars without replacing labels that are already present. B&S methods do not use the bidirectional synchronization workflow.

## Data/State/Caches
<!-- MANUAL:BEGIN -->
- Settlement Rate uses paid claims, closed claim counts, an ultimate claim-count vector, selected proportions settled, a method-level loess span, and the selected adjustment for each populated cell.
- Both variants list their Details sources in the ResQ order: Paid Claims, Closed Claim Counts, Ultimate Claim Counts for Settlement Rate, and Paid Claims, Incurred Claims, Reported Claim Counts, Closed Claim Counts for Case Reserve Adequacy.
- The contract carries two names per variant. `method_type` is the persisted routing identity shared with sidecars, `index.json`, method JSON, and the ResQ migration, and must not drift. `display_label` (`Berquist Sherman SR` / `Berquist Sherman CRA`) is the ResQ wording every user-visible surface shows instead: the Project Instance Method Type column and Add menu, the floating-window title, the page title and Details `Method Type` field, status messages, and the shared Data-tab links. Both names normalize back to the same variant, so a display string can never break window routing or an Add command.
- Number formats follow the canonical `dataset_number_format.js` helpers. Each input view renders with its own dataset instance's `number_format`/`decimal_places`, exactly as the Dataset Viewer shows that dataset; every calculated triangle uses the Details tab's `Number Format` and `Decimal Places` pair, which is also the output dataset's own format and is written to the output sidecar on save. B&S applies the Dataset Viewer mask together with the annual staircase when source triangles load, so real zero observations remain visible while padded zeroes in the unavailable lower-right area stay blank in source and calculated views. That mask has to survive presentation as well: `formatDatasetNumberValue` coerces its argument with `Number(...)`, which turns a missing cell into `0`, so the page resolves a blank before it formats. A row of a masked triangle is exactly as long as the cells it owns, and every grid past that length renders a `.bsMaskedCell` carrying neither a value, a fill, nor a grid line, so the unavailable area reads as it does in the Dataset Viewer instead of as a block of zeroes. Row hover leaves that area alone with the other meaningful fills. Inside the triangle a cell the calculation could not produce — an average with no open claims, an adjusted value above the latest diagonal — is blank rather than zero. Two rate grids are exempt: `Proportion Settled` keeps its percentage presentation and the CRA `Average Inflation` grid its four decimals, because at the Details format's zero or two decimals every estimator in a column would print the same figure.
- `method_tab.number_formats` records both: `derived` for the calculated triangles and one `sources` entry per source role. The recorded source formats are display state, not calculation inputs, so when a source dataset is restyled the method's copy catches up on its own the next time the method loads its sources: the page rewrites only that field of the stored method JSON, leaving `method_metadata.last_modified`, the output sidecar, and its review status untouched, and without making the page dirty. Only the Details pair counts as a user edit.
- The Details tab is the shared `arDetails*` form used by DFM, BF, CC, and RS, and it keeps their layout: the group padding and `--ar-details-group-separation` are the only spacing between the identity group and the source group, each source picker is a 22px square sitting inside the right edge of its own field rather than a control beside it, and the `Decimal Places` spinner is the same short numeric control as the read-only length fields. That spinner is the shared stepper, so its geometry comes from `--topbar-control-height` and its wrap must be a block-level box; an inline wrap silently drops its own width and lets the field stretch across the form.
- The page shell follows the DFM/BF frame: the shared tab strip, the bordered page frame, and the save bar are flex rows of the shell, the frame keeps the same left/right `--tabbed-page-gutter` as the strip so the strip's bottom rule meets the frame corners, and the save bar sits on the canvas outside the frame. Inside the Method tab, the nested calculation strip encloses its own client area the same way, matching the inner tab control in ResQ: `.bsMethodFrame` is inset by `--bs-method-inset` so its walls meet the ends of the strip's bottom rule, and its rows are inset by `--bs-method-pad`. Those rows are a flex column rather than fixed tracks, because the message row and each captioned grid pane are hidden when the view has nothing to put in them and the grids must keep filling the rest of the client area. The message row reports calculation failures only; a successful calculation clears it, as in ResQ. Row hover tints plain value cells only: it never repaints a fill that carries meaning, so a selected estimator, proportion, or inflation source cell, the `Selected` and `User Value` bands, and the rows that group or separate them keep their own fills under the pointer.
- A view is one captioned grid pane, except the Case Reserve Adequacy `Avg. Selections` view, which stacks two. Equal flex bases split the client area between them the way ResQ splits that tab. One `Loess Span` stepper serves both variants and moves into the caption of whichever grid owns the loess estimator.
- The Method tab's calculation views render as a nested tab strip using the shared tabbed-page chrome, in the exact ResQ sub-tab order. Settlement Rate: `Paid Claims`, `Numbers Closed` (closed triangle plus an `Ultimate` column), `Proportion Settled`, `Selected Numbers Closed`, and `Adjusted Paid Claims`. Case Reserve Adequacy: `Reported`, `Closed`, `Open`, `Paid Claims`, `Incurred Claims`, `Case Reserves`, `Avg. Case Reserves`, `Avg. Paid`, `Avg. Selections`, `Adj. Avg. Case Reserves`, and `Adj. Incurred`. Each view shows its ResQ caption line above the grid, each variant opens on its first sub-tab, and the strip wraps onto a second row when eleven sub-tabs do not fit, as the inner tab control does in ResQ.
- The `Proportion Settled` view mirrors the ResQ selection UX: the triangle shows percentages, clicking a value selects it for that development period, the chosen source cell per column is highlighted (the leading diagonal by default), and a separated `Selected` bottom row shows the selections in a pale band with editable typed values. Right-click offers `Select Leading Diagonal` to reset the defaults.
- The `Adjusted Paid Claims` view is the ResQ-style selection grid: each origin period shows `Unadjusted`, `Pairs`, `All`, `Loess (n)`, and `Selected` rows. Clicking a value selects that estimator for the single cell, clicking a row label selects it for the origin period, and Ctrl+Click on a row label selects it for every populated cell. The chosen source cell is highlighted and the `Selected` row echoes it in accent color.
- `calculation_helpers.js` owns the loess span bounds and the tri-cube weighted local straight-line fit over the `span + 1` nearest neighbours, so both variants and the ResQ migration normalize one span the same way. Settlement Rate fits log paid claims against closed counts, evaluated at the selected claim counts, and a degenerate fit reverts to the pair-wise interpolation. Case Reserve Adequacy fits the positive latest average case reserves themselves, on the value scale, against development period; a local line there needs three weighted neighbours, because ResQ reports `0.000` rather than interpolating between two. Both spans persist as `loess_span` in the method JSON, which the ResQ migration also emits from `LoessSpan`.
- Case Reserve Adequacy uses reported and closed claim counts, incurred and paid claims, inflation selections, average-case-reserve selections, and a method-level loess span.
- The `Avg. Selections` view mirrors the ResQ selection UX in two grids. `Average Inflation` lists `Column` and `All` under a `Case Reserves` and a `Paid` grouping row, then `User Value` and `Selected`; `Current Average Case Reserves` lists `Latest`, `Monotone`, `Loess (n)`, `User Value`, and `Selected`. Clicking a value selects that estimator for the development period, clicking a row label selects it for every development period, and committing a `User Value` enters the figure and selects it for that column. The chosen source cell is highlighted, the `User Value` row is the editable pale band, and the `Selected` row echoes the choice in accent color. Inflation keeps a fourth decimal because the third alone cannot separate the estimators; the case reserve grids keep ResQ's third.
- The COL CRA exclusion flags are deferred: verification with none, either matrix, or both matrices produced the same selected inflation and final output. The `Avg. Case Reserves` and `Avg. Paid` views are therefore read-only triangles rather than ResQ's click-to-exclude grids.
- All result-affecting selections live inside the Method grids at their ResQ granularity: per development age for proportions settled and the CRA inflation and average selections, and per populated cell for the Settlement Rate adjustment.
- Method JSON stores source dataset names, labels, selections, and identity metadata. Notes live only in the output dataset sidecar; method JSON does not duplicate notes, source matrices, or calculated result matrices.
- When opened inside Project Instance, B&S reuses the parent page's already-loaded dataset-index snapshot for its initial source inventory. Explicit refreshes and post-save refreshes still request the authoritative server index.
- Opening a page is one registered workspace read. `POST /berquist-sherman/load` returns the method JSON and the output sidecar together through `berquist_sherman_load` in `arcrho_workspace_read_contract`, so on a Client PC the pair is served by the ArcRho Gateway from the server host instead of costing two mapped-drive visits — the same transport DFM, BF, CC, RS, and Bootstrap already use. That read matters more here than elsewhere: B&S persists its method JSON through the Electron host API, and a host-API file read never enters the app server, so before this route the method file could not reach the Gateway at all. The sidecar half is not one file either — `load_dataset_sidecar` also opens the project's dataset-type rows and the reserving-class index. The service reads and only reads: the method payload comes back verbatim, because the page and the ResQ migration own that schema and a second normalization in the service would become a competing source of truth. The variant arrives from the browser and selects the `BSSR@`/`BSCRA@` filename prefix, so it is checked against the two B&S method types first; a hosted read runs on the server host under the caller's identity and must not be steerable at another method type's JSON. The page open and the dataset-index read are independent, so they are issued together rather than in sequence, and both land before the sources load.
- The final result is stored as an annual Triangle CSV at `datasets/<Name>@12@12@cum@dev.csv`; the related sidecar stores the canonical method/source identity and direct precedents.
- Matching dirty source previews recalculate the open method in memory without making the B&S page dirty. The recalculated B&S triangle is relayed to open dependents, and clearing a preview reloads the source and clears or refreshes the downstream preview. Saving is blocked until upstream preview changes are saved or discarded, so the persisted result remains reproducible from its named sources. Once sources are durable and readable, their Review Needed status does not block Save; the committed save is followed by a page-local message box reporting how many precedents have not been reviewed.
- A Berquist Sherman save runs behind the shared saving animation described in [`dataset.md`](dataset.md), titled `Saving ` plus the variant's display label, so the page cannot be edited while the method JSON, output CSV, and sidecar writes settle. `saveMethod` wraps the save in it, so the Save bar and the shell `arcrho:dataset-save` message are both covered; the card then streams the sidecar save's dependent walk (`calculated_updates`) live and the spinner is dismissed before the post-save review warning. Neither explicit save entry point closes the window: after a clean walk (`propagationClean`) they show the saved-dependents notice and leave the method open, and a failed or stalled walk shows no notice.
- The post-save review warning lists every unreviewed precedent by name. Each name is a keyboard-focusable link that opens its related method window when the dataset is method-backed, or its Dataset Viewer otherwise, while keeping the saved B&S method unchanged.
- Fresh methods load annual origin and development labels from the project's canonical headers; inputs with mismatched formats or known periods are rejected. A legacy source sidecar with no labels is treated as unavailable metadata rather than as a conflicting period set.

## Common Change Tasks
<!-- MANUAL:BEGIN -->
1. Change a formula in the corresponding pure calculation module and update the focused COL parity test.
2. Change saved fields only with the migration and dataset-index consumers aligned to the same contract.

## Known Risks
<!-- MANUAL:BEGIN -->
- All MVP inputs must be annual and use matching triangle shapes.
- Persisted labels, prefixes, source kinds, and JSON formats are routing identities and must not drift between the frontend and migration.
