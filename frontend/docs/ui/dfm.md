# Frontend: Dfm

## Purpose
<!-- MANUAL:BEGIN -->
DFM feature across Details, Data, Ratios, Results, Notes, Links, and Audit Log on top of dataset context, including method metadata in Details. Links appears immediately after Notes.
DFM Notes reuses `ui/shared/tabs/notes/` for path highlighting, `Tab`/`Shift+Tab` indentation, `Esc` to exit editing, spellcheck off, and whole-note display formatting while preserving DFM's `dfm_persistence.js` save flow. File paths render as deep-blue underlined non-bold text, known file extensions stop the token before trailing prose, and right-click shows `Open File`, `Copy File Path`, plus `Open as Read-Only` for Excel workbooks; focused editing shows plain text until focus leaves the textarea and toolbar. DFM relays nested `arcrho:open-path` requests to its parent so Notes links keep working in popped-out tab surfaces.
<!-- MANUAL:END -->

## External Interfaces
<!-- MANUAL:BEGIN -->
- Exchanges `arcrho:*` messages with shell and workflow iframe.
- Reuses dataset APIs and reserving class selectors.
- DFM lives under `ui/method_pages/dfm/` and uses `ui/shared/tabbed_page/` for reusable tab chrome plus the matching `ui/shared/tabs/data/`, `ui/shared/tabs/details/`, `ui/shared/tabs/notes/`, `ui/shared/tabs/links/`, and `ui/shared/tabs/audit_log/` modules for shared tab presentation/runtime. DFM modules still own method persistence, dirty state, save/close coordination, calculations, and page-specific behavior; `dfm_data_tab_adapter.js` connects those feature concerns to the host-neutral Data tab without importing Dataset Viewer assets. Established DFM tab IDs and `arcrho:*` contracts remain unchanged.
- DFM Data grid uses the shared Data-tab `#tableWrap` scroll frame, while the table draws its own complete cell-grid perimeter inside that frame. The Data and Ratios scroll frames use the same shared neutral border color, and the separate table edge matches the Ratios-tab structure without changing sticky-header or sticky-row-label behavior.
- The shared Data tab keeps native scrolling inside `#tableWrap` without idle row/column snapping, so mouse wheel and trackpad scrolling can stop with partial cells visible.
- DFM Ratios tab now uses a dedicated framed scroll host (`#ratioWrapHost` -> `#ratioWrap`) so sticky headers/first-column overlays are contained within the ratio grid viewport instead of page-level scrolling.
- DFM Data tab wraps `#tableWrap` inside `#tableWrapHost`, so shared data-surface sticky header/first-column behavior remains pinned inside the table viewport during Data-tab scrolling.
- DFM page boot waits for the shared Data-tab controller to finish so project-specific origin/development labels are refreshed before Data and Ratios tabs render their triangle headers. When the DFM inputs are not ready yet, the shared Data-tab runtime waits for the method load instead of requesting a stale remembered dataset ID.
- Opening a DFM tab now lands directly on the Details page instead of showing a startup chooser. The Details `Name` field has a `...` selector that reads the selected Reserving Class folder's cached `index.json` through the DFM method-index endpoint and lists DFM-backed dataset names associated with that path. Selecting a name commits the normal Details lookup, so the existing local DFM JSON load flow applies the method settings.
- DFM Data and Results table cells that display percent-formatted input values always use one decimal place (`0.0%`), independent of the DFM ratio decimal-place controls.
- DFM Results tab table now shows per-origin columns in this order: `Latest <Input Triangle Name>` (latest observed value from DFM Data-tab triangle row), `Reserve` (`Ultimate - Latest`), and `Ultimate`; Results header cells allow wrapped text so long input triangle names are readable instead of truncating to one line.
- DFM Details `Output Vector` is the vector dataset type that the DFM method attaches to and is selected from the current project's `dataset_types` Vector rows. `Input Triangle` is selected from the same project dataset-type picker filtered to `Triangle` rows. DFM Data refresh loads an exact input cache when present; generated input triangles can request ArcRhoTri to create a missing shape when the base sidecar exists. Manual/imported input triangles stay local-cache-only: DFM can derive coarser period requests from finer cumulative local caches, such as quarterly to annual, and rejects requests for finer detail than the local cache provides. DFM shows an explicit alert/status error when the input triangle sidecar is missing or a manual/imported requested period detail cannot be derived.
- DFM Ratios restores the machine-local user's last Select/Edit mode when the page opens; if no saved preference exists or local storage is unavailable, it opens in `Edit` mode. Changing mode from the context menu or with `S`, `E`, or `Ctrl+E` updates that local preference without changing method dirty state or saved method JSON. Select mode creates a temporary cell/range highlight for copying without changing ratio exclusions, active columns, selected average formulas, or average-row order; table headers retain the normal arrow cursor. Highlighting alone does not change User Entry values, but typing a digit or decimal point starts direct entry in the active highlighted User Entry cell in either Select or Edit mode. The main and average-table Ratios context menus show the dynamic `Switch to Edit Mode` / `Switch to Select Mode` command with its pen/hand icon after the text; the main menu follows it with `Show Data` / `Hide Data`, and there is no separate Ratios toolbar. In Ratios terminology, **selected** cells are persisted method choices shown with a light-green fill, while **highlighted** cells are the temporary copy/focus range shown with a continuous dark-green outer border. Clicking a Ratios table cell or header focuses the table surface; while it remains focused, `S` enables Select mode and `E` enables Edit mode. `Ctrl+E` toggles between Select and Edit whenever the Ratios tab is active; the shell and Project Instance forward this command to the active DFM, and the DFM captures it across its whole page, including while a control has focus. Plain `S` and `E` remain disabled while typing in controls. In Select mode, an Arrow key collapses the highlighted range to a new single cell one step from its anchor, Shift+Arrow extends the range from that anchor, Ctrl/Cmd+Arrow collapses it to the corresponding table-edge cell, and Ctrl/Cmd+Shift+Arrow extends it to that edge; keyboard movement keeps the active cell visible and works in the main Ratios, average-formula, and selected-summary tables. Pressing `Enter` in a highlighted main-ratio range toggles each valid cell's exclusion status as one undo step. Pressing `Enter` in a highlighted average-formula range selects the highlighted formula for each covered development column and applies the green selected fill; if one column's highlight spans multiple formula rows, the topmost highlighted row wins. Enter does not apply these range actions in Edit mode. The view-only Show Data command interleaves the current Data-tab observed values before their corresponding ratio columns; average-formula and selected/cumulative rows receive blank data-column spacers so all logical ratio columns remain aligned. Toggling Show Data does not change ratio indices, formulas, saved method JSON, or dirty state. Highlighted cells and rectangular ranges use the continuous dark-green outer border across the main Ratios triangle, average-formula table, and selected/cumulative table; covered development-column headers and row labels use the shared darker-gray, regular-weight selected-label style. Edit-mode summary-cell actions do not apply that temporary label emphasis. Starting a highlight in another Ratios table automatically clears the previous table's highlight and label emphasis, while `Escape` clears the active highlight. `Edit` clears any temporary highlight before restoring table mutations and uses the Windows-style Handwriting pen cursor over table cells. The Ratios, Ratios summary/selected rows, and Results tables support highlighted-cell copying consistent with Dataset grids: a single rectangle copies as tab-separated text, and multiple separate ranges copy the top-left highlighted cell. The shared table context menu keeps only `Copy value` and `Export data`; the main Ratios menu places its mode and data-view commands before `Copy value`, while the average-formula and percent-developed context menus retain their table-specific commands. Shift/Ctrl-drag highlights Ratios cells in Edit mode without replacing the existing strike-toggle drag gesture. Existing selected-ratio/selected-formula fills are preserved.
- The average-formula summary table context menu also begins with the dynamic Select/Edit mode switch and updates the same machine-local mode preference as the main Ratios menu.
- DFM Ratios User Entry formulas highlight referenced average-formula cells by exact quoted average-formula name. While the formula bar is in edit mode, the active referenced cell in the same development column gets a thicker colored outline; dragging that outline to another average-formula row rewrites the row reference in the formula bar immediately. The formula bar frame follows the average-formula summary table, while its `fx`, formula text, Excel-link, refresh, and open controls track horizontal scrolling and stay clamped inside the DFM scroll viewport.
- DFM Ratios User Entry formula cells accept standard external Excel range references containing the full workbook path, worksheet, and address, such as `='C:\Folder\[Book.xlsx]Sheet 1'!$A$1:$C$2`. The referenced matrix spills from the anchor into adjacent User Entry rows and development columns while every table cell continues to display its refreshed numeric value. Selecting any affected cell shows the shared range formula in the editable formula bar; editing from any cell updates the range through its anchor. A thin ArcRho-blue outer border with a light inset glow marks the range without changing interior fills, and activating any cell inside it strengthens the glow slightly. When Show Data is enabled, the border and glow continue across the interleaved blank data spacer cells so the logical formula array remains one connected rectangle. Changing, clearing, or overwriting the shared formula restores cells no longer controlled by that range to `1`. When a saved DFM page opens, its Excel-linked formulas refresh once; the DFM becomes dirty and the app status bar reports the changed linked-cell count only when refreshed values differ from the saved DFM JSON.
- The DFM Links tab appears immediately after Notes and derives its inventory from external Excel references in Ratios User Entry `inputs`, including standalone range formulas and external references embedded in expressions. It uses the reusable shared Links presentation and shared Excel-reference parser also used by Dataset Viewer. Workbook path/name, worksheet, cell address, current Values, and Ratios destination are separate columns; a range shows its first current value followed by `...`. The frameless toolbar provides `Refresh all` and `Break all` when no rows are selected. Clicking a row selects it, Ctrl/Cmd-click toggles individual rows, and Shift-click extends a contiguous selection; while rows are selected, refresh and break act only on that selection. Breaking replaces every related User Entry consumer with its current numeric value, including every destination controlled by a spilled range, then follows normal DFM dirty/save behavior. The inventory is derived from Ratios state and is not a separate DFM method JSON section.
- DFM Ratios User Entry rows accept a single clipboard value or a rectangular Excel cell range pasted from the active User Entry cell. Range pastes are applied atomically across User Entry rows and development columns; invalid, non-positive, non-rectangular, non-User Entry, or out-of-bounds destinations are rejected without partially changing the table.
- DFM Results tab adds a `Ratio Basis` selector above the table (typed input + `...` dataset picker window backed by `ui/shared/components/pickers/dataset_name_picker.js`). The picker exposes all dataset names from current-project `dataset_types` (including calculated and non-triangle/vector types), while Result-column extraction currently supports only `Triangle`/`Vector` selections; unsupported types show a clear error status. Results also includes a dedicated `Ultimate Ratio Decimals` input (default `2`) used only for the `Ultimate Ratio` percent column formatting. After selection, Results appends `Ratio Basis: <dataset>` and `Ultimate Ratio` columns after `Ultimate`; the ratio-basis column uses values from the selected dataset at the current DFM `Origin Length` basis (triangle basis datasets contribute the latest diagonal value per row), and `Ultimate Ratio = Ultimate / Ratio Basis`. Results also appends an unfilled `Total` row that sums numeric columns; `Ultimate Ratio` total is computed as `Total Ultimate / Total Ratio Basis`. Clicking a Results row label selects that row, and clicking a column header selects that column including its Total cell; implicated labels receive the shared spreadsheet selection emphasis. The selected Results table receives keyboard focus, so `Escape` clears the active cell or range, and its Total row label retains the shared Data-table label fill. Ratio Basis loading passes the current project and Origin Length to the dataset endpoint; if the server cannot resolve valid origin labels, the column stays unavailable and the Results error status displays the server's Origin Start Date message instead of using a default year.
- DFM method save writes Results vector CSV variants under `projects/<project>/data/<ReservingClassFolder>/datasets/<DatasetName>@<OriginLength>.csv` and saves a single canonical JSON metadata sidecar through the app-server sidecar endpoint at `sidecars/<DatasetName>.json` for the base instance name; the sidecar records `source_kind: "dfm"`, `method_type: "DFM"`, `status: 0`, `data_format: "Vector"`, and current `Precedents`/`Dependents` graph metadata. Saving a DFM Results vector returns and reports any dependent calculated dataset refreshes triggered by that output, then publishes `arcrho:calculated-datasets-updated` so open matching Dataset tabs/windows can reload. It no longer creates one metadata JSON file per length configuration. `ReservingClassFolder` is the single filename-escaped reserving-class path folder using the shared reversible `_%XX_` rule, and `DatasetName` uses Details `Name` unless an aggregated output name is supplied. The stored DFM `data tab`.`input data triangle csv path` uses the triangle mode-qualified CSV naming, for example `Claim Counts--CWP@12@12@cum@dev.csv`. When source period is Monthly/Quarterly, save also emits aggregated vector CSV variants (Monthly -> Quarterly/Half-Year/Year, Quarterly -> Half-Year/Year) in the same reserving-class `datasets/` folder.
- DFM Audit Log loads the saved output dataset sidecar's canonical `audit_log` on tab activation and after save, then renders it newest first with the shared Dataset/BF/RS/DFM audit table and loading/error/empty states. This read-only view is not added to DFM method JSON or dirty-state snapshots.
- DFM pages include a bottom Save/Cancel row that uses the same DFM method persistence path as shell `File -> Save`. Save writes the current DFM method JSON plus Results CSV outputs; after an existing local method has been loaded, editing Details `Name` and using normal Save renames the DFM identity by writing the new method/cache files and deleting the previous method/cache files only after the new save succeeds. Save As creates a separate method file. Cancel closes the DFM window; when dirty, it uses the shared page-local close confirmation before discarding and restoring the last loaded/saved clean DFM method state. The modal makes the rest of the DFM page inert while open. Opening, loading, restoring, and externally reloading a DFM method apply programmatically and leave the tab clean, so asynchronous dataset refreshes do not create startup dirty flashes. The first real user edit marks the tab dirty and it stays dirty until Save or Cancel, even if the user manually reverts the edited value. Closing a dirty DFM shell tab through the tab close button or `Ctrl+W` uses the same discard confirmation before the shell removes the tab. When there are no unsaved changes, Save is disabled with the neutral visual style and Cancel remains clickable.
- DFM owns dirty-state and close-confirmation behavior for the full method page. The shared data-surface runtime supplies the Data tab but does not publish a separate Dataset dirty state or install an independent Dataset unload block, so a clean DFM method remains reloadable after its saved dimensions and input dataset are restored.
- While hosted in Project Instance, dirty DFM edits publish the current Results vector through `arcrho:dependency-source-preview` so open dependent Result Selection windows and matching Dataset Viewer windows can update from unsaved in-memory output values. DFM also consumes Dataset preview messages for its current Input Triangle, refreshing Data/Ratios/Results from the temporary matrix without marking the method dirty. Save, Cancel, or close-without-save publishes `arcrho:dependency-source-cleared`, which makes dependents drop the temporary values and reload from the persisted cache.
- DFM tabs support keyboard cycling with `Ctrl+PageUp` and `Ctrl+PageDown`, wrapping across Details, Data, Ratios, Results, Notes, Links, and Audit Log while using the same tab-change behavior as clicking the tab buttons. The shell and Project Instance hosts forward those shortcuts to the active DFM iframe so the keys work immediately after a DFM tab or floating DFM window opens, before the user clicks inside the frame.
- Inactive DFM tabs use the same pale hover fill as Bornhuetter Ferguson tabs, while active-tab fill and weight remain unchanged.
- DFM tab bar includes a right-aligned `Sync` button for the RPC bridge workflow. Clicking Sync prompts the user to save first when the current DFM tab is dirty, sends a backend `Function = DFM` request containing Details page fields plus `DataPath`, waits up to 8 seconds for the returned remote DFM JSON under `data/<ReservingClassFolder>/methods/tmp_rpc`, then shows a taller draggable, resizable `Review Changes & Select One Version` window with local/remote `last modified` timestamps from the JSON plus `ArcRho - Local`/`RPC - Remote` cards without showing JSON file paths. The comparison body has its own vertical scrollbar so the bottom of both diff cards remains reachable when content is taller than the window; wide snapshot grids and long notes still scroll inside their own preview boxes. Resizing the window also resizes the comparison cards, with snapshot content scrolling inside the cards when space is tight and the Notes preview expanding vertically from its 42px minimum height up to 300px when extra space is available, then scrolling inside the notes box instead of truncating long notes. The local version always appears on the left and the remote version always appears on the right, with the source label in the card's top-left corner framed by a dark blue border and light blue fill. The newer card displays a `NEW` seal and green-framed timestamp; the older card displays a red-framed timestamp. Each version card snapshots the excluded ratio triangle as a masked triangle with rectangular cells that compact for large matrices; cells with value `2` outside the inferred active diagonal are masked, while value-`2` cells inside the active diagonal are shown with a light yellow fill for missing data. The active diagonal is inferred from the latest row containing data and that row's last non-`2` cell. Commonly excluded ratio cells are dark grey, exclusions added in the new version are green only on the new card, and exclusions removed from the old version are red only on the old card. The green `Newly excluded` legend appears only on the new card, the red `No longer excluded` legend appears only on the old card, and a yellow `Missing inside triangle` legend appears only when those cells exist. Hovering a ratio cell shows the same origin/development labels used by the Ratios triangle table. The Average Formulas section renders a compact formula-row/development-column selection diff instead of a plain formula-name list, using dark grey for commonly selected cells, green only on the new card for newly selected cells, and red only on the old card for no-longer-selected cells. Notes snapshots compare the full `notes` text, highlight deleted old-version text with a red background, and highlight newly added new-version text with a green background. If the local version is newer, selecting the Local card shows a `Confirm` primary action; after one more app-styled RPC server write confirmation dialog, the backend sends `Function = SyncDFM` with the local method JSON path and waits for the bridge status result. Selecting `Keep Using Local` in non-write-back cases keeps the local JSON unchanged and deletes the remote RPC JSON without sending `Function = SyncDFM`; selecting the remote version shows a `Confirm` primary action, overwrites the local method JSON using the same row-compact DFM method JSON formatter as normal saves, then reloads the current DFM tab. If applying the remote version changes Input Triangle, Origin Length, or Development Length, DFM refreshes the dataset-dependent UI and immediately saves the recalculated local method JSON; if that final save fails, the DFM tab is marked dirty so the user can save before closing. After a version action is selected, the comparison window closes and a smaller same-style DFM Sync message box shows waiting status while the action is running; successful final messages become non-blocking notifications that disappear after 2 seconds, while warnings/errors stay visible and can close with `Esc` or by clicking outside. Equal `last modified` timestamps show `Local and remote are already in sync` with no primary action, and missing remote JSON is informational only.
- ArcBot Ask for Approval mode reuses the DFM RPC comparison window for proposed DFM edits. The current DFM tab is shown as `ArcRho - Current`, the agent proposal is shown as `ArcBot - Proposed`, and the same ratio, average formula, cell-note, and Notes diff previews are used. Choosing the proposed version applies it to the live DFM tab and saves the method JSON; choosing the current version or closing the review rejects the proposal without changing the DFM.
- Method Notes are deliberately excluded from DFM RPC and ArcBot method snapshots and comparisons because the output dataset sidecar is their only persisted owner. Ratio cell notes remain in `ratios tab.cell notes` and may still appear in method comparisons.
- DFM Sync displays local and remote `last modified` timestamps as local `M/D/YYYY HH:mm:ss` labels and treats matching ResQ wall-clock metadata as already in sync even when one JSON value includes an explicit `Z`/offset and the other does not.
- When a DFM method payload is applied from local lookup, RPC remote-to-local sync, or ArcBot JSON edit and the payload changes Input Triangle / Origin Length / Development Length, the embedded dataset layer reruns with the new Details inputs and refreshes header labels so Data/Ratios reflect the new JSON immediately without closing and reopening the DFM tab.

- DFM template save is triggered from shell `File -> Save as Template` (relabel of `Save As...`) only when DFM `Details` tab is active; the Details page button `Save as Template` is removed.
- DFM Details uses two frameless field groups without block headers: Project/Reserving Class/Name followed by Output Vector/Input Triangle and the length settings. ## Data/State/Caches
<!-- MANUAL:BEGIN -->
- Persists ratio selection/templates via DFM persistence modules.
- Tracks dirty flags and active DFM tab state.
- Caches eligible output-type names per project for typed `Output Vector` validation and enforces selection-only input.
- Selecting or changing a Details `Output Vector` auto-fills the Details `Name` field with the same string only while `Name` is still blank.
- Details `Output Vector` and `Input Triangle` use the shared picker name search, sorting, column filters, and picker preferences.
- During async project-scoped `Output Vector` option refresh/load (for example immediately after page refresh with prefilled Project), the picker does not clear the field while the `Output Vector` input is actively focused/being typed in.
- Reuses the host-neutral coordinator at `ui/shared/tabs/data/data_tab_controller.js` through `ui/method_pages/dfm/dfm_data_tab_adapter.js`, plus server project user preferences for project-specific shared `lastReservingClassPath` / Dataset defaults when no query/workflow values override the inputs.
- For new DFM pages, `Name`, `Output Vector`, and `Input Triangle` start empty instead of prefilled defaults.
- DFM method JSON identity/save naming uses the configured workspace projects folder (`paths.projects_dir`, default `projects`) with `<project>/data/<ReservingClassFolder>/methods/DFM@<Name>.json`; within a project/reserving-class pair, the DFM `Name` is the sole instance identity and must be unique. A single Name cannot represent multiple DFM instances with different period lengths or input triangles. The project is represented by the containing folder, and the reserving class is represented by the containing filename-escaped folder, not repeated in the JSON filename.
- DFM no longer creates, reads, updates, or deletes `dfm_method_names.json` or the browser-local cached DFM Name key; local method lookup uses only the current Details fields and the standard local DFM JSON path.
- DFM method JSON save/load persists the selected Results `Ratio Basis` dataset name (`ratio basis dataset`) so reopening the same DFM method restores the Ratio Basis selection automatically.
- DFM method JSON also persists Details `Name` (`name`), `Output Vector` (`output type`), `Input Triangle` (`input triangle`), Origin Length (`origin length`), and Development Length (`development length`) and restores them on local method load; users may manually change these Details inputs afterward and the changes follow normal DFM dirty/save behavior.
- DFM Data tab triangle values use the selected input triangle sidecar `number_format` and `decimal_places` when rendering, so the embedded triangle display matches the Dataset page formatting for that input triangle.
- DFM Origin Length and Development Length are independent method arguments. When Origin Length changes, Development Length is automatically adjusted only if the current pair breaks the required relationship (`Origin Length >= Development Length` and `Origin Length = Development Length * integer`); editing Development Length directly does not trigger an automatic rewrite.
- DFM Details Origin Length, Development Length, and Decimal Places plus Results Ultimate Ratio Decimals use compact custom spinner controls with the shared filled-caret dropdown/stepper arrow style. Details Decimal Places reuses the exact Dataset Data-tab decimal stepper classes and shared CSS, while opened length lists match the ArcRho control styling.
- DFM suppresses centered loading popups from both DFM method setting loads and the embedded Dataset Viewer loader; dataset refresh and reserving-class validation should report through normal status UI without blocking the DFM page with a modal loading window.
- When a DFM page is active, the shell Help menu includes `Open DFM JSON`, which opens the current DFM method JSON file from the resolved project/reserving-class/method path in Arcode.
- DFM Details `Decimal Places` (default `4`) controls ratio number formatting across the Ratios tab display (main ratio grid, summary/selected rows, and ratio chart labels/tooltips) and is persisted in DFM method JSON as `decimal places` so reopening the method restores the same Ratios formatting. In DFM context this control is handled only by DFM Ratios formatting logic, not by the shared Dataset Data-tab number-format controller.
- DFM Ratios chart threshold drags recompute threshold-owned exclusions for the opened chart column: unprotected points outside the upper/lower band or left of the grey vertical left-cutoff line are excluded, and those same unprotected points are restored when moved back inside the active threshold region. The grey vertical left-cutoff threshold starts at the plot area's left edge and can be dragged right. While a threshold line is being dragged, the chart keeps the current y-axis range stable and lets the axis resize after the drag finishes. Users can also drag the top or bottom y-axis label to set a custom max or min y-axis boundary; a red horizontal preview line shows the pending boundary while dragging, drag movement can expand the boundary beyond the current plot range, double-clicking either label resets that custom boundary, and closing the chart clears the custom zoom. While the chart is open, exclusions that existed when the chart opened plus exclusions made manually by table-cell or chart-point click are protected from threshold-line actions; this session memory is cleared when the chart closes. The chart header includes `Included All Ratios`, which clears persisted ratio exclusions for the current chart column.
- DFM Ratios tracks Ratios-tab mouse-driven changes in a per-tab temporary JSON undo session under the desktop temp folder. `Ctrl+Z` / Edit `Undo Ratio Change` restores the previous Ratios state, `Ctrl+Y` / Edit `Redo Ratio Change` reapplies undone state, and both stacks are limited to 20 steps. One cell-drag gesture or toolbar/menu command is one undo step; if a mouse gesture loses its normal mouseup event, DFM finalizes that pending step before the next action so separate later cell exclusions do not merge into one undo/redo step. Closing the DFM tab clears that tab's temporary undo JSON copies.
- In the DFM Ratios tab, Select mode lets users click a main-table column label to highlight that table's entire column, or click a row label in the main ratio, average-formula, or selected-summary table to highlight that table's entire row. In Edit mode, clicking an origin row label in the ratio triangle excludes all valid ratio cells in that origin row; when every valid ratio in the row is already excluded, clicking the label includes the whole row again. Clicking an average-formula row label in Edit mode selects that formula row for every rendered development column.
- DFM dirty-state tracking compares the current editable method state with the last loaded/saved clean snapshot. If Ratios or Notes edits are undone so the method matches the stored DFM JSON again, the DFM tab returns to clean instead of staying dirty just because an edit occurred earlier.
- DFM records the post-startup Details/Data/Ratios/Results/Notes state as clean, then replaces that clean snapshot if a saved local method is loaded, so opening a new DFM tab does not show unsaved changes before the user edits anything. Links remains a derived view of Ratios inputs and adds no separate dirty-state snapshot.
- DFM method JSON also persists the Results tab `Ultimate Ratio Decimals` control as `ultimate ratio decimal places` (default `2`) so reopening the method restores `Ultimate Ratio` percentage formatting independently of Ratios-page decimal formatting.
- DFM Ratios supports cell notes on both the main ratio triangle and the average-formula summary table. Right-clicking a cell opens `Add Cell Notes` / `Edit Cell Notes`; cells with notes show a small yellow corner marker, hovering the cell opens the floating note box, edits made in that box mark the DFM dirty, and the note box's `Clear` button removes the note. Notes are saved in the local DFM method JSON under `ratios tab`.`cell notes`, keyed by the visible row and development-column labels; older index-keyed notes still load and migrate on the next save. DFM RPC bridge imports ResQ `CellNotes` string output into this same JSON shape for remote-to-local sync and shows cell-note differences in the sync review window; confirmed local-to-remote write-back does not overwrite ResQ cell notes because ResQ currently exposes them to the bridge as read-only string output.
- DFM method JSON now uses a canonical GUI-tab grouped shape (`json format = arcrho-dfm-method-by-tab-v1`) with `details tab`, `data tab`, `ratios tab`, `results tab`, and `method metadata` sections. Method notes live only in the output dataset sidecar's top-level `notes` field. The grouped JSON persists the ratio selection matrix under `ratios tab`.`ratio triangle`.`excluded`, ratio-tooltip labels, Results output, GUI save time, and read-analysis snapshots for input data triangle values, ratio values, average formula values, plus the input triangle CSV path; input-data and ratio snapshots are rounded to 4 decimals, while average formula values are rounded to 6 decimals so formula-driven User Entry values can display an accurate fourth decimal. Data-tab `development labels` use raw Data headers such as `2m`, while Ratios-tab ratio-triangle `development labels` use GUI-display ratio headers such as `(1) 2-14`. Analysis arrays trim trailing `null` cells from each row while preserving internal `null` cells, and `excluded` rows are clipped to the corresponding `ratio values` row length so non-value columns such as the trailing Ult mask column are not persisted. These snapshots are ignored when restoring editable method selections. The DFM method JSON formatter writes any 2D array as one compact child row per JSON line, including extra or nested 2D arrays. ArcBot active-context temp JSON uses the same grouped method shape and host-applied edits remain grouped. See `docs/ui/dfm_json_format.md` for the current DFM JSON format notes.
- DFM Ratios `Copy Ratio Patterns` stores the same compact row shape used by method JSON, and `Apply Ratio Patterns` validates against that compact shape rather than the full displayed grid width that includes non-value trailing mask columns.
- Opening a DFM page refreshes data-dependent tab content immediately: the dataset loader renders the Data tab, while DFM renders Ratios and Results even when those inner tabs are not currently visible. Dataset updates and DFM method loads also refresh Ratios and Results regardless of visibility, so tab pop-outs and later tab navigation start with current content.
- Right-clicking a DFM page tab temporarily moves that live tab page into a draggable, resizable floating window inside the DFM page, using the shared tab pop-out helper also used by Dataset. The floated tab keeps its original controls, event handlers, dirty-state behavior, and data state because the actual tab DOM is moved rather than cloned; the floating titlebar uses shell-style minimize, maximize, and close/dock buttons, double-click titlebar maximize/restore, drag-from-maximized restore to the previous window size, and resize handles on all edges and corners. Pop-out and dock use short fade/scale transitions. Closing the floating window, right-clicking its titlebar, or right-clicking the grey popped tab button docks the tab back into the normal tab area.
- DFM method/template JSON persists average formula settings under a columnar `average formulas` object with `label`, `custom average formula settings`, `selected`, `values`, and optional User Entry `inputs`; `summary rows`, `summary hidden`, and `summary order` are not used. `label` is the persistent formula identity and runtime-only `id` values are generated after load. The average formula table order follows the `average formulas.label` sequence, and dragging rows updates the actual formula metadata so the UI order and saved formula order stay synchronized. The average formula table delete action is disabled when only one row remains, so the table always keeps at least one row. The selected-summary area shows `Selected`, `Cumulative`, and `% Developed`; `% Developed` is calculated as `1 / Cumulative` for each development period and displayed as a one-decimal percentage.
- The User Entry formula bar in the Ratios summary table is available in both Select and Edit modes. In Select mode, the active highlighted User Entry cell drives the displayed formula and users can edit or use the Excel actions without switching modes. Formula and direct User Entry validation errors use a portal-rendered tooltip anchored to the formula bar instead of native alert dialogs. The tooltip is positioned above the bar when space permits and uses a below-bar fallback near the top of the viewport, overlaying the Ratios surface without moving the tables; other Ratios command errors use the in-page Ratios notice. Invalid formula commits preserve the draft, caret selection, and edit session for immediate correction; invalid direct entries stay editable after Enter without trapping focus when the user moves away. Excel validation is bounded to 30 seconds so a stalled workbook request releases the formula bar. Excel address column letters are automatically normalized to uppercase while typing and before persistence. The formula bar stays anchored to the visible ratio-grid viewport while users scroll horizontally, and remeasures that viewport when the app window or DFM frame is resized so the row label, formula text, and Excel action buttons remain reachable.

The highlight is recomputed when User Entry formulas are saved and when summary values recalculate, so it follows changed formula references and source-cell updates.
- The User Entry formula bar accepts Excel-style array constants for horizontal spill entry: `={1,2,3}` or `=TRANSPOSE({1;2;3})`. Spill values beyond the visible summary-table range are ignored, the full array formula is kept only in the first filled cell, following cells store the resulting values, and all filled columns are selected from the same User Entry row. The filled array receives the same blue outer border and light glow as an external Excel range without changing its interior cell fills.
- Right-clicking anywhere in the DFM Ratios selected-summary table opens a selected-summary context menu with `Show Percentage Developed Curve`. The floating `% Developed Curve` window reads the rendered `% Developed` row and places actual data points at the matching Data-tab development-month labels for each ratio column, so a ratio period like `(1) 11-23` plots at month 11. The curve starts at month 1 and `0%`, then interpolates monthly values to the first actual point. Each displayed ratio column owns the segment ending at that column's actual point; the `Curve Type By Segment` section presents those segments in a horizontally scrollable two-row table with `Period` labels and in-cell `Curve Type` dropdowns. Segment curve choices default to linear interpolation and include smooth, step, exponential, logarithmic, and power choices. The window also has an optional Prior Project input with the shared project tree picker; selecting a prior project does not change the active DFM project, and clicking `Add Curve` fetches the same Reserving Class path and DFM method name from that project and overlays its `% Developed` curve. If the matching DFM method cannot be found or cannot produce curve points, the window shows the error and leaves the current graph unchanged. The curve window does not persist display-only chart settings in DFM method JSON.
- The DFM Ratios average formula table right-click menu includes `Plot Table Data`, which opens a draggable and resizable floating plot window. The plot reads the current rendered summary table values, charts each average formula row plus the current `Selected` row across the current development-period columns, and shows a row legend. The plot window toolbar includes zoom, hand-drag, pencil tools, and a graph-mode toggle; `Ratios` plots the rendered summary values, while `% Dev` treats each row as the selected ratio row, computes its right-to-left cumulative product, and plots `1 / cumulative` as percent developed for each column. Zoom mode changes the chart cursor to zoom-in, dragging a chart region zooms into that selected area, a single chart click resets to the original full view, hand-drag mode pans the full chart view with pointer-captured dragging, pencil mode lets users click an average-formula point to make that formula the selected value for the clicked development period, and `Esc` deselects the active tool. The plot legend follows the Dataset Viewer chart legend behavior: clicking a legend label row or checkbox hides/shows that line, `Select All` controls all lines, individual toggles keep at least one line visible, and right-clicking a legend row isolates that line or restores all lines when it is already isolated.
- When loading DFM JSON from RPC/local method payloads, DFM reconstructs runtime average formula rows from the `average formulas` object. Supported inferred labels are `Volume - all`, `Volume - <n>`, `Simple - all`, `Simple - <n>`, and the same labels with `Ex hi/lo` or `Ex hi/lo x<n>` suffixes; unresolved labels are skipped.
- DFM template files use `.arc-dfm` extension only (`DFM_Template@<Project>@<ReservingClass>.arc-dfm`); legacy `.arcdfm` suffix is not accepted.

If found, it auto-loads the file and reports the loaded file path in the status bar. If not found, it reports a yellow status-bar warning (via shell status `tone=warn`) with the exact text `This method object has not been created yet, changes will be saved to a new container.` The lookup does not wait for `Input Triangle` / `Output Vector` / period lengths.

When the page is dirty, DFM does not overwrite in-memory edits and posts a warning so the user can save or reload deliberately.
