## External Interfaces
<!-- MANUAL:BEGIN -->
- Opened by shell as a `project_instance` iframe tab after Project Settings posts `arcrho:open-project-instance`.
- Calls shared dataset-types and reserving-class picker helpers.
- Embeds the same lazy reserving-class picker body used by Dataset/DFM/Workflow, so the project instance left panel loads the same hierarchy, filters, hidden-path preferences, Shortcut section, favorites, and user-defined favorite folders.
- The embedded reserving-class path tree uses tight horizontal padding with a small left inset and does not reserve two-sided scrollbar gutters, so more path text fits in the left panel. Tree rows keep their depth-based left indentation while favorite-star actions in Shortcut and All Paths share one right-edge vertical line. Hovering a tree or Shortcut label shows its full path in a compact app-styled tooltip that wraps within the viewport instead of using the browser-native tooltip.
- Project instance loading shows one centered page-level loading card with the same blue sweep spinner style used by Dataset loading while the reserving-class path tree and dataset table load.
- Embeds the existing Dataset Viewer page in draggable in-tab windows.
- Double-clicking a dataset that already has an open or hidden floating window activates or restores the existing window instead of creating a duplicate for the same selected path and dataset.
- New floating dataset windows default to about 80% of the project-instance frame and reuse the most recent floating dataset window size for subsequent dataset windows in the same project instance page.
- Floating Dataset, DFM, Result Selection, Bornhuetter Ferguson, and Cape Cod window titlebars highlight the active top window. Titlebars show only the dataset/method name when the window belongs to the currently selected reserving-class path, and fall back to the full reserving-class path plus dataset/method name when the left-panel selection moves to a different path; hovering the titlebar text does not show a native browser tooltip. Minimized toolbar tabs use the dataset/method name without method-type prefixes.
- Floating dataset window titlebars include shell-matching minimize, maximize/restore, and close icon buttons; clicking the minimize button or right-clicking the titlebar sends the window into the toolbar hidden-tab strip.
- Dataset viewer windows follow the shell's existing Windows 11 frame flag, using rounded frame corners on Windows 11 and square corners otherwise.
- Dataset viewer windows can be resized from all corners and edges, with the southeast handle using the same dotted resize glyph as the main shell and shell floating tabs.
- Double-clicking a floating dataset window titlebar toggles maximize/restore within the project-instance frame; dragging a maximized titlebar restores the prior size under the pointer before moving.
- Dataset viewer windows are clamped below the project-instance toolbar; they may be dragged partially off the left, right, or bottom edge as long as a side grab area and the titlebar remain reachable.
- `Ctrl+W` closes the active floating dataset window, including when keyboard focus is inside the embedded Dataset Viewer iframe or when the shell/Electron close-tab shortcut reaches the parent shell first; the project instance tab closes only when no floating dataset window can consume the shortcut.
- The toolbar includes a hidden-tab collection area to the right of the selected path; hidden windows appear as large-radius minimized tabs on the toolbar that show dataset names only plus a styled hover tooltip with the full window title. Each minimized tab uses a centered inline SVG close icon, and hovering or clicking the hidden-tabs button opens a wider content-fitting dropdown that lists full hidden window titles with a one-second hover grace period, per-item close controls, Resume all tabs, Close all tabs, a centered inline SVG close icon that dismisses the dropdown itself, and a matching restore animation that starts from the matching minimized tab. The hidden-tabs button and its dropdown are hidden entirely while no window is hidden, so the toolbar never shows a `0 hidden` control or an empty-state menu.
- Dataset viewer windows add a transparent parent-page drag shield during move/resize so embedded iframes do not interrupt fast mouse movement.
- The project instance toolbar is compact, shows only the currently selected reserving-class path, omits the duplicate selected path above the tree, and sizes the path label to its content with a capped width so minimized toolbar tabs get the remaining space.
- The selected reserving-class path in the toolbar is interactive: each level renders as a compact rounded segment, and clicking a segment opens a small styled picker below it with alternate values for that level from the shared reserving-class hierarchy. The picker focuses a type-to-search field that filters the loaded values without reloading the hierarchy; Arrow keys move between the search field and visible results, and Enter chooses the sole matching value. Choosing a value preserves the existing lower-level suffix when that branch exists, otherwise it selects the first valid descendant path. Right-clicking anywhere on the path highlights the full path and opens Copy/Paste actions. Paste accepts only a valid leaf path from the loaded reserving-class hierarchy, selects that canonical path, collapses the old divergent branch, expands the pasted path, keeps its selected-row highlight visible, and scrolls it into view.
- The left and right panel title bars are omitted so the reserving-class tree and dataset table start directly below the toolbar. The embedded reserving-class tree starts from the full project path hierarchy instead of applying a previously saved reserving-class picker filter; the All Paths header exposes a Collapse Bottom Level control before the Hidden Paths, Filter, and Preferences controls. It collapses the deepest currently expanded folder level in one click, while the remaining controls let users intentionally narrow or configure the tree in place.
- The dataset table has a compact transparent toolbar above the scroll area. Its default Normal view is driven by cached dataset instances from the selected reserving-class path: `Name` is the instance name, `Dataset Type Name` is the stored dataset type, `Category` is the indexed `dataset_category`, and multiple instance names can share the same dataset type. The cached dataset count in the toolbar reflects visible instance rows after table filters, while the refresh button sits on the right side of the toolbar.
- The toolbar also has a Temporary view icon with a styled hover/focus tooltip that explicitly states whether Temporary view is enabled or disabled and describes only the active mode. Temporary view lists every Dataset Type marked `Generated`, whether or not it has been created for the selected path. Its Status column uses a green check when the dataset is already listed in the selected-path `index.json` and a gray check when it is not. Type-derived fields remain available; cache-only metadata such as Method Type, Last Modified, Created, and User is blank. Temporary rows can only be opened in a read-only Dataset Viewer window. A gray-status row's context menu also provides `Make Permanent`, which runs the same canonical generated-dataset flow as Add Dataset to create the CSV cache and sidecar before rebuilding `index.json`.
- Normal table column filters, except for the icon-only `Status` column, show in a framed `Filter:` section in the dataset toolbar. When no filters are active it reads `Filter: None`; active filters appear as compact column-name chips, and hovering or clicking a chip opens the same filter dropdown used by the active table-header filter button so users can review or change the selected values. Every filter menu includes a Type to search field that narrows only its displayed values; `All` still selects the full column's values. Dragging a table column header or grouped-column chip into the filter frame adds that column as a neutral `All` filter chip and opens its filter menu. Selecting `All` keeps a neutral chip in the filter frame without the blue active-filter treatment, and dragging a filter chip out of the frame clears that column filter.
- The dataset table `Method Type` and `Status` columns, including their filter options, read method metadata from the selected reserving-class folder's cached `index.json` `files` entries, matching rows by instance `name`; datasets missing from the cache display `None` and a green updated status. `Status` shows a green check for sidecar `status: 0` and a yellow warning when a method-backed output has `status: 2` because one of its recorded input precedents was updated later than the method output.
- Double-clicking a dataset row whose `Method Type` is `DFM`, or choosing `View` from its row context menu, opens the DFM method tab by default. Rows whose `Method Type` is `Result Selection`, `Bornhuetter Ferguson`, or `Cape Cod` open that method window directly on its Method tab; method routing is independent of whether the indexed output format is Vector or Triangle. The same row context menu shows `Show as vector` immediately after `View` for DFM, Result Selection, Bornhuetter Ferguson, and Cape Cod vector rows, and shows `View as triangle` for triangle rows. These format-specific actions always open the saved output in a normal Dataset Viewer window without showing method details. Method-backed vectors label the single value column `Ultimate` instead of using the first development-period label. Cached dataset rows open read-only unless their indexed `source_kind` is `input`.
- The dataset table `Formula`, `Last Modified`, `Created`, and `User` columns read from the selected reserving-class folder's cached `.csv`/`.json` file metadata. `Last Modified` comes from sidecar JSON metadata such as `updated_at`/`modified` when present, with filesystem modified time only as a fallback; `Created` comes from sidecar JSON metadata such as `created_at`/`created` without using filesystem creation time; timezone-aware sidecar timestamps, including UTC `Z` values, are normalized to local display time before they are written into the cached index. Formula values come from sidecar/index metadata, and user values come from the sidecar `user`/`modified_by` Windows-login fields when present.
- Adding a dataset from the cached-dataset table's add picker refreshes the cached list, highlights the newly added dataset row, and selects it in place instead of opening a floating Dataset Viewer window.
- Double-clicking a dataset table row whose `Method Type` is `DFM` opens a floating DFM window inside the Project Instance frame on its Ratios page, initialized with the current project, selected reserving-class path, and dataset name instead of opening the in-tab Dataset Viewer window or a main shell tab; it also records the selected DFM method/output name in project-user `dfmObject` preferences.
- Floating Dataset and DFM windows inside Project Instance follow the main shell corner convention: 6px by default and 8px when the page is running with the Windows 11 frame style.
- Floating Dataset and DFM windows mirror standalone save/dirty behavior: dirty-state messages show a dirty dot on the floating titlebar and minimized tab, closing a dirty window asks for confirmation, confirming discard closes the floating window, and shell Save plus Ctrl+S routes to the active floating Dataset or DFM window. DFM windows also support Save As/Ctrl+Shift+S through the active floating DFM window.
- Floating DFM windows publish their active DFM state to the shell and forward standalone DFM commands, so shell Edit/Help menu actions, ratio hotkeys including the Ctrl+E Select/Edit toggle, DFM JSON opening, Notes file-link context-menu actions including popped DFM tab surfaces, and macro context/apply requests target the active Project Instance DFM window the same way they target a standalone DFM tab. Ctrl+E is forwarded even before the nested DFM iframe receives keyboard focus. When the active Ratios window is in Select mode with a highlighted range, Project Instance also forwards Enter and Arrow-key navigation with Shift/Ctrl/Cmd modifiers, including when focus is on the surrounding DFM window surface. Clicking back into the reserving-class tree or dataset table clears the active nested window and returns shell context to the Project Instance reserving-class level.
- Project Instance relays `arcrho:calculated-datasets-updated` reports between nested Dataset windows and the shell, so open nested calculated dataset windows can auto-refresh after an upstream component save.
- Project Instance relays `arcrho:dependency-source-preview` and `arcrho:dependency-source-cleared` messages between nested Dataset, DFM, Result Selection, Bornhuetter Ferguson, Cape Cod, and Berquist Sherman windows, including DFM windows that use the shared Dataset layer. This lets a dirty upstream source feed temporary values to an open dependent method or matching Dataset Viewer window. For dirty sources that feed app-calculated Dataset Types, Project Instance also requests an in-memory calculated preview and relays the downstream calculated values, then tells dependents to reload the source from disk when the upstream source is saved, canceled, or closed without saving.
- Project Instance handles dependency open requests from nested Dataset Details pages, opening or activating the clicked dependent as a floating Dataset window using the source window's reserving-class path even if the left-panel selection has moved; method-backed Formula component chips open the related DFM, Result Selection, Bornhuetter Ferguson, or Cape Cod method window instead.
- Project Instance publishes `arcrho:project-instance-state` snapshots to the shell when the selected path or nested floating Dataset/DFM/Result Selection/Bornhuetter Ferguson/Cape Cod/Berquist Sherman windows change. Berquist Sherman snapshots use `kind: "berquist_sherman"` plus `bsTab` and `bsVariant`; the page reports tab changes with `arcrho:berquist-sherman-tab-changed`. A successful first B&S save rekeys the same floating window to the saved output Name, and restored B&S windows reopen against their own saved reserving-class path. The snapshot also includes selected path, nested window name/title, hidden/active/maximized/dirty flags, other method subtabs, and restore rectangles so Browsing History can restore Project Instance pages after Clear Cache & Reload without turning method windows into dataset viewers.
- Deleting cached files from the row context menu redraws the table from the index the delete response already carries instead of issuing a follow-up `/datasets/cached` read, and suppresses the index watcher for the write it just made so the `Index updated` prompt does not appear for the user's own delete. If that response has no usable index, the table falls back to the normal reload.
- Confirming a delete shows the same page loading overlay, spinner, and elapsed counter the project load uses, titled `Deleting cached files` and naming the dataset or the selected count. The server removes the files and rebuilds `index.json` in one request that reports no intermediate progress, so the indicator is deliberately indeterminate; the elapsed counter is what tells the user a slow mapped drive is still working. The overlay clears whether the delete succeeds or fails, and cancelling the confirmation never opens it. Any Project Instance action can claim the shared overlay this way by passing a title and message to `beginPageLoading`; tasks that pass none keep the project-load wording, and finishing a labelled task restores the wording of whatever is still loading.
- The dataset toolbar includes a refresh icon button. Clicking it reloads the right-panel dataset table from disk via `/datasets/cached` and restores the table scroll position plus selected rows afterward. The reload does not ask the server to force a rebuild: the lookup lists the selected reserving class's `datasets/`, `methods/`, and `sidecars/` folders and rebuilds `index.json` only when that listing no longer matches the persisted folder signature, so an unchanged reserving class reloads without reading any sidecar or method file. A user-initiated reload uses its own in-flight request key so it never joins a background read that started earlier. In Temporary view, the same action refreshes selected-path index membership; the temporary-view cache itself never creates an `index.json` entry or triggers an index rebuild. In Electron, Project Instance watches the selected reserving-class data folder for `index.json` changes; when the index changes on disk, the toolbar shows an `Index updated` button so users can reload the table deliberately. Nested Dataset, DFM, Result Selection, Bornhuetter Ferguson, Cape Cod, and B&S saves also request the same selected-path table refresh. Unsaved Dataset grid edits and pasted Excel references stay in the in-memory dirty/preview flow and do not reload this disk-backed table.
- If the server can scan the selected dataset folder but cannot persist its derived `index.json` on the mapped drive, Project Instance still renders the scanned rows and shows `Warning: index not saved` in the table toolbar. The full filesystem warning remains available as the toolbar's accessible label, and a later successful persisted lookup clears the warning.
- The dataset toolbar includes a gear button for workspace-global default number formats. It opens a draggable floating editor that shows the resolved `config/dataset_number_formats.json` path, fallback format, filterable Dataset Type Name override table, and add/remove controls. Save validates complete unique rows, reports load/save failures in the window, and rejects stale revisions instead of overwriting changes made in another window. The saved type-level defaults apply to subsequently generated engine and app-calculated dataset sidecars across every project and reserving-class path, including instances whose Name differs from their Dataset Type Name; existing sidecar display settings are not rewritten. Opening a generated dataset from Temporary view resolves the same saved fallback/override by Dataset Type Name when no sidecar exists, while keeping the viewer read-only and leaving the temporary cache unindexed. That resolution happens during the Dataset Viewer boot, before the first run paints the grid, so a temporary open shows the configured format immediately instead of only after a parameter such as Origin Length changes.
- The dataset toolbar includes a visible grouping drop zone. When no grouping is active it prompts users to drag a column header there; when grouping is active a compact `+` icon appears to the right of grouped chips and shows the drag-to-group hint in a styled hover tooltip. Grouped columns appear as draggable chips, disappear from the main table while grouped, and can be reordered inside the grouping drop zone with an insertion marker. Project Instance supports nested grouping for every available dataset table column rather than stopping at two subgroup levels. Dragging a group chip over a table header shows the same blue insertion line as column reorder and restores the column at that drop location; dropping it over table body space removes grouping and restores the saved column position. Right-clicking dataset table header cells still opens a context menu with `Group by ...` choices for `Data Format` and `Category` plus a placeholder `Reset Columns` option; grouping creates nested compact collapsible group headers inside the same table instead of rendering separate grouped tables. Top-level group headers show record counts as low-contrast circular badges, while subgroup headers omit counts. Every table header still supports drag-to-reorder column labels and drag-to-resize header edges, and all columns except `Status` support per-column filter dropdowns; dragging a column shows a full-height blue insertion line at the target location and a framed drag preview with the column label. Per-column filters match the Project Settings Dataset Types table: no checked values means the filter is not applied, checked values narrow results, and selecting all values is treated as unfiltered while keeping that column as a neutral filter chip when the user explicitly chose it. Each filter dropdown includes an `All` checkbox that clears selected values and resets that column filter; right-clicking a value row selects every value except the clicked one. Resizing a column changes only that column and updates the total table width instead of redistributing space across other columns.
- Dataset table default column order, grouping, filters, sort state, and widths come from the built-in Project Instance preference snapshot. Manual resize can still expand or shrink a column, and double-clicking a resize handle restores that column to its built-in default width.
- Right-clicking a dataset table group header opens `Collapse all` and `Expand all` actions for group headers at the same grouping level as the clicked header.
- Clicking a dataset table row keeps that exact row highlighted, including rows whose dataset names differ only by special characters. Clicking the only highlighted row again removes it from the selection, while clicking one row inside a multi-selection narrows selection to that row. `Ctrl`/`Cmd` click toggles individual rows, `Shift` click selects the visible range from the last anchor row, Up/Down arrow keys move a focused row selection to the previous or next visible dataset, and Enter opens the focused selected dataset. The app status bar shows the selected item count when more than one row is selected. Right-clicking a row opens a row menu that can view the right-clicked dataset or first highlighted dataset, shows `Show as vector` for DFM, Result Selection, Bornhuetter Ferguson, and Cape Cod vector rows, shows `View as triangle` for triangle rows, exposes an Add submenu, and can delete cached files related to all highlighted datasets after a custom confirmation dialog. Add > Dataset opens the shared dataset picker window (`ui/shared/components/pickers/dataset_name_picker.js`) for the current project, with Dataset Type Name search, sorting, column filters, grouping, and shared picker preferences. Choosing a generated type sends an ArcRhoTri refresh request to the data engine; generated dataset types are one-instance-per-reserving-class path, so choosing one that already exists in the selected path shows a custom message box instead of issuing another request. Choosing a non-generated dataset type opens a fresh Dataset Viewer draft on the Details page with `Name` defaulted to the dataset type name, initial `number_format` set to `0,000`, default period lengths set to 12, and an editable zero-filled Data-tab placeholder whose labels come from the project settings. Triangle placeholders use the standard triangle shape and Vector placeholders use a one-column vector shape so users can paste from Excel or type values into the available cells. The draft window opens with Save enabled, so the new dataset can be created straight from the prefilled draft without editing a cell first. Users may rename the instance before saving, and the draft page blocks duplicate instance names in the selected path. Add > DFM opens a fresh floating DFM window on Details with project/path and default Origin Length, Development Length, and Decimal Places; Name and Output Vector remain blank, and the right-clicked dataset is passed as Input Triangle. Add > Result Selection opens a fresh floating Result Selection window for a vector dataset whose Method Type is `None`, prefilled with project/path, output vector name, output type, and category. Add > Bornhuetter Ferguson opens a fresh BF method window for a vector dataset whose Method Type is `None`, prefilled with project/path, output vector name, output type, and category. Add > Cape Cod opens a fresh Cape Cod method window the same way for a vector dataset whose Method Type is `None`. For an annual Triangle row whose Method Type is `None`, Add provides direct `B&S Settlement Rate Adjustment` and `B&S Case Reserve Adequacy Adjustment` commands. Each opens the shared B&S method page with the selected row as its initial paid-claims triangle and the chosen canonical variant.
- Project Instance context-menu submenus include a small pointer bridge between the parent menu item and nested menu so the nested choices remain open during normal diagonal mouse movement.
- When a reserving-class path is selected, Help > Reveal in File Explorer resolves that path's cached `folder_paths.data` folder and asks the shell's desktop open-path bridge to open it in File Explorer.
- Help > Open Dataset JSON File resolves the active floating DFM, Result Selection, Bornhuetter Ferguson, or Cape Cod window to its `methods/*.json` method file and opens it in Arcode through the shell desktop bridge. Help > Open Dataset Sidecar resolves the active floating Dataset, DFM, Result Selection, Bornhuetter Ferguson, or Cape Cod window to its `sidecars/<DatasetName>.json` file and opens it the same way.
- When the selected reserving-class path has no cached datasets, right-clicking the empty table area or `No dataset found in this path.` label opens the same Add submenu so Add > Dataset can launch the existing dataset-type picker.
- Dataset table renders precompute row cell values, filter option lists, and active filter selections once per render before grouping and sorting, keeping filter/group changes responsive on larger project dataset lists.
- Dataset table headers remain opaque while scrolling, so row contents do not show through sticky header cells.
- Dataset table body cells wrap long text and clamp display to two lines per cell, without row-hover fill or browser tooltips over row values.
- Clicking a dataset table column label cycles that column through ascending sort, descending sort, and no active sort, with the third click returning rows to the default cached order and removing the sort indicator. `Last Modified` and `Created` sort by their cached numeric timestamp values instead of their formatted display strings.
- The left reserving-class panel defaults to 400px and has a draggable splitter constrained to 200px-600px; collapse/expand is animated, live drag updates are frame-throttled with transitions disabled for responsiveness, dragging the panel to 200px or smaller collapses it, and double-clicking the splitter toggles collapse/expand.
- Dependency-source `cleared` messages may carry a `propagationJobId` from a save that enqueued an Engine dependent-propagation job. Project Instance then defers relaying the clear (and clearing its calculated preview fan-out targets) until the job's terminal status, so downstream open windows keep their live-preview values instead of snapping back to stale persisted values; it brackets the wait with `arcrho:dependent-propagation-started`/`-finished` broadcasts so those windows' change watches pause for the job. A failed job still releases the clear so windows reload the honest Review Needed state. Save flows can fire more than one clean transition, and only the first cleared message carries the job id, so while a source has a deferral pending Project Instance swallows job-less cleared duplicates for that same source — relaying one would clear downstream previews early and reload pre-walk stale values that never recover.

## Data/State/Caches
<!-- MANUAL:BEGIN -->
- Uses the shell-persisted project name/folder/table path as tab inputs.
- Loads the project's last selected reserving-class path from project-user preferences when the tab opens; if no last path exists, it selects the first Shortcut item when available, otherwise leaving the path empty.
- Keeps the selected reserving-class path in page memory, saves user selections back to project-user preferences, and passes it into new floating Dataset Viewer and DFM windows. Opening a floating DFM window also updates the shared project-user DFM object defaults with the selected method/output name without waiting for the DFM method to be saved.
- Saves the right-panel dataset table layout in the same project-user preferences JSON under `projectInstance.datasetTable`, including column order, manual column widths, filterable column selections, grouping fields, collapsed group rows, and sort state. Cleared/no-op filters and the non-filterable `Status` column are saved as empty arrays so stale saved filter values do not return after reload. Normal view is always the default; Temporary view is session-only and is not saved as a table preference, although its retained CSV cache persists on disk. When the current project/user has no saved `projectInstance` object yet, the preference API supplies the built-in default `projectInstance` settings before the page loads, unless `ARCRHO_PROJECT_INSTANCE_DEFAULT_PREFS_PATH` points to an override JSON. If preference loading stalls during startup, Project Instance falls back to the default table layout so the page can finish opening.
- Opening a Temporary-view dataset reuses a valid canonical cache read-only when available; otherwise it writes generated or derived CSV output to `data/<ReservingClassFolder>/datasets/.temporary-view/`. The retained temporary-view cache persists after Temporary view closes, never creates a sidecar, and never creates an `index.json` entry or triggers an index rebuild. The Temporary Status check is green when the dataset is already listed in the selected-path `index.json` and gray when it is not. Temporary windows are excluded from Project Instance restore snapshots.
- Changing the selected reserving-class path refreshes the server-side `index.json` lookup for logical cached dataset instances, stored dataset type names, minimal table metadata, and method types for the selected reserving-class data folder while preserving existing table column filters and grouping.
- Method type and review-status lookup are derived from the same selected-path `index.json` payload as cached dataset names and metadata, so Project Instance does not issue a second method-index request during path selection.
- Floating DFM window dirty state is tracked by DFM iframe `arcrho:dfm-dirty` messages keyed by the DFM `inst`, with iframe-source fallback during startup state sync; Project Instance sends aggregate `arcrho:project-instance-dirty` messages to the shell and consumes shell-level DFM save commands before forwarding them to the active floating DFM iframe. New floating windows start clean until their iframe reports an actual edit state.
- Floating DFM window active state is tracked by DFM iframe edit/history/tab messages and reported to the shell with `arcrho:project-instance-dfm-active-state`; Project Instance forwards `arcrho:assistant-context-request`, `arcrho:dfm-apply-method-payload`, `arcrho:assistant-dfm-edit-approval`, and nested `arcrho:open-path` requests so macros, ArcBot approval review, and file-open actions can use the same active-context and desktop-open contracts for standalone and nested DFM pages. ArcBot app context uses the top active non-minimized floating Dataset/DFM window as the primary Project Instance context and includes lightweight metadata for the other visible nested windows so ArcBot knows they are open without eagerly loading every window's data. The App Context hover text shows the Project, Segment, active nested tab name, table-consistent Method Type, and visible nested-tab count. Minimized nested windows are excluded from ArcBot app context.
- Nested Dataset, DFM, Result Selection, Bornhuetter Ferguson, and Cape Cod windows render dirty-close confirmation inside their own page iframe through the shared close-confirm component; Project Instance only invokes each child page's close hook and does not relay or render the modal.
- Project Instance handles the shell `arcrho:automation-open-dataset` message for Python UI automation. The command opens or activates a floating Dataset Viewer window for the current selected reserving-class path, or opens the matching DFM/Result Selection/Bornhuetter Ferguson/Cape Cod method window when callers pass `openMethod` with a method type, then returns the project name, selected path, dataset name, window id, title, and current window properties to the command bridge.
- Project Instance handles the shell `arcrho:automation-project-instance-refresh-datasets` message for Python UI automation. The command reloads the selected reserving-class dataset table from disk with the same behavior as the refresh toolbar button, then returns the project name, selected path, and `refreshed` status to the command bridge.
- Project Instance handles the shell `arcrho:automation-window-command` message for Python UI automation window objects. It can return properties for the active or addressed floating window and perform activate/focus, maximize, restore, minimize, and close actions through the same window manager used by the Project Instance titlebar controls.
- Project Instance consumes `arcrho:project-instance-restore-state` from the shell after the page boots. Restore selects the saved reserving-class path, recreates saved nested Dataset, DFM, Result Selection, Bornhuetter Ferguson, Cape Cod, and B&S windows, reapplies window rectangles/maximized/hidden state, restores saved method subtabs, and raises the saved active visible window.
- Dataset table refresh is available from the toolbar, from the `Index updated` prompt shown after watched `index.json` changes, and after nested Dataset, DFM, Result Selection, Bornhuetter Ferguson, Cape Cod, and B&S saves. Unsaved Dataset edits do not request it. Each refresh re-reads the selected-path cached index, rebuilding it only when the reserving-class folder listing no longer matches the persisted signature, and keeps existing table preferences such as filters, grouping, sorting, column widths, selected rows, and scroll position.
- Left and right panels own their scroll areas so overflowing path trees and dataset tables scroll inside the project instance tab frame.
