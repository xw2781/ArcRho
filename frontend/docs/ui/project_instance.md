## External Interfaces
<!-- MANUAL:BEGIN -->
- Opened by shell as a `project_instance` iframe tab after Project Settings posts `arcrho:open-project-instance`.
- Calls shared dataset-types and reserving-class picker helpers.
- Embeds the same lazy reserving-class picker body used by Dataset/DFM/Workflow, so the project instance left panel loads the same hierarchy, filters, hidden-path preferences, Shortcut section, favorites, and user-defined favorite folders.
- The embedded reserving-class path tree uses tight horizontal padding with a small left inset and does not reserve two-sided scrollbar gutters, so more path text fits in the left panel. Tree rows keep their depth-based left indentation while favorite-star actions in Shortcut and All Paths share one right-edge vertical line. Hovering a tree or Shortcut label shows its full path in a compact app-styled tooltip that wraps within the viewport instead of using the browser-native tooltip.
- Project instance loading shows one centered page-level loading card with the same blue sweep spinner style used by Dataset loading while the reserving-class path tree and dataset table load.
- The path-tree load issues its requests concurrently rather than in sequence, because project data may sit on a mapped drive where every serialized request costs a full round trip. The picker starts the saved filter-spec request alongside the combinations and types pair instead of waiting for them, and the shared project-user preference loader joins an already in-flight request so the path panel and the dataset table, which both load preferences as the page opens, share one read instead of making two. A forced reload still issues its own request, and a failed load is not cached.
- Embeds the existing Dataset Viewer page in draggable in-tab windows.
- Double-clicking a dataset that already has an open or hidden floating window activates or restores the existing window instead of creating a duplicate for the same selected path and dataset.
- New floating dataset windows default to about 80% of the project-instance frame and reuse the most recent floating dataset window size for subsequent dataset windows in the same project instance page.
- Floating Dataset, DFM, Result Selection, Bornhuetter Ferguson, and Cape Cod window titlebars highlight the active top window. Titlebars show only the dataset/method name when the window belongs to the currently selected reserving-class path, and fall back to the full reserving-class path plus dataset/method name when the left-panel selection moves to a different path; hovering the titlebar text does not show a native browser tooltip. Minimized toolbar tabs use the dataset/method name without method-type prefixes.
- Floating dataset window titlebars include shell-matching minimize, maximize/restore, and close icon buttons; clicking the minimize button or right-clicking the titlebar sends the window into the toolbar hidden-tab strip.
- Dataset viewer windows follow the shell's existing Windows 11 frame flag, using rounded frame corners on Windows 11 and square corners otherwise.
- Dataset viewer windows can be resized from all corners and edges, with the southeast handle using the same dotted resize glyph as the main shell and shell floating tabs.
- Double-clicking a floating dataset window titlebar toggles maximize/restore within the project-instance frame; dragging a maximized titlebar restores the prior size under the pointer before moving.
- Dataset viewer windows are clamped below the project-instance toolbar; they may be dragged partially off the left, right, or bottom edge as long as a side grab area and the titlebar remain reachable.
- `Ctrl+W` closes the active floating dataset window, including when keyboard focus is inside the embedded Dataset Viewer iframe or when the shell/Electron close-tab shortcut reaches the parent shell first; the project instance tab closes only when no floating dataset window can consume the shortcut.
- `Ctrl+PageUp` and `Ctrl+PageDown` are forwarded to the active floating Dataset or method window when Project Instance owns keyboard focus; once focus is inside the child iframe, its shared tab runtime handles the same shortcut directly.
- The toolbar includes a hidden-tab collection area to the right of the selected path; hidden windows appear as large-radius minimized tabs on the toolbar that show dataset names only plus a styled hover tooltip with the full window title. Each minimized tab uses a centered inline SVG close icon, and hovering or clicking the hidden-tabs button opens a wider content-fitting dropdown that lists full hidden window titles with a one-second hover grace period, per-item close controls, Resume all tabs, Close all tabs, a centered inline SVG close icon that dismisses the dropdown itself, and a matching restore animation that starts from the matching minimized tab. The hidden-tabs button and its dropdown are hidden entirely while no window is hidden, so the toolbar never shows a `0 hidden` control or an empty-state menu.
- Dataset viewer windows add a transparent parent-page drag shield during move/resize so embedded iframes do not interrupt fast mouse movement.
- The project instance toolbar is compact, shows only the currently selected reserving-class path, omits the duplicate selected path above the tree, and sizes the path label to its content with a capped width so minimized toolbar tabs get the remaining space.
- The selected reserving-class path in the toolbar is interactive: each level renders as a compact rounded segment, and clicking a segment opens a small styled picker below it with alternate values for that level from the shared reserving-class hierarchy. The picker focuses a type-to-search field that filters the loaded values without reloading the hierarchy; Arrow keys move between the search field and visible results, and Enter chooses the sole matching value. Choosing a value preserves the existing lower-level suffix when that branch exists, otherwise it selects the first valid descendant path. Right-clicking anywhere on the path highlights the full path and opens Copy/Paste actions. Paste accepts only a valid leaf path from the loaded reserving-class hierarchy, selects that canonical path, collapses the old divergent branch, expands the pasted path, keeps its selected-row highlight visible, and scrolls it into view.
- The left and right panel title bars are omitted so the reserving-class tree and dataset table start directly below the toolbar. The embedded reserving-class tree starts from the full project path hierarchy instead of applying a previously saved reserving-class picker filter; the All Paths header exposes a Collapse Bottom Level control before the Hidden Paths, Filter, and Preferences controls. It collapses the deepest currently expanded folder level in one click, while the remaining controls let users intentionally narrow or configure the tree in place.
- The dataset table has a compact transparent toolbar above the scroll area. Its default Normal view is driven by cached dataset instances from the selected reserving-class path: `Name` is the instance name, `Dataset Type Name` is the stored dataset type, `Category` is the indexed `dataset_category` and otherwise the `Category` that Dataset Types defines for that dataset type, and multiple instance names can share the same dataset type. The cached dataset count in the toolbar reflects visible instance rows after table filters, while the refresh button sits on the right side of the toolbar.
- The toolbar also has a Temporary view icon with a styled hover/focus tooltip that explicitly states whether Temporary view is enabled or disabled and describes only the active mode. Temporary view lists every Dataset Type marked `Generated`, whether or not it has been created for the selected path. Its Status column uses a green check when the dataset is already listed in the selected-path `index.json` and a gray check when it is not. Type-derived fields remain available; cache-only metadata such as Method Type, Last Modified, Created, and User is blank. Temporary rows can only be opened in a read-only Dataset Viewer window. A gray-status row's context menu also provides `Make Permanent`, which runs the same canonical generated-dataset flow as Add Dataset to create the CSV cache and sidecar before rebuilding `index.json`.
- Normal table column filters, except for the icon-only `Status` column, show in a framed `Filter:` section in the dataset toolbar. When no filters are active it reads `Filter: None`; active filters appear as compact column-name chips, and hovering or clicking a chip opens the same filter dropdown used by the active table-header filter button so users can review or change the selected values. Every filter menu includes a Type to search field that narrows only its displayed values; `All` still selects the full column's values. Dragging a table column header or grouped-column chip into the filter frame adds that column as a neutral `All` filter chip and opens its filter menu. Selecting `All` keeps a neutral chip in the filter frame without the blue active-filter treatment, and dragging a filter chip out of the frame clears that column filter.
- The dataset table `Method Type` and `Status` columns, including their filter options, read method metadata from the selected reserving-class folder's cached `index.json` `files` entries, matching rows by instance `name`; datasets missing from the cache display `None` and a green updated status. `Status` shows a green check for sidecar `status: 0` and a yellow warning when a method-backed output has `status: 2` because one of its recorded input precedents was updated later than the method output.
- Double-clicking a dataset row whose `Method Type` is `DFM`, or choosing `View` from its row context menu, opens the DFM method tab by default. Rows whose `Method Type` is `Result Selection`, `Bornhuetter Ferguson`, or `Cape Cod` open that method window directly on its Method tab; method routing is independent of whether the indexed output format is Vector or Triangle. The same row context menu shows `Show as vector` immediately after `View` for DFM, Result Selection, Bornhuetter Ferguson, and Cape Cod vector rows, and shows `View as triangle` for triangle rows. These format-specific actions always open the saved output in a normal Dataset Viewer window without showing method details. Method-backed vectors label the single value column `Ultimate` instead of using the first development-period label. Cached dataset rows open read-only unless their indexed `source_kind` is `input`.
- The dataset table `Formula`, `Last Modified`, `Created`, and `User` columns read from the selected reserving-class folder's cached `.csv`/`.json` file metadata. `Last Modified` comes from sidecar JSON metadata such as `updated_at`/`modified` when present, with filesystem modified time only as a fallback; `Created` comes from sidecar JSON metadata such as `created_at`/`created` without using filesystem creation time; timezone-aware sidecar timestamps, including UTC `Z` values, are normalized to local display time before they are written into the cached index. A dependent propagation walk stamps the sidecar of every method or calculated dataset it rewrites, so `Last Modified` moves for each object the walk actually changed, not only for the object the user saved. Formula values come from sidecar/index metadata, and user values come from the sidecar `user`/`modified_by` Windows-login fields when present. The `Formula` column displays through the shared `formatDetailsFormulaText`, the same formatter the Project Settings Dataset Types table and the Dataset Viewer Formula field use, so one formula never reads three ways: every recognised dataset-type name is quoted whether or not the stored text quoted it, and operator spacing is normalised. The dataset-type rows the page already holds supply the names the matcher needs; without them a name containing `-` or `/`, such as `C 22 - CWOP DFM w/ Selected LDFs`, could not be told from an expression. Filtering, grouping and sorting all see the same displayed text, so a filter chip matches the cell beside it.
- Adding a dataset from the cached-dataset table's add picker refreshes the cached list, highlights the newly added dataset row, and selects it in place instead of opening a floating Dataset Viewer window.
- Double-clicking a dataset table row whose `Method Type` is `DFM` opens a floating DFM window inside the Project Instance frame on its Ratios page, initialized with the current project, selected reserving-class path, and dataset name instead of opening the in-tab Dataset Viewer window or a main shell tab; it also records the selected DFM method/output name in project-user `dfmObject` preferences.
- Floating Dataset and DFM windows inside Project Instance follow the main shell corner convention: 6px by default and 8px when the page is running with the Windows 11 frame style.
- Floating Dataset and DFM windows mirror standalone save/dirty behavior: dirty-state messages show a dirty dot on the floating titlebar and minimized tab, closing a dirty window asks for confirmation, confirming discard closes the floating window, and shell Save plus Ctrl+S routes to the active floating Dataset or DFM window. Saving a nested dataset or method window never closes it; the window stays open and clean so the user can keep working, and only Cancel, the titlebar close, or the close shortcut dismisses it. DFM windows also support Save As/Ctrl+Shift+S through the active floating DFM window.
- Floating DFM windows publish their active DFM state to the shell and forward standalone DFM commands, so shell Edit/Help menu actions, ratio hotkeys including the Ctrl+E Select/Edit toggle, DFM JSON opening, Notes file-link context-menu actions including popped DFM tab surfaces, and macro context/apply requests target the active Project Instance DFM window the same way they target a standalone DFM tab. Ctrl+E is forwarded even before the nested DFM iframe receives keyboard focus. When the active Ratios window is in Select mode with a highlighted range, Project Instance also forwards Enter and Arrow-key navigation with Shift/Ctrl/Cmd modifiers, including when focus is on the surrounding DFM window surface. Clicking back into the reserving-class tree or dataset table clears the active nested window and returns shell context to the Project Instance reserving-class level.
- Project Instance relays `arcrho:calculated-datasets-updated` reports between nested Dataset windows and the shell, so open nested calculated dataset windows can auto-refresh after an upstream component save.
- Project Instance relays `arcrho:dependency-source-preview` and `arcrho:dependency-source-cleared` messages between nested Dataset, DFM, Result Selection, Bornhuetter Ferguson, Cape Cod, and Berquist Sherman windows, including DFM windows that use the shared Dataset layer. This lets a dirty upstream source feed temporary values to an open dependent method or matching Dataset Viewer window. For dirty sources that feed app-calculated Dataset Types, Project Instance also requests an in-memory calculated preview and relays the downstream calculated values, then tells dependents to reload the source from disk when the upstream source is saved, canceled, or closed without saving.
- Project Instance handles dependency open requests from nested Dataset Details pages, opening or activating the clicked dependent as a floating Dataset window using the source window's reserving-class path even if the left-panel selection has moved; method-backed Formula component chips open the related DFM, Result Selection, Bornhuetter Ferguson, or Cape Cod method window instead.
- Project Instance publishes `arcrho:project-instance-state` snapshots to the shell when the selected path or nested floating Dataset/DFM/Result Selection/Bornhuetter Ferguson/Cape Cod/Berquist Sherman windows change. Berquist Sherman snapshots use `kind: "berquist_sherman"` plus `bsTab` and `bsVariant`; the page reports tab changes with `arcrho:berquist-sherman-tab-changed`. A successful first B&S save rekeys the same floating window to the saved output Name, and restored B&S windows reopen against their own saved reserving-class path. The snapshot also includes selected path, nested window name/title, hidden/active/maximized/dirty flags, other method subtabs, and restore rectangles so Browsing History can restore Project Instance pages after Clear Cache & Reload without turning method windows into dataset viewers.
- Project Instance can host a macro review table (`ui.reviewTableOpen` with `host: "projectInstance"`, used by the Sync Reserving Class with ResQ, Import ResQ Reserving Class, and Export Reserving Class to ResQ macros) as a normal nested pi-window built from the shared `review_table` panel component. Its grid is the same `pi-table` the dataset table renders, from the same `ui/shared/styles/pi_table.css`: a colgroup carrying an explicit width per column, a sticky header cell whose label sorts on click and drags to reorder columns, a per-column value filter popover, a resize grip that double-clicks back to auto-fit, and rows the shared selection rules paint. Grouping is the one dataset-table feature it does not offer, because a review lists the actions of a single sync run, so there is no group-by strip above the table. Selection means "accept this action": a click anywhere on a row toggles its tick and highlights it, Shift-click paints the range from the anchor with the anchor's new state, and the tick column keeps its select-all for the visible rows. Because the grid uses the shared class names, the Dark and High Contrast sheets dress it without rules of their own. The window is non-modal, so users can minimize it to the toolbar's minimized tabs, browse the dataset table or open datasets to check details, and restore it before accepting or cancelling. The same window also hosts the macro's results after the apply phase, opened with `selectable: false`: one row per applied, failed, or warned item with its outcome and message under a header naming the run's one direction, no tick column, and a single `Close` button; the macro keeps polling until that window is closed. The Import and Export macros open the same window twice: first the shared transfer review, where every dataset and method output either system holds is ticked or left out, and then the results form, one row per item in write order with `Exported`, `Saved`, `Skipped`, or `Failed` and the reason. Closing the window through its X, the minimized-tab close, or the hosting tab resolves the pending review as a cancelled completion for the polling macro. Review windows never enter the persisted `arcrho:project-instance-state` snapshot, so they are not restored after reload. An implicit `projectInstance.activeWindow` properties query with no open or focused nested window replies ok with an empty `windowId` (Python `active_window()` returns `None`) instead of an error; explicit `windowId`/`windowKey` lookups still fail with "Project Instance window was not found."
- A delete is refused while anything still uses the selection as an input. The server checks the whole request before removing a single file, so a refusal changes nothing on disk and the table stays correct without a reload. Project Instance then shows a `Cannot delete: still in use` window listing the full downstream chain the refusal carries (`downstream_closure`, breadth-first, each row tagged with its method type): clicking a row closes the window and opens that object's own method or dataset window, where the input can be cleared before the delete is retried, and a `Delete all (N downstream)` action resubmits the delete with the whole chain included — the user has just seen exactly what it covers, so that click is the confirmation, and a resubmission the graph outgrew in the meantime simply shows the fresh refusal. Dependents already selected for the same delete are not treated as blockers, so selecting a method together with the input it consumes deletes both. The page never pre-checks dependents before offering Delete: a cached answer could be stale by the time the user confirms, and the server's refusal is the only one that is current. A delete during a running dependent walk is refused with the same busy-class `423` a save meets.
- Deleting cached files from the row context menu redraws the table from the index the delete response already carries instead of issuing a follow-up `/datasets/cached` read, and suppresses the index poll for the write it just made so the `Refresh Table` prompt does not appear for the user's own delete. If that response has no usable index, the table falls back to the normal reload.
- Confirming a delete shows the same page loading overlay, spinner, and elapsed counter the project load uses, titled `Deleting cached files` and naming the dataset or the selected count. The server removes the files and rebuilds `index.json` in one request that reports no intermediate progress, so the indicator is deliberately indeterminate; the elapsed counter is what tells the user a slow mapped drive is still working. The overlay clears whether the delete succeeds or fails, and cancelling the confirmation never opens it. Any Project Instance action can claim the shared overlay this way by passing a title and message to `beginPageLoading`; tasks that pass none keep the project-load wording, and finishing a labelled task restores the wording of whatever is still loading.
- The dataset toolbar includes a refresh icon button. Clicking it reloads the right-panel dataset table from disk via `/datasets/cached` and restores the table scroll position plus selected rows afterward. The reload does not ask the server to force a rebuild: the lookup lists the selected reserving class's `datasets/`, `methods/`, and `sidecars/` folders and rebuilds `index.json` only when that listing no longer matches the persisted folder signature, so an unchanged reserving class reloads without reading any sidecar or method file. A user-initiated reload uses its own in-flight request key so it never joins a background read that started earlier. In Temporary view, the same action refreshes selected-path index membership; the temporary-view cache itself never creates an `index.json` entry or triggers an index rebuild. Project Instance polls `/datasets/cached/index-signature` every 8 seconds for the selected reserving class and compares `index.json`'s size and mtime against the loaded snapshot; when a newer write appears, the toolbar shows a `Refresh Table` button so users can reload the table deliberately. The comparison baseline is the `index_signature` the `/datasets/cached` snapshot itself carries, statted by the process that wrote or validated `index.json` (the Gateway for hosted reads), so it cannot be an SMB attribute-cache echo of the pre-write file; when an older server omits the field, the client stats once behind a short settle suppression instead. A polled signature whose mtime is older than that baseline is the mapped drive's metadata cache echoing the past and is ignored without being adopted, so a save, dependent propagation, delete, or Excel-link retarget this app session itself triggered never raises the prompt — only a genuinely newer index write can. Polling pauses while the window is hidden and re-checks as soon as it is visible again. Nested Dataset, DFM, Result Selection, Bornhuetter Ferguson, Cape Cod, and B&S saves also request the same selected-path table refresh. Unsaved Dataset grid edits and pasted Excel references stay in the in-memory dirty/preview flow and do not reload this disk-backed table.
- If the server can scan the selected dataset folder but cannot persist its derived `index.json` on the mapped drive, Project Instance still renders the scanned rows and shows `Warning: index not saved` in the table toolbar. The full filesystem warning remains available as the toolbar's accessible label, and a later successful persisted lookup clears the warning.
- The dataset toolbar's gear button opens the Preferences window, a draggable floating dialog with a section rail on the left and one panel per section on the right. The rail lists section names only; each panel's own note says whether the setting is shared with everyone on the same ArcRho Server or personal, and the Number Formats panel also shows the resolved file path it reads and writes. Save writes only the sections that changed, Cancel and Escape close without writing, and Ctrl+S saves from anywhere in the window. Both scroll surfaces use the shared framed scrollbar (`ui/shared/styles/framed_scrollbars.css`): a pale tray that reads as part of the frame with one arrow at each end.
- The **Number Formats** section is server-shared. It edits the resolved `config/dataset_number_formats.json` path, fallback format, filterable Dataset Type Name override table, and add/remove controls. The table lists every Dataset Type of the open project (read fresh from `/dataset_types` when the window opens, in Project Settings order) merged with the saved overrides, so a type added in Project Settings appears without anyone typing its name; overrides for types the project does not define follow, still editable. A project type's name is read-only, and a blank format shows the fallback as a placeholder, is styled as inherited, and is never written — only rows with a format of their own become overrides, and a reset button on a project row clears its format back to the fallback while the trash button removes a row for a type outside the project. Opening never writes the shared file; the merge logic lives in `project_instance_number_format_rows.js` (`mergeNumberFormatRows`, `numberFormatOverridesFromRows`, `numberFormatOverridesKey`), and the dirty check compares override sets independent of row order. If the project's Dataset Types cannot be listed the window still shows the saved overrides and says so. Save validates complete unique rows, reports load/save failures in the window, and rejects stale revisions instead of overwriting changes made in another window. The saved type-level defaults apply to subsequently generated engine and app-calculated dataset sidecars across every project and reserving-class path, including instances whose Name differs from their Dataset Type Name; existing sidecar display settings are not rewritten. Opening a generated dataset from Temporary view resolves the same saved fallback/override by Dataset Type Name when no sidecar exists, while keeping the viewer read-only and leaving the temporary cache unindexed. That resolution happens during the Dataset Viewer boot, before the first run paints the grid, so a temporary open shows the configured format immediately instead of only after a parameter such as Origin Length changes.
- The **Default Tabs** section is local-user state and writes the `arcrho_default_window_tabs` browser-storage key, so one Windows account on one PC keeps one choice and every project it opens uses it. It lists every kind of nested window Project Instance opens - Dataset Viewer, DFM, Result Selection, Bornhuetter Ferguson, Cape Cod, and Berquist Sherman - with that page's tabs as a row of chips. Picking a chip and saving makes windows of that kind open on that tab; `Reset to app defaults` returns every row to the app default, which is `Data` for the Dataset Viewer, `Ratios` for DFM, and `Method` for every method page. The whole map is written, never a partial one, so a kind left at the app default cannot keep an older stored value. A Project Instance window already open on another project adopts a saved change through the browser storage event rather than waiting to be reopened. An opener that asks for a specific tab still wins, and only two do: a restored window returns to the tab it was on, and adding a brand-new dataset or method opens on Details because its Dataset Type, lengths, or sources have to be chosen before anything can be computed. Opening an existing object never names a tab - not from the dataset table, not from an automation route, and not from a cross-window navigation - so the preference is what decides. The window also paints on that tab straight away: `ui/shared/tabbed_page/initial_tab_paint.js` is a plain classic script each tabbed page runs while it is still parsing, and it applies the requested tab to the panels the same way the tab system's own `setActive` later will. Panels carry `data-page` for it, the attribute the tab buttons already use, so it needs no page-id rule that could drift. Without it a window painted whichever panel its markup pre-selected - Details on the method pages, Data in the Dataset Viewer, whose tab system does not run until its first reads finish - and then visibly jumped. The Dataset Viewer builds its panels in script, so it calls the same pass on the fragment before inserting it. The same file owns the other half of a quiet open: each tabbed page marks its own `body` with `data-arcrho-page-hold`, which `tabbed_page.css` reads to hide the body's children until the page calls `window.arcrhoRevealPage()`, two animation frames after its opening tab has finished loading and rendering. Only the children are hidden, never the body, so the theme's own background keeps painting and a dark window cannot flash white while it loads. The window therefore appears in one step rather than assembling itself in front of the user. Three releases guarantee it can never stay blank: each page reveals from a `finally`, so a failed load still shows; the script reveals on an uncaught error and after six seconds, so a load slower than that trades the single clean paint for its own loading feedback; and a pure-CSS animation releases the hold at twelve seconds even if the script never loads. The tab lists and the app defaults are owned by `ui/shared/tabs/window_tab_catalog.js`, which the Dataset Viewer and every method page also read, so the window can never offer a tab a page does not have.
- The dataset toolbar includes an Excel-link button between the Temporary view and refresh buttons. It opens the Excel Link Manager for the selected reserving class as a standard nested pi-window (`kind: "excel_links"`, page `ui/project_instance/excel_links_window.html`), so it drags, resizes from every edge and corner, minimizes to the toolbar's minimized tabs, maximizes, and closes through the same titlebar controls as a Dataset or DFM window, and the table grows with the frame. Like every other nested window it is pinned to the reserving class it was opened on: the titlebar names that path and ends in `Manage Excel Links`, selecting another class in the tree leaves the window alone, and the toolbar button then opens a second window for the new class while re-activating an existing one for a class already open. Because the manager is a tool window rather than an object, it never enters the persisted `arcrho:project-instance-state` snapshot and is not restored after reload.
- The window lists every workbook referenced by its reserving class's saved dataset sidecars and v2 DFM methods as one row per usage rather than one row per workbook: a workbook read by two datasets and one DFM method is three rows, so the reader sees the dependent objects without hovering a summary cell. The columns are `Dataset Name`, `Method Type`, `Workbook`, `Location`, `Last Modified`, `Created`, and `User`; `Method Type` carries the same values the dataset table shows (`None`, `DFM`, `Result Selection`, ...), resolved server-side from each sidecar by its canonical owner, and a DFM row reads `DFM` because the row is the method; everything that describes the workbook — `Location`, and the three metadata columns — repeats on every row of the same workbook, which is what makes the column filters meaningful. `Location` drops the trailing path separator the server keeps internally for building Excel external references. `Last Modified`, `Created`, and `User` answer the same questions the dataset table's columns of those names answer, about the workbook instead of the dataset: they are the workbook's own document properties (`dcterms:modified`, `dcterms:created`, `cp:lastModifiedBy` in the package's `docProps/core.xml`), not the file system's, so they survive a copy or a move that would reset the file's creation time. They are read on the server host in the same batch pass that stats each workbook, so the listing does not walk the file list twice. A workbook that carries no readable properties — a legacy `.xls`, an encrypted package — leaves all three blank and is still found and still relinkable; only a file the host cannot stat at all is reported missing. The two dates use the shared ArcRho timestamp text (`ui/shared/utils/timestamp.js`), the same rule and module the dataset table's Created and Last Modified use. Every cell keeps its right border, including the last column, so the rows close against the frame when the window is wider than the table. There is no `Status` column: a workbook ArcRho Server cannot open is shown by painting its `Workbook` cell in the danger color, with the tooltip carrying the path and the reason. That verdict is ArcRho Server's answer — whether the server host can open the workbook — not the client PC's, because the server is the machine that reads workbooks for every retarget and refresh. Above the table sits one compact toolbar row: a muted cue (`Right-click a row for workbook actions. Click a name to open it.`) on the left and the refresh icon on the right, sized to match the dataset toolbar buttons; there is no header, hint paragraph, per-row button, or recalculation checkbox. The status line under the table reports the linked workbook count, the reference count (`n of m references shown` while a filter hides rows), and any files the scan could not read.
- The table follows the `pi-table` column model from the dataset table (`.claude/skills/arcrho-ui-design` T09): every column carries an explicit width written onto a `colgroup`, the table's width is their sum, dragging a header's right edge resizes only that column and lets the table grow or shrink instead of redistributing its neighbours, and double-clicking a resize handle hands that column back to auto-fit. Widths start from the content: when a listing loads, every column the user has not dragged is sized to fit its own header and cells, capped by that column's `maxAutoWidth` so one deep folder path cannot crowd out the columns the reader acts on. A value longer than its column wraps instead of being cut at one line, clamped to two lines so the tallest row stays inside twice the 31px base row height (T01); the measured font is read off the rendered cell, so the stylesheet remains the only place the table's typography is declared. Each column has a header filter button that opens a value-checkbox popover with a search box, an `All` row that clears the column filter, and a right-click on a value that keeps only that value. No checked values means the column is unfiltered, and reloading the listing drops filter values the new rows no longer contain. Widths and filters are per window and are not persisted.
- Clicking a `Dataset Name` cell posts `arcrho:project-instance-open-dependent-dataset` to the Project Instance page, which opens a dataset row in Dataset Viewer and a DFM row in the DFM page (`openMethod`/`methodType: "DFM"`), pinned to this window's reserving class. A dataset row carries the `dataset_type` and `method_type` the listing read from its sidecar, so an instance whose name differs from its Dataset Type opens correctly even when the tree has since moved to another class — the same route a method page uses to open a precedent.

The three open actions run on the client machine through the desktop host's `arcrho:open-path` route (`ui/shared/integrations/open_path.js`), because Excel and File Explorer are on the user's PC — so a workbook the server cannot reach can still open here, and the reverse. `Change Link...` opens the desktop file picker (desktop app only) and posts `/excel_links/retarget` with only the old and new paths. The retarget always runs on ArcRho Engine as a hosted save: the server opens the picked workbook (a workbook it cannot open is refused with the server's own reason, and the status line names the picked path), rewrites every saved reference in the reserving class, re-saves every affected dataset and DFM with values refreshed from the new workbook — even when the numbers did not change — and walks the class once so affected objects and their dependents are marked Needs Review. The status line reports links/files updated, cells recalculated (and whether values changed), cells that could not be recalculated, and the review/propagation outcome.
- The manager page runs in the window's iframe and owns only the inventory and its row actions; the frame is owned by `project_instance_windows.js` and the table view (widths, resizing, filters, rendering) by `ui/project_instance/excel_links_table.js`. It reports the two moments the host needs with `arcrho:excel-links-retarget-begin` and `arcrho:excel-links-retarget-end`: the first suppresses the `Refresh Table` prompt for the index rebuild the retarget performs, and the second restores the poll, writes the picked workbook into the page status bar, and reloads the cached dataset table when any file changed (statuses move even when values did not). Open Dataset windows learn of rewritten sidecars through the standard change-watch alert, and a dirty open DFM whose method was retargeted hits the normal owned-revision conflict on its next save.
- The dataset toolbar includes a visible grouping drop zone. When no grouping is active it prompts users to drag a column header there; when grouping is active a compact `+` icon appears to the right of grouped chips and shows the drag-to-group hint in a styled hover tooltip. Grouped columns appear as draggable chips, disappear from the main table while grouped, and can be reordered inside the grouping drop zone with an insertion marker. Project Instance supports nested grouping for every available dataset table column rather than stopping at two subgroup levels. Dragging a group chip over a table header shows the same blue insertion line as column reorder and restores the column at that drop location; dropping it over table body space removes grouping and restores the saved column position. Right-clicking dataset table header cells still opens a context menu with `Group by ...` choices for `Data Format` and `Category` plus a placeholder `Reset Columns` option; grouping creates nested compact collapsible group headers inside the same table instead of rendering separate grouped tables. Top-level group headers show record counts as low-contrast circular badges, while subgroup headers omit counts. Every table header still supports drag-to-reorder column labels and drag-to-resize header edges, and all columns except `Status` support per-column filter dropdowns; dragging a column shows a full-height blue insertion line at the target location and a framed drag preview with the column label. Per-column filters match the Project Settings Dataset Types table: no checked values means the filter is not applied, checked values narrow results, and selecting all values is treated as unfiltered while keeping that column as a neutral filter chip when the user explicitly chose it. Each filter dropdown includes an `All` checkbox that clears selected values and resets that column filter; right-clicking a value row selects every value except the clicked one. Resizing a column changes only that column and updates the total table width instead of redistributing space across other columns.
- Dataset table default column order, grouping, filters, sort state, and widths come from the built-in Project Instance preference snapshot. Manual resize can still expand or shrink a column, and double-clicking a resize handle restores that column to its built-in default width.
- Right-clicking a dataset table group header opens `Collapse all` and `Expand all` actions for group headers at the same grouping level as the clicked header.
- Clicking a dataset table row keeps that exact row highlighted, including rows whose dataset names differ only by special characters. Clicking the only highlighted row again removes it from the selection, while clicking one row inside a multi-selection narrows selection to that row. `Ctrl`/`Cmd` click toggles individual rows, `Shift` click selects the visible range from the last anchor row, Up/Down arrow keys move a focused row selection to the previous or next visible dataset, and Enter opens the active selected dataset. The active row is the row of the last click, `Ctrl` toggle, `Shift` range end, or right-click. All selected rows share the same background fill; inside a multi-row selection only the active row keeps the solid blue left-edge bar while the other selected rows draw a hollow left bar (two 1px lines around a 2px transparent gap), so the solid bar is what shows which dataset Enter will open. A single selected row keeps the original solid bar. The app status bar shows the selected item count when more than one row is selected. Right-clicking a row targets the row under the mouse pointer: a right-click outside the current selection collapses the selection to that row, a right-click inside it keeps the selection and moves the active-row emphasis to the pointer row, and the row menu can view the right-clicked dataset or first highlighted dataset, shows `Show as vector` for DFM, Result Selection, Bornhuetter Ferguson, and Cape Cod vector rows, shows `View as triangle` for triangle rows, exposes an Add submenu, and can delete cached files related to all highlighted datasets after a custom confirmation dialog. Add > Dataset opens the shared dataset picker window (`ui/shared/components/pickers/dataset_name_picker.js`) for the current project, with Dataset Type Name search, sorting, column filters, grouping, and shared picker preferences. Choosing a generated type sends an ArcRhoTri refresh request to the data engine; generated dataset types are one-instance-per-reserving-class path, so choosing one that already exists in the selected path shows a custom message box instead of issuing another request. Choosing a non-generated dataset type opens a fresh Dataset Viewer draft on the Details page with `Name` defaulted to the dataset type name, initial `number_format` set to `0,000`, default period lengths set to 12, and an editable zero-filled Data-tab placeholder whose labels come from the project settings. Triangle placeholders use the standard triangle shape and Vector placeholders use a one-column vector shape so users can paste from Excel or type values into the available cells. The draft window opens with Save enabled, so the new dataset can be created straight from the prefilled draft without editing a cell first. Users may rename the instance before saving, and the draft page blocks duplicate instance names in the selected path. Add > DFM opens a fresh floating DFM window on Details with project/path and default Origin Length, Development Length, and Decimal Places; Name and Output Vector remain blank, and the right-clicked dataset is passed as Input Triangle. Add > Result Selection opens a fresh floating Result Selection window for a vector dataset whose Method Type is `None`, prefilled with project/path, output vector name, output type, and category. Add > Bornhuetter Ferguson opens a fresh BF method window for a vector dataset whose Method Type is `None`, prefilled with project/path, output vector name, output type, and category. Add > Cape Cod opens a fresh Cape Cod method window the same way for a vector dataset whose Method Type is `None`. For an annual Triangle row whose Method Type is `None`, Add provides direct `B&S Settlement Rate Adjustment` and `B&S Case Reserve Adequacy Adjustment` commands. Each opens the shared B&S method page with the selected row as its initial paid-claims triangle and the chosen canonical variant.
- Project Instance context-menu submenus include a small pointer bridge between the parent menu item and nested menu so the nested choices remain open during normal diagonal mouse movement.
- When a reserving-class path is selected, Help > Reveal in File Explorer resolves that path's cached `folder_paths.data` folder and asks the shell's desktop open-path bridge to open it in File Explorer.
- Help > Open Dataset JSON File resolves the active floating DFM, Result Selection, Bornhuetter Ferguson, or Cape Cod window to its `methods/*.json` method file and opens it in Arcode through the shell desktop bridge. Help > Open Dataset Sidecar resolves the active floating Dataset, DFM, Result Selection, Bornhuetter Ferguson, or Cape Cod window to its `sidecars/<DatasetName>.json` file and opens it the same way.

- Dataset table renders precompute row cell values, filter option lists, and active filter selections once per render before grouping and sorting, keeping filter/group changes responsive on larger project dataset lists.
- Dataset table headers remain opaque while scrolling, so row contents do not show through sticky header cells.
- Dataset table body cells wrap long text and clamp display to two lines per cell, without row-hover fill or browser tooltips over row values.
- Clicking a dataset table column label cycles that column through ascending sort, descending sort, and no active sort, with the third click returning rows to the default cached order and removing the sort indicator. `Last Modified` and `Created` sort by their cached numeric timestamp values instead of their formatted display strings.
- The left reserving-class panel defaults to 400px and has a draggable splitter constrained to 200px-600px; collapse/expand is animated, live drag updates are frame-throttled with transitions disabled for responsiveness, dragging the panel to 200px or smaller collapses it, and double-clicking the splitter toggles collapse/expand.
- Dependency-source `cleared` messages may carry a `propagationJobId` from a save that enqueued an Engine dependent-propagation job. Project Instance then defers relaying the clear (and clearing its calculated preview fan-out targets) until the job's terminal status, so downstream open windows keep their live-preview values instead of snapping back to stale persisted values; it brackets the wait with `arcrho:dependent-propagation-started`/`-finished` broadcasts so those windows' change watches pause for the job. A failed job still releases the clear so windows reload the honest Review Needed state. Save flows can fire more than one clean transition, and only the first cleared message carries the job id, so while a source has a deferral pending Project Instance swallows job-less cleared duplicates for that same source — relaying one would clear downstream previews early and reload pre-walk stale values that never recover.
- The page polls `GET /dependent_propagation/reserving_class_busy` (~5 s, plus an immediate probe on every path change) for the selected reserving-class path. While the class is held by a dependent-propagation walk — this app instance's save or another user's — class-mutating row actions (Add, Delete, Make Permanent) are refused with a status message; opening dataset and method windows stays allowed. Nothing is rendered above the dataset toolbar: live propagation updates stream inside the saving window's popup log, and a blocked action explains itself in the status bar. The freeze is advisory UX only: the app server enforces the hold by refusing writes into a busy class with 423, so a missed poll can never corrupt anything, and the probe's freshness windows release the pause by themselves when a worker dies.

## Data/State/Caches
<!-- MANUAL:BEGIN -->
- Uses the shell-persisted project name/folder/table path as tab inputs.
- Loads the project's last selected reserving-class path from project-user preferences when the tab opens; if no last path exists, it selects the first Shortcut item when available, otherwise leaving the path empty.
- Keeps the selected reserving-class path in page memory, saves user selections back to project-user preferences, and passes it into new floating Dataset Viewer and DFM windows. Opening a floating DFM window also updates the shared project-user DFM object defaults with the selected method/output name without waiting for the DFM method to be saved.
- Saves the right-panel dataset table layout in the same project-user preferences JSON under `projectInstance.datasetTable`, including column order, manual column widths, filterable column selections, grouping fields, collapsed group rows, and sort state. Cleared/no-op filters and the non-filterable `Status` column are saved as empty arrays so stale saved filter values do not return after reload. Normal view is always the default; Temporary view is session-only and is not saved as a table preference, although its retained CSV cache persists on disk. When the current project/user has no saved `projectInstance` object yet, the preference API supplies the built-in default `projectInstance` settings before the page loads, unless `ARCRHO_PROJECT_INSTANCE_DEFAULT_PREFS_PATH` points to an override JSON. If preference loading stalls during startup, Project Instance falls back to the default table layout so the page can finish opening.
- Opening a Temporary-view dataset reuses a valid canonical cache read-only when available; otherwise it writes generated or derived CSV output to `data/<ReservingClassFolder>/datasets/.temporary-view/`. The retained temporary-view cache persists after Temporary view closes, never creates a sidecar, and never creates an `index.json` entry or triggers an index rebuild. The Temporary Status check is green when the dataset is already listed in the selected-path `index.json` and gray when it is not. Temporary windows are excluded from Project Instance restore snapshots.
- Changing the selected reserving-class path refreshes the server-side `index.json` lookup for logical cached dataset instances, stored dataset type names, minimal table metadata, and method types for the selected reserving-class data folder while preserving existing table column filters and grouping.
- Every dataset table load reads the project's Dataset Types alongside that `index.json` lookup, concurrently and under the same in-flight request guard. Dataset Types owns the `Data Format`, `Category`, and `Formula` shown for each instance, and Project Settings can add or change a type while this page stays open, so a type added after the page opened would otherwise leave its saved instances grouped under a blank `Category`. A failed dataset-type read leaves the rows already loaded in place instead of clearing the type-owned columns.
- Method type and review-status lookup are derived from the same selected-path `index.json` payload as cached dataset names and metadata, so Project Instance does not issue a second method-index request during path selection.
- Floating DFM window dirty state is tracked by DFM iframe `arcrho:dfm-dirty` messages keyed by the DFM `inst`, with iframe-source fallback during startup state sync; Project Instance sends aggregate `arcrho:project-instance-dirty` messages to the shell and consumes shell-level DFM save commands before forwarding them to the active floating DFM iframe. New floating windows start clean until their iframe reports an actual edit state.
- Floating DFM window active state is tracked by DFM iframe edit/history/tab messages and reported to the shell with `arcrho:project-instance-dfm-active-state`; Project Instance forwards `arcrho:assistant-context-request`, `arcrho:dfm-apply-method-payload`, `arcrho:assistant-dfm-edit-approval`, and nested `arcrho:open-path` requests so macros, ArcBot approval review, and file-open actions can use the same active-context and desktop-open contracts for standalone and nested DFM pages. ArcBot app context uses the top active non-minimized floating Dataset/DFM window as the primary Project Instance context and includes lightweight metadata for the other visible nested windows so ArcBot knows they are open without eagerly loading every window's data. The App Context hover text shows the Project, Segment, active nested tab name, table-consistent Method Type, and visible nested-tab count. Minimized nested windows are excluded from ArcBot app context.
- Nested Dataset, DFM, Result Selection, Bornhuetter Ferguson, and Cape Cod windows render dirty-close confirmation inside their own page iframe through the shared close-confirm component; Project Instance only invokes each child page's close hook and does not relay or render the modal.
- Project Instance handles the shell `arcrho:automation-open-dataset` message for Python UI automation. The command opens or activates a floating Dataset Viewer window for the current selected reserving-class path, or opens the matching DFM/Result Selection/Bornhuetter Ferguson/Cape Cod method window when callers pass `openMethod` with a method type, then returns the project name, selected path, dataset name, window id, title, and current window properties to the command bridge.
- Project Instance handles the shell `arcrho:automation-project-instance-refresh-datasets` message for Python UI automation. The command reloads the selected reserving-class dataset table from disk with the same behavior as the refresh toolbar button, then returns the project name, selected path, and `refreshed` status to the command bridge.
- Project Instance handles the shell `arcrho:automation-window-command` message for Python UI automation window objects. It can return properties for the active or addressed floating window and perform activate/focus, maximize, restore, minimize, and close actions through the same window manager used by the Project Instance titlebar controls.
- Project Instance consumes `arcrho:project-instance-restore-state` from the shell after the page boots. Restore selects the saved reserving-class path, recreates saved nested Dataset, DFM, Result Selection, Bornhuetter Ferguson, Cape Cod, and B&S windows, reapplies window rectangles/maximized/hidden state, restores saved method subtabs, and raises the saved active visible window.
- Dataset table refresh is available from the toolbar, from the `Refresh Table` prompt shown after a polled `index.json` change, and after nested Dataset, DFM, Result Selection, Bornhuetter Ferguson, Cape Cod, and B&S saves. Unsaved Dataset edits do not request it. Each refresh re-reads the selected-path cached index, rebuilding it only when the reserving-class folder listing no longer matches the persisted signature, and keeps existing table preferences such as filters, grouping, sorting, column widths, selected rows, and scroll position.
- Left and right panels own their scroll areas so overflowing path trees and dataset tables scroll inside the project instance tab frame.
