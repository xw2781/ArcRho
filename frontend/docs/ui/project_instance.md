# Frontend: Project Instance

## Purpose
<!-- MANUAL:BEGIN -->

## External Interfaces
<!-- MANUAL:BEGIN -->
- Opened by shell as a `project_instance` iframe tab after Project Settings posts `arcrho:open-project-instance`.
- Calls shared dataset-types and reserving-class picker helpers.
- Embeds the same lazy reserving-class picker body used by Dataset/DFM/Workflow, so the project instance left panel loads the same hierarchy, filters, hidden-path preferences, Shortcut section, favorites, and user-defined favorite folders.
- The embedded reserving-class path tree uses tight horizontal padding with a small left inset and does not reserve two-sided scrollbar gutters, so more path text fits in the left panel.
- Project instance loading shows one centered page-level loading card with the same blue sweep spinner style used by Dataset loading while the reserving-class path tree and dataset table load.
- Embeds the existing Dataset Viewer page in draggable in-tab windows.
- Double-clicking a dataset that already has an open or hidden floating window activates or restores the existing window instead of creating a duplicate for the same selected path and dataset.
- New floating dataset windows default to about 80% of the project-instance frame and reuse the most recent floating dataset window size for subsequent dataset windows in the same project instance page.
- Floating Dataset, DFM, and Result Selection window titlebars highlight the active top window. Titlebars show only the dataset/method name when the window belongs to the currently selected reserving-class path, and fall back to the full reserving-class path plus dataset/method name when the left-panel selection moves to a different path; hovering the titlebar text does not show a native browser tooltip. Minimized toolbar tabs use the dataset/method name without method-type prefixes.
- Floating dataset window titlebars include shell-matching minimize, maximize/restore, and close icon buttons; clicking the minimize button or right-clicking the titlebar sends the window into the toolbar hidden-tab strip.
- Dataset viewer windows follow the shell's existing Windows 11 frame flag, using rounded frame corners on Windows 11 and square corners otherwise.
- Dataset viewer windows can be resized from all corners and edges, with the southeast handle using the same dotted resize glyph as the main shell and shell floating tabs.
- Double-clicking a floating dataset window titlebar toggles maximize/restore within the project-instance frame; dragging a maximized titlebar restores the prior size under the pointer before moving.
- Dataset viewer windows are clamped below the project-instance toolbar; they may be dragged partially off the left, right, or bottom edge as long as a side grab area and the titlebar remain reachable.
- `Ctrl+W` closes the active floating dataset window, including when keyboard focus is inside the embedded Dataset Viewer iframe or when the shell/Electron close-tab shortcut reaches the parent shell first; the project instance tab closes only when no floating dataset window can consume the shortcut.
- The toolbar includes a hidden-tab collection area to the right of the selected path; hidden windows appear as large-radius minimized tabs on the toolbar that show dataset names only plus a styled hover tooltip with the full window title, and hovering or clicking the hidden-tabs button opens a wider content-fitting dropdown that lists full hidden window titles with a one-second hover grace period, per-item close controls, Resume all tabs, Close all tabs, and a matching restore animation that starts from the matching minimized tab.
- Dataset viewer windows add a transparent parent-page drag shield during move/resize so embedded iframes do not interrupt fast mouse movement.
- The project instance toolbar is compact, shows only the currently selected reserving-class path, omits the duplicate selected path above the tree, and sizes the path label to its content with a capped width so minimized toolbar tabs get the remaining space.
- The selected reserving-class path in the toolbar is interactive: each level renders as a compact rounded segment, and clicking a segment opens a small styled picker below it with alternate values for that level from the shared reserving-class hierarchy. Choosing a value preserves the existing lower-level suffix when that branch exists, otherwise it selects the first valid descendant path.
- The left and right panel title bars are omitted so the reserving-class tree and dataset table start directly below the toolbar. The embedded reserving-class tree starts from the full project path hierarchy instead of applying a previously saved reserving-class picker filter; the All Paths header exposes the same Hidden Paths, Filter, and Preferences controls as the shared reserving-class picker so users can intentionally narrow or configure the tree in place.
- The dataset table has a compact transparent toolbar above the scroll area, and the table always shows the cached dataset view for the selected reserving-class path. The table is driven by cached dataset instances from the selected path: `Name` is the instance name, `Dataset Type Name` is the stored dataset type, `Category` is the indexed `dataset_category`, and multiple instance names can share the same dataset type. The cached dataset count in the toolbar reflects visible instance rows after table filters, while the refresh button sits on the right side of the toolbar.
- Normal table column filters, except for the icon-only `Status` column, show in a framed `Filter:` section in the dataset toolbar. When no filters are active it reads `Filter: None`; active filters appear as compact column-name chips, and hovering or clicking a chip opens the same filter dropdown used by the active table-header filter button so users can review or change the selected values. Dragging a table column header or grouped-column chip into the filter frame adds that column as a neutral `All` filter chip and opens its filter menu. Selecting `All` keeps a neutral chip in the filter frame without the blue active-filter treatment, and dragging a filter chip out of the frame clears that column filter.
- The dataset table `Method Type` and `Status` columns read method metadata from the selected reserving-class folder's cached `index.json` `files` entries, matching rows by instance `name`; datasets missing from the cache display `None` and a green updated status. `Status` shows a green check for sidecar `status: 0` and a yellow warning when a method-backed output has `status: 2` because one of its recorded input precedents was updated later than the method output.
- Double-clicking a vector dataset row whose `Method Type` is `DFM`, or choosing `View` from its row context menu, opens the DFM method tab by default. Double-clicking a vector dataset row whose `Method Type` is `Result Selection` opens the Result Selection method window directly on its Method tab. The same row context menu shows `Show as vector` immediately after `View` for DFM and Result Selection vector rows; choosing it opens the saved output in a normal Dataset Viewer window without showing method details. Cached dataset rows open read-only unless their indexed `source_kind` is `input`.
- The dataset table `Formula`, `Last Modified`, `Created`, and `User` columns read from the selected reserving-class folder's cached `.csv`/`.json` file metadata. `Last Modified` comes from sidecar JSON metadata such as `updated_at`/`modified` when present, with filesystem modified time only as a fallback; `Created` comes from sidecar JSON metadata such as `created_at`/`created` without using filesystem creation time; timezone-aware sidecar timestamps, including UTC `Z` values, are normalized to local display time before they are written into the cached index. Formula values come from sidecar/index metadata, and user values come from the sidecar `user`/`modified_by` Windows-login fields when present.
- Adding a dataset from the cached-dataset table's add picker refreshes the cached list, highlights the newly added dataset row, and selects it in place instead of opening a floating Dataset Viewer window.
- Double-clicking a dataset table row whose `Method Type` is `DFM` opens a floating DFM window inside the Project Instance frame on its Ratios page, initialized with the current project, selected reserving-class path, and dataset name instead of opening the in-tab Dataset Viewer window or a main shell tab; it also records the selected DFM method/output name in project-user `dfmObject` preferences.
- Floating Dataset and DFM windows inside Project Instance follow the main shell corner convention: 6px by default and 8px when the page is running with the Windows 11 frame style.
- Floating Dataset and DFM windows mirror standalone save/dirty behavior: dirty-state messages show a dirty dot on the floating titlebar and minimized tab, closing a dirty window asks for confirmation, confirming discard closes the floating window, and shell Save plus Ctrl+S routes to the active floating Dataset or DFM window. DFM windows also support Save As/Ctrl+Shift+S through the active floating DFM window.
- Floating DFM windows publish their active DFM state to the shell and forward standalone DFM commands, so shell Edit/Help menu actions, ratio hotkeys, DFM JSON opening, Notes file-link context-menu actions including popped DFM tab surfaces, and macro context/apply requests target the active Project Instance DFM window the same way they target a standalone DFM tab. Clicking back into the reserving-class tree or dataset table clears the active nested window and returns shell context to the Project Instance reserving-class level.
- Project Instance relays `arcrho:calculated-datasets-updated` reports between nested Dataset windows and the shell, so open nested calculated dataset windows can auto-refresh after an upstream component save.
- Project Instance relays `arcrho:dependency-source-preview` and `arcrho:dependency-source-cleared` messages between nested Dataset, DFM, and Result Selection windows, including DFM windows that use the shared Dataset layer. This lets a dirty upstream source feed temporary values to an open dependent method or matching Dataset Viewer window. For dirty sources that feed app-calculated Dataset Types, Project Instance also requests an in-memory calculated preview and relays the downstream calculated values, then tells dependents to reload the source from disk when the upstream source is saved, canceled, or closed without saving.
- Project Instance handles dependency open requests from nested Dataset Details pages, opening or activating the clicked dependent as a floating Dataset window using the source window's reserving-class path even if the left-panel selection has moved; method-backed Formula component chips open the related DFM or Result Selection method window instead.
- Project Instance publishes `arcrho:project-instance-state` snapshots to the shell when the selected path or nested floating Dataset/DFM/Result Selection windows change. The snapshot includes selected path, nested window kind/name/title, hidden/active/maximized/dirty flags, DFM and Result Selection subtabs, and restore rectangles so Browsing History can restore Project Instance pages after Clear Cache & Reload without turning method windows into vector dataset viewers.
- The dataset toolbar includes a refresh icon button. Clicking it rebuilds the selected reserving-class `index.json` cache via `/datasets/cached?refresh=true`, reloads the right-panel dataset table from disk, and restores the table scroll position plus selected rows afterward. In Electron, Project Instance watches the selected reserving-class data folder for `index.json` changes; when the index changes on disk, the toolbar shows an `Index updated` button so users can reload the table deliberately. Nested Dataset, DFM, and Result Selection saves also request the same selected-path table refresh, and Dataset grid paste requests it after pasted cells land so cached table metadata such as `Last Modified` is not left stale after common edit actions.
- The dataset toolbar includes a visible grouping drop zone. When no grouping is active it prompts users to drag a column header there; when grouping is active a compact `+` icon appears to the right of grouped chips and shows the drag-to-group hint in a styled hover tooltip. Grouped columns appear as draggable chips, disappear from the main table while grouped, and can be reordered inside the grouping drop zone with an insertion marker. Project Instance supports nested grouping for every available dataset table column rather than stopping at two subgroup levels. Dragging a group chip over a table header shows the same blue insertion line as column reorder and restores the column at that drop location; dropping it over table body space removes grouping and restores the saved column position. Right-clicking dataset table header cells still opens a context menu with `Group by ...` choices for `Data Format` and `Category` plus a placeholder `Reset Columns` option; grouping creates nested compact collapsible group headers inside the same table instead of rendering separate grouped tables. Top-level group headers show record counts as low-contrast circular badges, while subgroup headers omit counts. Every table header still supports drag-to-reorder column labels and drag-to-resize header edges, and all columns except `Status` support per-column filter dropdowns; dragging a column shows a full-height blue insertion line at the target location and a framed drag preview with the column label. Per-column filters match the Project Settings Dataset Types table: no checked values means the filter is not applied, checked values narrow results, and selecting all values is treated as unfiltered while keeping that column as a neutral filter chip when the user explicitly chose it. Each filter dropdown includes an `All` checkbox that clears selected values and resets that column filter; right-clicking a value row selects every value except the clicked one. Resizing a column changes only that column and updates the total table width instead of redistributing space across other columns.
- Dataset table default column order, grouping, filters, sort state, and widths come from the built-in Project Instance preference snapshot. Manual resize can still expand or shrink a column, and double-clicking a resize handle restores that column to its built-in default width.
- Right-clicking a dataset table group header opens `Collapse all` and `Expand all` actions for group headers at the same grouping level as the clicked header.
- Clicking a dataset table row keeps that exact row highlighted, including rows whose dataset names differ only by special characters. Clicking the only highlighted row again removes it from the selection, while clicking one row inside a multi-selection narrows selection to that row. `Ctrl`/`Cmd` click toggles individual rows, `Shift` click selects the visible range from the last anchor row, Up/Down arrow keys move a focused row selection to the previous or next visible dataset, and Enter opens the focused selected dataset. The app status bar shows the selected item count when more than one row is selected. Right-clicking a row opens a row menu that can view the right-clicked dataset or first highlighted dataset, shows `Show as vector` for DFM and Result Selection vector rows, exposes an Add submenu, and can delete cached files related to all highlighted datasets after a custom confirmation dialog. Add > Dataset opens the shared dataset picker window (`dataset_name_picker.js`) for the current project, with Dataset Type Name search, sorting, column filters, grouping, and shared picker preferences. Choosing a generated type sends an ArcRhoTri refresh request to the data engine; generated dataset types are one-instance-per-reserving-class path, so choosing one that already exists in the selected path shows a custom message box instead of issuing another request. Choosing a non-generated dataset type opens a fresh Dataset Viewer draft on the Details page with `Name` defaulted to the dataset type name, initial `number_format` set to `0,000`, default period lengths set to 12, and an editable zero-filled Data-tab placeholder whose labels come from the project settings. Triangle placeholders use the standard triangle shape and Vector placeholders use a one-column vector shape so users can paste from Excel or type values into the available cells. Users may rename the instance before saving, and the draft page blocks duplicate instance names in the selected path. Add > DFM opens a fresh floating DFM window on Details with project/path and default Origin Length, Development Length, and Decimal Places; Name and Output Vector remain blank, and the right-clicked dataset is passed as Input Triangle. Add > Result Selection opens a fresh floating Result Selection window for a vector dataset whose Method Type is `None`, prefilled with project/path, output vector name, output type, and category. Add > Berquist Sherman Method is always selectable and currently shows a placeholder status message.
- Project Instance context-menu submenus include a small pointer bridge between the parent menu item and nested menu so the nested choices remain open during normal diagonal mouse movement.
- When a reserving-class path is selected, Help > Reveal in File Explorer resolves that path's cached `folder_paths.data` folder and asks the shell's desktop open-path bridge to open it in File Explorer.
- Help > Open Dataset JSON File resolves the active floating DFM or Result Selection window to its `methods/*.json` method file and opens it in Arcode through the shell desktop bridge. Help > Open Dataset Sidecar resolves the active floating Dataset, DFM, or Result Selection window to its `sidecars/<DatasetName>.json` file and opens it the same way.
- When the selected reserving-class path has no cached datasets, right-clicking the empty table area or `No dataset found in this path.` label opens the same Add submenu so Add > Dataset can launch the existing dataset-type picker.
- Dataset table renders precompute row cell values, filter option lists, and active filter selections once per render before grouping and sorting, keeping filter/group changes responsive on larger project dataset lists.
- Dataset table headers remain opaque while scrolling, so row contents do not show through sticky header cells.
- Dataset table body cells wrap long text and clamp display to two lines per cell, without row-hover fill or browser tooltips over row values.
- Clicking a dataset table column label cycles that column through ascending sort, descending sort, and no active sort, with the third click returning rows to the default cached order and removing the sort indicator. `Last Modified` and `Created` sort by their cached numeric timestamp values instead of their formatted display strings.
- The left reserving-class panel defaults to 400px and has a draggable splitter constrained to 200px-600px; collapse/expand is animated, live drag updates are frame-throttled with transitions disabled for responsiveness, dragging the panel to 200px or smaller collapses it, and double-clicking the splitter toggles collapse/expand.

## Data/State/Caches
<!-- MANUAL:BEGIN -->
- Uses the shell-persisted project name/folder/table path as tab inputs.
- Loads the project's last selected reserving-class path from project-user preferences when the tab opens; if no last path exists, it selects the first Shortcut item when available, otherwise leaving the path empty.
- Keeps the selected reserving-class path in page memory, saves user selections back to project-user preferences, and passes it into new floating Dataset Viewer and DFM windows. Opening a floating DFM window also updates the shared project-user DFM object defaults with the selected method/output name without waiting for the DFM method to be saved.
- Saves the right-panel dataset table layout in the same project-user preferences JSON under `projectInstance.datasetTable`, including column order, manual column widths, filterable column selections, grouping fields, collapsed group rows, and sort state. Cleared/no-op filters and the non-filterable `Status` column are saved as empty arrays so stale saved filter values do not return after reload. The cached dataset view is always active and is not saved as a normal table filter. When the current project/user has no saved `projectInstance` object yet, the preference API supplies the built-in default `projectInstance` settings before the page loads, unless `ARCRHO_PROJECT_INSTANCE_DEFAULT_PREFS_PATH` points to an override JSON. If preference loading stalls during startup, Project Instance falls back to the default table layout so the page can finish opening.
- Changing the selected reserving-class path refreshes the server-side `index.json` lookup for logical cached dataset instances, stored dataset type names, minimal table metadata, and method types for the selected reserving-class data folder while preserving existing table column filters and grouping.
- Method type and review-status lookup are derived from the same selected-path `index.json` payload as cached dataset names and metadata, so Project Instance does not issue a second method-index request during path selection.
- Floating DFM window dirty state is tracked by DFM iframe `arcrho:dfm-dirty` messages keyed by the DFM `inst`, with iframe-source fallback during startup state sync; Project Instance sends aggregate `arcrho:project-instance-dirty` messages to the shell and consumes shell-level DFM save commands before forwarding them to the active floating DFM iframe. New floating windows start clean until their iframe reports an actual edit state.
- Floating DFM window active state is tracked by DFM iframe edit/history/tab messages and reported to the shell with `arcrho:project-instance-dfm-active-state`; Project Instance forwards `arcrho:assistant-context-request`, `arcrho:dfm-apply-method-payload`, `arcrho:assistant-dfm-edit-approval`, and nested `arcrho:open-path` requests so macros, ArcBot approval review, and file-open actions can use the same active-context and desktop-open contracts for standalone and nested DFM pages. ArcBot app context uses the top active non-minimized floating Dataset/DFM window as the primary Project Instance context and includes lightweight metadata for the other visible nested windows so ArcBot knows they are open without eagerly loading every window's data. The App Context hover text shows the Project, Segment, active nested tab name, table-consistent Method Type, and visible nested-tab count. Minimized nested windows are excluded from ArcBot app context.
- Project Instance relays nested Dataset dirty-close confirmation requests to the shell so the discard prompt can appear above nested floating Dataset/DFM windows, while still allowing the Dataset iframe to fall back to its own prompt when no shell host answers.
- Project Instance handles the shell `arcrho:automation-open-dataset` message for Python UI automation. The command opens or activates a floating Dataset Viewer window for the current selected reserving-class path, or opens the matching DFM/Result Selection method window when callers pass `openMethod` with a method type, then returns the project name, selected path, dataset name, window id, title, and current window properties to the command bridge.
- Project Instance handles the shell `arcrho:automation-project-instance-refresh-datasets` message for Python UI automation. The command reloads the selected reserving-class dataset table from disk with the same behavior as the refresh toolbar button, then returns the project name, selected path, and `refreshed` status to the command bridge.
- Project Instance handles the shell `arcrho:automation-window-command` message for Python UI automation window objects. It can return properties for the active or addressed floating window and perform activate/focus, maximize, restore, minimize, and close actions through the same window manager used by the Project Instance titlebar controls.
- Project Instance consumes `arcrho:project-instance-restore-state` from the shell after the page boots. Restore selects the saved reserving-class path, recreates saved nested Dataset, DFM, and Result Selection windows, reapplies window rectangles/maximized/hidden state, restores saved method subtabs, and raises the saved active visible window.
- Dataset table refresh is available from the toolbar, from the `Index updated` prompt shown after watched `index.json` changes, and is also requested after nested Dataset, DFM, and Result Selection saves or Dataset grid paste actions. Each refresh forces a selected-path cached-index rebuild and keeps existing table preferences such as filters, grouping, sorting, column widths, selected rows, and scroll position.
- Left and right panels own their scroll areas so overflowing path trees and dataset tables scroll inside the project instance tab frame.

## Common Change Tasks
<!-- MANUAL:BEGIN -->
1. Change project instance launch behavior: update Project Settings sender and shell message/tab routing together.
2. Change dataset-window behavior: update the relevant `ui/project_instance/project_instance_*` module while preserving the reused Dataset Viewer page contract.

## Known Risks
<!-- MANUAL:BEGIN -->
- Nested dataset iframes post messages to the project instance page before reaching the shell.
- Dataset viewer query parameters must remain compatible with normal top-level dataset tabs.
