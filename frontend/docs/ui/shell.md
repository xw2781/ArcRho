# Frontend: Shell

## Purpose
<!-- MANUAL:BEGIN -->
Shell-level tab/iframe host for all feature pages.
It owns the main desktop frame, home view, docked/floating tab layout, scoped menus, hotkeys, shell preferences, iframe message routing, and Electron host bridge coordination.
The shell keeps one active top-level tab across docked and floating tabs while preserving iframe sessions as tabs move between layouts.
The desktop shell hosts ArcBot and has no global auto-save mode; workflow and editor file saves are explicit.
The floating window minimize control docks that window back to the end of the main tab strip without activating the docked tab; focus remains on the prior docked tab unless another floating window is still present, in which case the top layered floating window becomes active.
Detailed menu, floating-window, lifecycle, and bridge behavior belongs in focused sections or source-specific docs, not this overview.
<!-- MANUAL:END -->

## External Interfaces
<!-- MANUAL:BEGIN -->
- Communicates with child iframes via `arcrho:*` postMessage events.
- The main docked tab strip keeps a stable row height and connects the active tab to the shell body through border and stacking-layer styling rather than resolution-sensitive transform offsets.
- Home is permanently docked as the first tab. Dragging or docking other tabs cannot place a reorder preview before Home, move Home during preview animation, or persist Home anywhere else in restored tab state.
- The tab strip's add-tab control uses a centered SVG plus with an accessible button hit target. Its surface, border, icon stroke, hover, active, and focus colors derive from shared theme tokens so the control remains legible without a light rectangle in Dark mode.
- In Dark mode, the three main-window titlebar controls use the shared raised surface and strong border tokens, with a restrained accent hover for minimize/maximize and a danger hover for close; their SVG strokes follow the current control foreground color.
- Invokes app-server endpoints for workflow import helpers and configuration endpoints.
- Uses Electron host bridge and explicit shell commands for shutdown/clear-cache actions; ordinary document unloads and reloads do not send app shutdown.
- The desktop host consumes F5 and Ctrl+F5 as no-op shortcuts so accidental refreshes do not reload the app; Ctrl+R remains the explicit shell refresh shortcut.
- The desktop shell uses a 10px left/right workspace gutter; the menubar and status bar run flush to the desktop window border, with the status bar showing a decorative resize glyph only. It does not expose custom drag-to-resize behavior, so window resizing is left to the native Electron window frame while in-shell floating tab windows keep their own resize controls.
- Clear Cache & Reload is available from the Settings menu and `Alt+Q`. It runs immediately, asks open Project Instance tabs for a current state snapshot, stores a one-shot shell restore payload in the Electron host, clears Electron cache/storage, then reloads the shell with a fresh timestamped UI URL and restores the previously active page/tab layout before normal localStorage persistence resumes. Because this command is an explicit forced reload, the Electron host temporarily overrides descendant-page `beforeunload` cancellation while navigating; open nested DFM windows therefore cannot leave the shell stuck at the reload status. File > Restart uses the same Electron cache/storage clear and restore snapshot before posting the app restart requests, so users do not need to run Clear Cache & Reload separately before restarting. If the desktop host cannot perform the cache reload, the shell reports that status and falls back to a browser reload. Project Settings iframes include the shell UI version query parameter so reloads fetch the current Project Settings HTML/module graph consistently.
- App-server startup is host-managed on preferred local port `28765` by default (`ARCRHO_PORT`/`ARCODE_PORT` override), with retry on transient launch failures; Electron verifies a per-launch `/app/health` token so it does not attach to a stale backend process that happens to be listening on the same port, clears mismatched listeners before starting its backend, writes packaged app-server stdout/stderr logs under the Electron user-data `logs` folder, and writes Electron main-process startup logs plus a visible startup-failure dialog for diagnostics. When the preferred port is held by a listener the host can neither reuse nor clear (for example another Windows user's ArcRho session on the same machine), startup checks known sibling-instance ports for a compatible backend to reuse and otherwise falls back to an automatically chosen free local port instead of failing. After the backend is ready, the host publishes the effective endpoint to the per-user `%APPDATA%\ArcRho\app_endpoint.json` (or `%APPDATA%\Arcode\app_endpoint.json`) discovery file for local integrations and removes it on clean exit when it still owns the file. This backend lifecycle logic lives in `electron/backend_lifecycle.js`, installer update checking in `electron/update_checker.js`, and shared host logging/utility helpers in `electron/host_support.js`; `electron/main.js` owns windows, IPC, and app wiring.
- After the packaged desktop shell is visible, the Electron host checks `E:\ArcRho Server\releases\installers` for a newer ArcRho installer without blocking startup. Development and other unpackaged launches skip installer update checks by default because they run from the local source tree; set `ARCRHO_ENABLE_DEV_UPDATE_CHECK=1` before launching only when intentionally testing updater behavior in dev. `start_electron_no_python_window.bat` reads that update feed's `latest.json` and `ArcRho-Setup-*.exe` filenames, then marks the splash page and About dialog display version with a trailing `+`, such as `1.1.1+`, so dev launches are visually distinct from installed releases while internal update comparisons still use the strict package version. The no-console dev supervisor runs npm scripts in silent/no-window mode so the npm package banner does not show stale source-tree package versions during startup. The About dialog also exposes a Check for Updates button that runs the same host check and reports when ArcRho is already current, when update checks are unavailable, when the update location is unavailable, or when a newer installer exists but is missing the required SHA-256 checksum. Update checks time out quickly, require a SHA-256 checksum before launching an installer, ask the user whether to update, and reuse the normal shutdown confirmation before starting the installer and quitting ArcRho.
- Home has no left navigation panel. A compact welcome panel at the top of the Launch Center contains the existing brand identity, a welcome message, and the low-contrast circular SVG initial mark. The brand resolves the current Windows login through the app server and shows its case-insensitive `full_name` mapping from the workspace-global `config/username_index.json`; an unmapped login remains visible unchanged. If the identity endpoint is unavailable, Electron sessions fall back to the host-provided login name and plain browser sessions keep the default ArcRho identity.
- Home presents its launch groups directly below the welcome panel without a separate Launch Center heading. General is the first group, followed by the workspace-specific groups. Group labels use a larger title-case treatment, and consecutive groups are separated by low-opacity divider lines derived from the active theme's neutral border color.
- The Home Launch Center groups Dataset, DFM, Bornhuetter Ferguson, and Result Selection under `Datasets & Methods`. Each method card opens a standalone restorable shell tab, while the `My Workspace` card opens or focuses one standard `file_explorer` shell tab. That tab defaults to `My Workspace` and adopts the selected folder's configured nickname, or its folder name when no nickname exists. Home group labels use title case rather than all-uppercase styling.

- Uses Electron host bridge for desktop-only ArcBot Codex CLI status, install, login, persisted chat sessions, streamed activity/output events and assistant response deltas, file revision checks, per-request timing logs under `Documents\ArcRho\ArcBot\request_logs`, and warm `codex app-server` turns with fallback to one-shot `codex exec` requests. The host keeps one long-lived app-server process because the official Codex SDK wraps the same transport, while each request starts a fresh ephemeral thread and hydrates it once from the bounded persisted chat transcript so prior messages are not duplicated. The Electron renderer passes the computed native-window background token through a validated per-window host bridge, which applies it immediately and caches it only as a startup paint hint.
- The docked tab and floating titlebar context menus include scripting-only actions for `Open File Location` and `Copy File Path`; scripting title updates include the tab instance id and current file path so background scripting tabs update their own tab title/path rather than the active tab. Holding the pointer still over a saved scripting tab or floating scripting titlebar for two seconds shows the full file path in the shell styled tooltip; moving the pointer hides or cancels it.
- In the desktop app, dragging files from File Explorer over the shell or an open feature iframe shows a shell-owned drop overlay. Dropping `.ipynb`, `.arcnb`, or `.py` files opens each scripting file in Arcode.
- Arcode owns scripting recent files and notebook/code-editor tab behavior; the ArcRho shell no longer creates new in-shell scripting tabs.
- Before closing the active top-level tab for `Ctrl+W`/close-tab shortcuts, the shell lets the active iframe consume the shortcut through `window.__arcrho_consume_close_shortcut`; dirty Dataset and DFM tabs use this to show their in-page discard confirmation first, and project instance tabs use it to close their top floating dataset window first.
- OS-level detached tab pop-out windows are not supported; floating tabs stay inside the main shell and reuse the same iframe/message contracts as docked tabs.

## Data/State/Caches
<!-- MANUAL:BEGIN -->
- Persists tab state, docked/floating layout, floating window position/size/z-order, zoom, and toggles in `localStorage`; Clear Cache & Reload preserves the current shell tab snapshot through the Electron host because the action intentionally clears browser storage.
- Persists File Explorer favorites in `%APPDATA%\ArcRho\prefs\home_folders.json` as the normalized versioned document `{ "version": 1, "folders": [{ "path": "...", "nickname": "..." }] }`. The Electron file is authoritative and written atomically so favorites survive Clear Cache & Reload; `arcrho_home_folder_preferences_v1` local storage is only a browser fallback and first-run migration source.
- Persists the normalized frontend color theme (`light` or `dark`) as the local OS user's authoritative `color_theme` preference in `%APPDATA%\ArcRho\prefs\main_window_prefs.json`. The shared `arcrho_color_theme` local-storage value is a renderer cache that is seeded from the user preference at startup; an existing cache is migrated into the preference file when that field is first introduced. Clear Cache & Reload may clear browser storage, but it preserves the user preference and the derived native-window background cache, passes the stored theme into the reload URL for correct first paint, and restores the renderer cache from Electron.
- Persists project instance tab identity using the selected project name plus project folder/table-path metadata.
- Persists dataset browsing history entries (latest 15) via `browsing_history.js`.
- Persists the latest 10 active restore-capable page entries under `shellActivityHistory.entries` in `%APPDATA%\ArcRho\local_project_prefs.json`. Project Instance entries also persist selected path, nested floating Dataset/DFM window names, hidden/active/maximized/dirty flags, DFM subtab, and restore rectangles. Successfully opened My Workspace paths retain their own local-user browser history (latest 15) under `arcrho_workspace_history_v1`.
- Persists the ArcBot launcher icon visibility and position in `localStorage`.
- Persists ArcBot chat sessions as local JSON under Electron user data, including messages, activity, mode, archived state, latest active-tab context summary, and estimated context usage; ArcBot writes shared exchange JSON/CSV copies under the user `Documents\ArcRho\ArcBot\workspace` folder while keeping per-request edit metadata under `Documents\ArcRho\ArcBot\sessions`, and latest ArcBot edit metadata is stored under Electron user data so a later `revert latest` request can restore the backed-up method JSON when the file has not changed again.
- ArcBot panel resizing clamps saved and live widths to a 420px minimum that keeps the composer controls visible without clipping, and each app session's first ArcBot panel open starts at that minimum width while preserving the saved height. Resizing the main app window repositions the open ArcBot panel back into view without changing the panel's current width or height.
- The ArcBot model selector obtains its visible OpenAI catalog and supported reasoning efforts from the bundled Codex app-server `model/list` contract instead of a hardcoded list. New empty chats use an advertised and verified GPT-5.6-or-newer default, with future newer defaults taking precedence automatically. A stale CLI catalog that lacks GPT-5.6 triggers Repair; ArcBot never inserts or auto-saves an unadvertised model, and a temporary discovery failure blocks sends until retry or Repair verifies the catalog. Safe model slugs saved by older chats remain visible as unavailable rather than being silently replaced. Anthropic choices remain Claude Opus 4.8, Claude Sonnet 4.6, and Claude Haiku 4.5. The reasoning/thinking selector shows only the selected model's reported capabilities (including Ultra when supported), and the legacy Codex default inherits those capabilities before send. Both `model` and `reasoningEffort` remain session-persisted and are forwarded through `codexAssistantSend`; switching providers rechecks the matching credentials.
- Claude requests in the Electron host are authenticated using the OAuth access token in `~/.claude/.credentials.json` written by the Claude CLI (`claude login`); no separate API key is required. The `codex-assistant-status` IPC now returns `claudeAuthenticated` alongside the existing Codex fields, and `codex-assistant-login` accepts an optional `{ provider: "anthropic" }` payload to open `claude login` instead of `codex login`. Claude messages are sent to the Anthropic Messages API (`/v1/messages`) over HTTPS with SSE streaming; edit sessions are skipped for Claude models (responses are conversational only).
- Dirty-state messages from workflow, DFM, and scripting tabs update the shared tab dirty indicator for both docked tabs and floating tab titlebars.

## Common Change Tasks
<!-- MANUAL:BEGIN -->
1. Add a new tab type: update `tab_actions.js`, `iframe_host.js`, relevant menu/hotkey dispatch modules, and any state persistence in `shell_state.js`.
2. Add shell menu action: wire menu item + action handler in `shell_menus.js` and hotkey mapping in `shell_hotkeys.js`; for `Edit`/`View` items, always set `data-page-scopes` (`*` for global visibility) because those dropdowns require explicit scope declarations.
3. Change tab layout behavior: update `tab_strip.js`, `floating_tabs.js`, `shell_content.js`, active-tab dispatch in `tab_actions.js`, localStorage migration in `shell_state.js`, and close/dirty-state flows together.
4. Change theme behavior: keep preference normalization and messaging in `ui/shared/services/color_theme.js`, keep Light and Dark values in their corresponding shared theme stylesheet, and preserve the `arcrho:set-color-theme` relay for existing and newly loaded iframe contexts.
5. Change File Explorer behavior: keep favorite normalization, path rules, metadata formatting, filtering, and sorting in `ui/file_explorer/file_explorer_model.js`; keep DOM interaction in `ui/file_explorer/file_explorer.js`; and preserve the shared Electron folder-listing, watcher, file-opening, and file-icon contracts used by Arcode.

## Known Risks
<!-- MANUAL:BEGIN -->
- DOM replacement in shell can invalidate iframe references.
- Unsaved-state handling must stay consistent for close/close-all flows.
- Floating/docking must reposition existing iframes without recreating or reparenting them, or feature pages can lose in-memory state.
- Active-tab styling and menu dispatch must stay single-source through `state.activeId` so docked background content does not behave as active while a floating window is focused.
- Host/app-server startup races can surface as blank shell or startup timeout if lifecycle flags/process teardown are not coordinated.
- Offline, slow, or inaccessible update feed folders must not block startup; failures should remain a skipped update check.
