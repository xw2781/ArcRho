# App Server Domain: dataset

## Purpose
<!-- MANUAL:BEGIN -->
Dataset retrieval/patch domain for in-memory dataset instances.
Also handles reserving-class dataset file discovery, sidecar metadata, and dataset Notes persistence under each project `data` folder.
See [`data-engine/docs/dataset-scenarios.md`](../../../../data-engine/docs/dataset-scenarios.md) for the source-kind scenario matrix, editability rules, and cache rebuild behavior.
<!-- MANUAL:END -->

## External Interfaces
<!-- MANUAL:BEGIN -->
- Called by Dataset Viewer and DFM frontend flows via `ui/shared/dataset/dataset_api.js`.
- `GET /dataset/{ds_id}` and `GET /dataset/{ds_id}/diagonal` require `project_name` and `origin_length` query values. The registered CSV path must be inside that project's data folder, then origin labels are always requested from the current ArcRho project headers rather than reused from potentially stale sidecar labels. Embedded project-name fields may remain stale after a supported project copy or rename and are not used for ownership checks. Header loading validates the project's Origin Start Date before using a cache and invalidates header caches older than `general_settings.json`. Labels must use the annual, half-year, quarterly, or monthly date format matching `origin_length`, be consecutive, and exactly match the CSV row count. Missing/invalid settings or labels return `422`, header-generation timeouts return `504`, and filesystem/lock failures retain their server error status; no route synthesizes labels from a default year.
- Exposes Notes load/save endpoints for project-scoped dataset notes persistence.
- Exposes `GET` and `PUT /dataset/number-format-defaults` for the workspace-global `config/dataset_number_formats.json`. Override rows are keyed by `reserving_class` plus `dataset_type_name`; saves validate nonblank fields, reject duplicate reserving-class/Dataset Type Name keys, use revision checks to prevent stale-window overwrites, and replace the JSON atomically.
- Exposes dataset sidecar load/save endpoints. Dataset sidecars live in `projects/<project>/data/<ReservingClassFolder>/sidecars/<DatasetName>.json`; `dataset_name` is the persisted user-visible instance name, `dataset_type` is the persisted Dataset Type, `origin_labels` stores persisted row labels when supplied by method pages, `number_format` stores the Dataset Data tab numeric display pattern, `decimal_places` stores its fractional digit count, `method_type` stores `None`, `DFM`, `Result Selection`, or another method type, `status` stores `0` for current and `2` when a method-backed output needs human review, and `audit_log` stores up to 50 records with `event_date`, `action`, `change_info`, and Windows login `user`. Vector sidecars store the single vector period granularity as `period_length`; triangle sidecars store `origin_length`, `development_length`, `cumulative`, and `calendar`. Editable Dataset Excel sources are stored as `external_links`, an array of `{reference, target_cells}` records where each target contains zero-based `{row, column}` logical Dataset coordinates and a normalized A1 `source_cell`; Dataset coordinates remain untransposed even when the client displays the grid transposed. Each saved reference must be a standalone workbook cell/range, each mapped source cell must belong to that reference, and target ownership cannot overlap another record. Explicit source cells allow the normalized target list to contain only the editable destinations reached by a larger range after grid-boundary or triangle-mask clipping; non-strict loads keep the first valid target owner and discard malformed or ambiguous later records. Insert records leave `change_info` blank; update records use `Values`. Sidecar load/save responses include normalized `external_links`, `Precedents`, and `Dependents`; a missing external-link field loads as `[]`, omitting `external_links` from a save preserves the existing field, and sending `[]` clears it. Graph entries support Dataset Details dependency navigation: precedent entries include resolved `method_type` for method-backed formula component navigation, and dependent entries include formula text when the dependent sidecar or Dataset Type formula can be resolved. The old root aliases `instance_name` and `dataset_type_name` are not accepted. Save updates metadata, appends a sidecar audit record, preserves caller-supplied `source_kind`/`data_format`, applies current formula graph fields, marks transitive method-backed dependents as needing review while leaving app-calculated `method_type: None` outputs unflagged, refreshes the selected reserving-class `index.json`, and returns dependent recalculation details when the saved dataset feeds app-calculated outputs. When the save payload includes `values` and `mask`, the service also writes the current numeric/`null` snapshot, not Excel formulas, to the format-scoped CSV under `datasets/` (`<DatasetName>@<PeriodLength>.csv` for vectors, mode-qualified origin/development names for triangles), stores that file name in `csv_file`, registers the CSV-backed `ds_id`, and returns the CSV modification time for follow-up grid edits. The CSV is restored to its prior version if the paired sidecar replacement fails, preventing new values from being left behind without their external-link metadata; if the restore is itself blocked, the rollback copy is retained and its path is reported for recovery.
- Exposes `/dataset/cache/load` for method pages that need numeric values from a named cached dataset. The route resolves the canonical sidecar, can target a specific `csv_file` or requested origin/development length, and otherwise falls back to the sidecar's `csv_file` and matching CSV names in the selected reserving-class `datasets/` folder. Exact `csv_file` or length requests are strict: if that cache is missing, the route returns a clear not-found error instead of falling back to a native-length cache. The response includes the raw CSV matrix plus basic sidecar metadata including persisted `origin_labels` when present. When a scoped filename is loaded, the response reports the period lengths parsed from that cache filename so method pages can distinguish native sidecar length from materialized cache length.
- Exposes a project/path cached dataset lookup for Project Instance and DFM Details backed by the reserving-class `index.json` cache. The index resolves `project_name` plus selected reserving-class path to `projects/<project>/data/<ReservingClassFolder>`, then returns logical dataset names inferred from `datasets/*.csv`, `methods/*.json`, and `sidecars/*.json` metadata plus a folder signature derived from physical cache-file names, sizes, modification times, and folder existence. Returned `files` entries are minimal records with base dataset instance `name`, stored `dataset_type`, stored `dataset_category`, sidecar `data_format`, origin length/labels when present, latest modified time, earliest created time, user text from related metadata JSON, formula text, `source_kind`, method type when applicable, and sidecar review status. Formula text comes from sidecar/index metadata when present and otherwise falls back to the matching project `dataset_types.json` row for the stored `dataset_type` or logical name. User text comes from sidecar/index metadata and is replaced during index rebuild when `config/username_index.json` maps that Windows login to a full name. Mode-qualified triangle cache filenames such as `<DatasetName>@12@12@cum@dev.csv` and vector period cache filenames such as `<DatasetName>@12.csv` are normalized to one base dataset instance entry; older two-length-only filenames are treated as literal stems instead of compatibility aliases. When a sidecar or method payload supplies `dataset_name`, that metadata name is the canonical logical row `name`, while filename-derived variants remain aliases for matching/deletion and do not create extra Project Instance rows. DFM, Result Selection, and Bornhuetter Ferguson method JSON use their Details name as the logical row identity and their configured output type as `dataset_type`, so the prefixed physical method filenames do not create extra Project Instance rows. Passing `refresh=true` rebuilds the selected path's index before returning it, which Project Instance uses from the dataset-table toolbar refresh button and DFM Details uses for the current-path Input Triangle selector. Index rebuilds serialize writes per selected index path, write through unique temporary files, and briefly retry Windows sharing violations during the atomic replace so overlapping DFM saves, Sync pre-saves, and Project Instance refreshes do not collide on a shared `index.json.tmp`.
- Exposes cached empty dataset creation for Project Instance non-generated dataset types. The endpoint writes a zero-filled CSV under `datasets/` and base metadata sidecar under `sidecars/`, using the format-scoped filename convention and deriving the actual triangle/vector shape from the project's `general_settings.json` date boundaries. Missing, malformed, or invalid Origin Start, Origin End, or Development End settings return an actionable error instead of creating a default 12-by-12 dataset. For triangles, cells are included only when the origin period plus development period falls on or before `development_end_date`, so older origin periods have wider editable rows and newer periods narrow toward the latest diagonal. Dataset patch validation reuses that date-derived mask when sidecar metadata is available, resolves the current project from the containing project/data folder so copied or renamed sidecars may retain their old embedded name, and preserves Project Settings errors instead of silently falling back to a generic triangle; successful patch saves append an `Update` audit record to the related sidecar.
- Treats `dataset_types.json` rows with `Calculated=true` and `Generated=false` as app-calculated outputs. Adding one through Project Instance, requesting one whose output cache is missing, or changing one of its component CSV caches recalculates the output under the selected reserving-class folder, marks the sidecar `source_kind: "calculated"` and `calculated: true`, and refreshes the selected reserving-class dataset index. When a requested app-calculated output is missing one of its generated or app-calculated component caches, the runtime materializes that component with the same reserving-class and period settings and retries the output before reporting a dependency failure. A newly generated durable engine cache triggers dependent recalculation even when the loading request uses `WriteSidecar: false`; that flag suppresses source-sidecar replacement, not downstream cache maintenance. Recalculation follows the direct-dependent chain from the changed dataset type for app-calculated dataset types that already exist as instances in the selected reserving-class folder, so a source update in an existing `A -> B -> C` chain refreshes `B` before `C` but does not create or warn about absent calculated outputs. It returns ordered `steps` details to the caller. The `/dataset/calculated/preview` endpoint reuses the same formula evaluator with caller-supplied in-memory source values and returns downstream matrices without writing CSV, sidecar, or index files.
- Exposes cached dataset deletion for Project Instance. The delete endpoint accepts project, reserving-class path, and logical dataset names, removes matching `datasets/`, `methods/`, and related `sidecars/` files only inside the selected reserving-class data folder, and rebuilds `index.json` afterward.

## Data/State/Caches
<!-- MANUAL:BEGIN -->
- Uses in-memory dataset map and patch payloads.
- ArcRhoTri CSV request targets are `projects/<project>/data/<ReservingClassFolder>/datasets/<InstanceName>@<OriginLength>@<DevelopmentLength>@<cum|inc>@<dev|cal>.csv` when `InstanceName` is supplied, otherwise the Dataset Name is used. ArcRhoVec request targets are `projects/<project>/data/<ReservingClassFolder>/datasets/<InstanceName>@<PeriodLength>.csv`. The metadata sidecar is `sidecars/<InstanceName>.json` and records the generated instance as `dataset_name`, separately from `dataset_type`, plus `source_kind: "engine"`, `data_format`, `transposed`, `number_format`, `decimal_places`, `created`, `updated_at`, and user fields. New engine and app-calculated sidecars take `number_format` from the matching reserving-class/Dataset Type Name override in workspace-global `config/dataset_number_formats.json`, fall back to its `default_number_format`, and derive `decimal_places` from the selected pattern; lookup uses sidecar `dataset_type`, not instance `dataset_name`, and later app-calculated refreshes preserve saved display settings. Triangle sidecars store `origin_length`, `development_length`, `cumulative`, and `calendar`; vector sidecars store `period_length`. The reserving-class path is a single filename-escaped folder name using the reversible `_%XX_` rule and is not repeated in the CSV filename.
- Project Instance non-generated placeholders are stored under `projects/<project>/data/<ReservingClassFolder>/datasets` with sidecars using `source_kind: "input"`. Draft saves persist the visible grid values to the format-scoped CSV file and update the sidecar `csv_file` field so custom entered values survive window reloads.
- App-calculated outputs also stay under `projects/<project>/data/<ReservingClassFolder>/datasets` but use `source_kind: "calculated"`, store `calculated: true`, store their formula and graph metadata in the sidecar, and are recomputed eagerly after editable component patch saves, ArcRhoTri cache writes, explicit sidecar saves, or Dataset Types formula saves. Sidecars use `Precedents` for direct formula inputs and `Dependents` for direct formula consumers; `Dependents` includes only direct formula consumers that exist as logical instances in the same reserving-class folder. Formula evaluation supports dataset references, DFM method output references, parentheses, and `+`, `-`, `*`, `/`; when a referenced DFM output CSV is missing, calculation can rebuild the DFM Results vector from the saved `methods/DFM@<Name>.json` method and its input triangle cache. Missing or ambiguous component caches skip the dependent update without failing the source dataset save.
- Result Selection output sidecars store `Precedents` as a plain string array of source dataset names, for example `["Paid Loss", "Reported Loss"]`, instead of formula graph entry objects. Result Selection output CSVs use the vector cache shape `<DatasetName>@<PeriodLength>.csv`; quarterly and half-year saves can also materialize coarser aggregate vector caches in the same `datasets/` folder while the sidecar `csv_file` remains pointed at the native-period CSV.
- ArcRhoTri precheck/execution treats a missing variant-specific CSV as a cache miss. When `InstanceName` is supplied, cache validation keys on the sidecar's decoded instance/dataset name plus project and reserving-class path, so manually imported datasets whose `dataset_type` is a broader label such as `Net Loss - ad hoc` can still satisfy DFM/Dataset loads by their visible instance name. Manual `source_kind: "input"` caches are never cleared or regenerated by ArcRhoTri execution; the runtime uses the exact cache when present, can derive coarser period requests from finer cumulative caches (for example quarterly to annual), and returns an explicit local-cache error when only a coarser fixed-size cache exists or no input sidecar is found. DFM/local-only cache checks also inspect generated local triangle sidecars, and generated input triangles may fall through to ArcRhoTri generation for a missing requested shape as long as the base sidecar exists. Runtime engine cache creation writes the base sidecar when it is missing; when a generated cache is refreshed, the existing base sidecar updates `csv_file`, current request metadata, and modification/audit metadata so method-backed dependents can be marked for review.
- Persists dataset Notes as JSON files in `projects/<project>/data/<ReservingClassFolder>/sidecars/ArcRhoTriNotes@<DatasetName>.json`.
- Cached dataset lookup is read-only and scans the selected reserving-class folder's `datasets/`, `methods/`, and `sidecars/` children, matching CSV caches, DFM `DFM@...`, Result Selection `RS@...`, and Bornhuetter Ferguson `BF@...` method JSON plus sidecar metadata back to logical instance-name candidates after applying the same server-side folder/file sanitizers used by runtime cache writes. Filename-derived names and metadata payload names are decoded from the reversible `_%XX_` form before they are returned for display, so encoded sidecar/method payloads and decoded file-derived names collapse to one logical Project Instance row; when both metadata and filename names are present, the metadata `dataset_name` becomes the row `name` and the filename name is only an alias. The response keeps a short `sha256:` `folder_signature` derived from physical file names, sizes, modification times, and folder existence for frontend stale-content detection, while the saved `files` list remains a compact logical instance list for Project Instance. Each cached instance row stores `name` as the user-visible instance Name, `dataset_type` as the Dataset Type used to open/decorate that instance, and `dataset_category` as the category used by Project Instance and Result Selection filters.
