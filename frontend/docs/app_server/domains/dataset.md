# App Server Domain: dataset

## Purpose
<!-- MANUAL:BEGIN -->
Dataset retrieval/patch domain for in-memory dataset instances.
Also handles reserving-class dataset file discovery, sidecar metadata, and dataset Notes persistence under each project `data` folder.
See [`data-engine/docs/dataset-scenarios.md`](../../../../data-engine/docs/dataset-scenarios.md) for the source-kind scenario matrix, editability rules, and cache rebuild behavior.
<!-- MANUAL:END -->

## External Interfaces
<!-- MANUAL:BEGIN -->
- Called by dataset/DFM frontend flows via `shared/api.js`.
- Exposes Notes load/save endpoints for project-scoped dataset notes persistence.
- Exposes dataset sidecar load/save endpoints. Dataset sidecars live in `projects/<project>/data/<ReservingClassFolder>/sidecars/<DatasetName>.json`; `dataset_name` is the persisted user-visible instance name, `dataset_type` is the persisted Dataset Type, `origin_labels` stores persisted row labels when supplied by method pages, `number_format` stores the Dataset Data tab numeric display pattern, `decimal_places` stores its fractional digit count, `method_type` stores `None`, `DFM`, `Result Selection`, or another method type, `status` stores `0` for current and `2` when a method-backed output needs human review, and `audit_log` stores up to 50 records with `event_date`, `action`, `change_info`, and Windows login `user`. Insert records leave `change_info` blank; update records use `Values`. Sidecar load/save responses include normalized `Precedents` and `Dependents` graph entries for Dataset Details dependency navigation; precedent entries include resolved `method_type` for method-backed formula component navigation, and dependent entries include formula text when the dependent sidecar or Dataset Type formula can be resolved. The old root aliases `instance_name` and `dataset_type_name` are not accepted. Save updates metadata, appends a sidecar audit record, preserves caller-supplied `source_kind`/`data_format`, applies current formula graph fields, marks transitive method-backed dependents as needing review while leaving app-calculated `method_type: None` outputs unflagged, refreshes the selected reserving-class `index.json`, and returns dependent recalculation details when the saved dataset feeds app-calculated outputs. When the save payload includes `values` and `mask`, the service also writes the length/mode-scoped CSV under `datasets/`, stores that file name in `csv_file`, registers the CSV-backed `ds_id`, and returns the CSV modification time for follow-up grid edits.
- Exposes `/dataset/cache/load` for method pages that need numeric values from a named cached dataset. The route resolves the canonical sidecar, can target a specific `csv_file` or requested origin/development length, and otherwise falls back to the sidecar's `csv_file` and other mode-qualified CSV names in the selected reserving-class `datasets/` folder. Exact `csv_file` or length requests are strict: if that cache is missing, the route returns a clear not-found error instead of falling back to a native-length cache. The response includes the raw CSV matrix plus basic sidecar metadata including persisted `origin_labels` when present. When a length-scoped filename is loaded, the response reports the origin/development length parsed from that cache filename so method pages can distinguish native sidecar length from materialized cache length.
- Exposes a project/path cached dataset lookup for Project Instance and DFM Details backed by the reserving-class `index.json` cache. The index resolves `project_name` plus selected reserving-class path to `projects/<project>/data/<ReservingClassFolder>`, then returns logical dataset names inferred from `datasets/*.csv`, `methods/*.json`, and `sidecars/*.json` metadata plus a folder signature derived from physical cache-file names, sizes, modification times, and folder existence. Returned `files` entries are minimal records with base dataset instance `name`, stored `dataset_type`, stored `dataset_category`, sidecar `data_format`, origin length/labels when present, latest modified time, earliest created time, user text from related metadata JSON, formula text when present, `source_kind`, method type when applicable, and sidecar review status. Mode-qualified cache filenames such as `<DatasetName>@12@12@cum@dev.csv` are normalized to one base dataset instance entry; older length-only filenames are treated as literal stems instead of compatibility aliases. When a sidecar or method payload supplies `dataset_name`, that metadata name is the canonical logical row `name`, while filename-derived variants remain aliases for matching/deletion and do not create extra Project Instance rows. DFM method JSON rows use Details `name` as the logical row identity and Details `output type` as `dataset_type`, so renaming a DFM Name changes the Project Instance row without changing the selected output dataset type. Passing `refresh=true` rebuilds the selected path's index before returning it, which Project Instance uses from the dataset-table toolbar refresh button and DFM Details uses for the current-path Input Triangle selector.
- Exposes cached empty dataset creation for Project Instance non-generated dataset types. The endpoint writes a zero-filled CSV under `datasets/` and base metadata sidecar under `sidecars/`, using the existing length/mode-scoped filename convention and deriving the actual triangle/vector shape from the project's `general_settings.json` date boundaries. For triangles, cells are included only when the origin period plus development period falls on or before `development_end_date`, so older origin periods have wider editable rows and newer periods narrow toward the latest diagonal. Dataset patch validation reuses that date-derived mask when sidecar metadata is available, and successful patch saves append an `Update` audit record to the related sidecar.
- Treats `dataset_types.json` rows with `Calculated=true` and `Generated=false` as app-calculated outputs. Adding one through Project Instance or changing one of its component CSV caches recalculates the output under the selected reserving-class folder, marks the sidecar `source_kind: "calculated"` and `calculated: true`, and refreshes the selected reserving-class dataset index. Recalculation follows the full direct-dependent chain from the changed dataset type, so a source update in an `A -> B -> C` chain refreshes `B` before `C` and returns ordered `steps` details to the caller. The `/dataset/calculated/preview` endpoint reuses the same formula evaluator with caller-supplied in-memory source values and returns downstream matrices without writing CSV, sidecar, or index files.
- Exposes cached dataset deletion for Project Instance. The delete endpoint accepts project, reserving-class path, and logical dataset names, removes matching `datasets/`, `methods/`, and related `sidecars/` files only inside the selected reserving-class data folder, and rebuilds `index.json` afterward.

## Data/State/Caches
<!-- MANUAL:BEGIN -->
- Uses in-memory dataset map and patch payloads.
- ArcRhoTri CSV request targets are `projects/<project>/data/<ReservingClassFolder>/datasets/<InstanceName>@<OriginLength>@<DevelopmentLength>@<cum|inc>@<dev|cal>.csv` when `InstanceName` is supplied, otherwise the Dataset Name is used. The metadata sidecar is `sidecars/<InstanceName>.json` and records the generated instance as `dataset_name`, separately from `dataset_type`, plus `source_kind: "engine"`, `data_format`, saved `origin_length`, `development_length`, `cumulative`, `transposed`, `calendar`, `number_format`, `decimal_places`, `created`, `updated_at`, and user fields. The reserving-class path is a single filename-escaped folder name using the reversible `_%XX_` rule and is not repeated in the CSV filename.
- Project Instance non-generated placeholders are stored under `projects/<project>/data/<ReservingClassFolder>/datasets` with sidecars using `source_kind: "input"`. Draft saves persist the visible grid values to the mode-qualified CSV file and update the sidecar `csv_file` field so custom entered values survive window reloads.
- App-calculated outputs also stay under `projects/<project>/data/<ReservingClassFolder>/datasets` but use `source_kind: "calculated"`, store `calculated: true`, store their formula and graph metadata in the sidecar, and are recomputed eagerly after editable component patch saves, ArcRhoTri cache writes, explicit sidecar saves, or Dataset Types formula saves. Sidecars use `Precedents` for direct formula inputs and `Dependents` for direct formula consumers; both are populated from the current Dataset Types table when sidecars are created or refreshed. Formula evaluation supports dataset references, DFM method output references, parentheses, and `+`, `-`, `*`, `/`; when a referenced DFM output CSV is missing, calculation can rebuild the DFM Results vector from the saved `methods/DFM@<Name>.json` method and its input triangle cache. Missing or ambiguous component caches skip the dependent update without failing the source dataset save.
- Result Selection output sidecars store `Precedents` as a plain string array of source dataset names, for example `["Paid Loss", "Reported Loss"]`, instead of formula graph entry objects.
- ArcRhoTri precheck/execution treats a missing variant-specific CSV as a cache miss. When `InstanceName` is supplied, cache validation keys on the sidecar's decoded instance/dataset name plus project and reserving-class path, so manually imported datasets whose `dataset_type` is a broader label such as `Net Loss - ad hoc` can still satisfy DFM/Dataset loads by their visible instance name. Manual `source_kind: "input"` caches are never cleared or regenerated by ArcRhoTri execution; the runtime uses the exact cache when present, can derive coarser period requests from finer cumulative caches (for example quarterly to annual), and returns an explicit local-cache error when only a coarser fixed-size cache exists or no input sidecar is found. DFM/local-only cache checks also inspect generated local triangle sidecars, and generated input triangles may fall through to ArcRhoTri generation for a missing requested shape as long as the base sidecar exists. Runtime engine cache creation writes the base sidecar only when it is missing; later sidecar setting changes come from the explicit Dataset sidecar save endpoint so ordinary dataset runs do not overwrite the user's saved period lengths. When a generated cache is refreshed, the existing base sidecar keeps its settings but updates its modification/audit metadata so method-backed dependents can be marked for review.
- Persists dataset Notes as JSON files in `projects/<project>/data/<ReservingClassFolder>/sidecars/ArcRhoTriNotes@<DatasetName>.json`.
- Cached dataset lookup is read-only and scans the selected reserving-class folder's `datasets/`, `methods/`, and `sidecars/` children, matching CSV caches, DFM method JSON, Result Selection `RS@...` method JSON, and sidecar metadata back to logical instance-name candidates after applying the same server-side folder/file sanitizers used by runtime cache writes. Filename-derived names and metadata payload names are decoded from the reversible `_%XX_` form before they are returned for display, so encoded sidecar/method payloads and decoded file-derived names collapse to one logical Project Instance row; when both metadata and filename names are present, the metadata `dataset_name` becomes the row `name` and the filename name is only an alias. The response keeps a short `sha256:` `folder_signature` derived from physical file names, sizes, modification times, and folder existence for frontend stale-content detection, while the saved `files` list remains a compact logical instance list for Project Instance. Each cached instance row stores `name` as the user-visible instance Name, `dataset_type` as the Dataset Type used to open/decorate that instance, and `dataset_category` as the category used by Project Instance and Result Selection filters.
